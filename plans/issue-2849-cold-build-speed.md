## Ordered implementation steps (single builder, no parallel lanes)

Each cycle follows the `tdd` skill (Red, Green, post-refactor check) and ends in a local commit; evidence of each cycle is kept in the ignored task record.

0. **Baseline.** Record the base's behavior with the selected suites (see Verification) and the base binary's matrix numbers with the same harness once it exists. Recorded so far: base CI run `39243883911` failed 4 of 173 `domestic` tests with `forecast cache: raw storage: Capacity` (overflow under load, not diagnosed); locally the 4 pass in isolation, the whole binary passes with `--test-threads=4` (173/0, 2 ignored) and fails 30 tests in fixture publication with the default 10 threads (host contention). Base and candidate are compared with `--test-threads=4`; the CI result of a later PR is read against this baseline, not claimed as fixed.
1. **Harness and test aids** (`catalog_peer.py` latency control + self-check, example gate/`aged` mode, `cold_build_matrix.py` + pure tests). Red: the pure tests and the peer self-check fail before the code exists. This step must precede R1 so that D2-as-published and the candidate use one harness.
2. **R1 and R2.** Red tests in `forecast_cold_read.rs` first: peak concurrent catalog lookups ≥ 8, elapsed ≤ ⅓ of the sequential estimate for ≥ 120 partitions, 4 MiB+1 partition returns `Capacity`; characterization tests for first-error precedence, scope-cap partition, jitter equality and cancellation (these pass on the base and must stay green). Green: `forecast_lookup`/`Looked`/`Counted`, `ForecastScope::admit`, `read_partitions` with `buffered(READ_AHEAD)`, store limits.
3. **R3a cached weight.** Red: a `#[cfg(test)]` counter of full weight walks shows quadratic growth on the base; cached-equals-recomputed and store-decision-versus-oracle tests are written first and pass on the base. Green: `Weight` cache in `Doc`, exact delta maintenance in `try_set`, `checked_store_with_limit` over cached weights.
3b. **R5 owner hand-off.** Red: a waker registered by the next owner observes the workspace budget at its wake-up and sees the previous 192 MiB lease still counted. Green: declare the lease before the owner permit. Then rerun the whole `domestic` binary with 4 threads.
4. **R3b borrowed row lookup.** Red: `Row::str_is` is absent; equality tests against `Row::get` (own, template, missing, non-string, `0xF4` canonicalization). Green: `str_is` and `find_or_create`. Then re-profile and remove further per-read copies only where the profile and equality tests justify it (R3.3, R3.4).
5. **Documentation and diagrams.** D2 architecture section, operator guide, `server2.json` card, rebind `server2-cold-read` to the implementation commit; Archify `finalize` and `visual-check` for both sources; declaration file; documentation assessment.
6. **Verification and evidence.** Full self-verification (below), selected evidence under `docs/evidence/tasks/issue-2849-cold-build-speed/`, then the Seoul host matrix when AK confirms the launch.

Dependencies: step 1 before 2; steps 2–4 in order (measured separately); step 5 after code is final; step 6 last. A change to R1–R3 behavior after step 2 starts is recorded as a dated design amendment.

## Migration, rollback and blast radius

No stored-data, wire or configuration change; rollback is reverting the PR. The blast radius is the forecast read path of the domestic KMA source (all Grid, RSS and Mid keys) and every consumer of `Doc` (accounting only; equality, cloning results and `Debug` are unchanged). The process S3 gate is shared: a cold build may hold all 12 permits while it reads (recorded in the spec; resizing is a separate decision for AK).

## What could break, riskiest part, rejected alternatives

- Riskiest: the cached `Doc` weight returning a stale value (wrong accept/reject at a cap) and the ordered-consumption equivalence of the concurrent read. Proof: cached-equals-recomputed under random operation sequences, store decisions equal to the old recomputation at exact boundaries, jitter-versus-serialized equality, fault precedence in partition order, goldens, and the unchanged owner/epoch tests.
- Also: lookups beyond a failing partition may have started (documented, results discarded); timing assertions (use peak concurrency and operation counts first, wide ratios second); the stacked base is unmerged, `CONFLICTING` and under review, so the branch may need a rebase; the base CI is red on 4 tests (see step 0).
- Rejected: `buffer_unordered` plus sort, spawned per-lookup tasks, charging in-flight bytes to the workspace, sampled weight checks, per-collection weight vectors and resizing the S3 gate (reasons in the design record).
