## Screen placements

| Screen and source | Anchor in the outer vertical scroll | Visibility and sizing |
| --- | --- | --- |
| Hourly · [WeatherPageView](../ios/TodayWeather/Weather/WeatherPageView.swift) | After the entire hourly chart, including expanded rows, and hourly AQI when present. Before current air readings or detail cards. | Require the actual rendered hourly chart. The block list contains a chart entry even when no chart can render. Compact card. |
| Daily · same forecast view | After the daily chart, optional air outlook and the **whole** horizontal day-details row. Before attribution. With optional sections absent, use the last rendered section after or including the chart. | Require a rendered daily chart. Keep the card outside the horizontal scroll. Compact card. |
| Air · [AirPageView](../ios/TodayWeather/Air/AirPageView.swift) | After current grade, guidance and the hourly AQI chart when available. Insert before detailed pollutants, preserving the existing relative order of air sections. | Require meaningful air content. Compact card. |
| Saved places · [PlacesView](../ios/TodayWeather/Places/PlacesView.swift) | After the last **visible** saved row. | At least one visible saved place in ordinary list mode. Search, results, edit and empty list suppress the card. Stacked card. |

Measure compact versus stacked using the same creative, phone width and default text size. Target roughly half the stacked height on Hourly, Daily and Air. Let content grow for Dynamic Type. Keep the localized ad label, AdChoices, media and registered CTA visible with SDK-owned click targets. Keep the surrounding whitespace inert. The native host owns load identity per placement and visit. Omit the entire slot and margins on no fill. Ignore stale callbacks after consent, screen or city changes. Once a reader has reached the anchor, defer a late creative until another visit. Do not mark an anchor reached merely because an eager SwiftUI stack constructed its children.

## Forecast transition and privacy rules

1. Observe a visible forecast to persist the Hourly or Daily seen flag for the local date. A cold start, notification or widget arrival can mark visibility. Route the draw only through an intentional foreground tab-bar tap. [CurrentPositionPopups](../ios/TodayWeather/Start/CurrentPositionPopups.swift) must retain first refusal when no place is enabled. Preserve programmatic selection, tab reselect and refresh semantics.
2. The source and destination must be opposite forecast tabs, the user must have scrolled vertically beyond the source chart into details during this visit, and the destination must already have been seen today. Reset the read state when leaving the visit or changing cities. A horizontal chart gesture, resize, background return, alert, back or deep link cannot qualify a transition. A ready presenter, consent and enabled format are prerequisites before drawing once. A draw below 0.10 qualifies. A draw of 0.10 or above navigates directly.
3. The policy owner serializes taps and saves the local date, both flags and a shared spent flag as **one durable record** per installation across all cities. Reserve before calling the SDK. Use acknowledged atomic persistence; an asynchronous preference write alone cannot prove the reservation survived process death. On write failure, navigate without showing. Release only for a confirmed pre-display failure for that reservation. Keep an ambiguous reservation spent after restart. Reset only on a later local date, fail closed on clock rollback and account for a display crossing midnight. Completion of a single presentation opens its intended destination once.
4. Reuse [AdsConsent](../ios/Core/Sources/TWDomain/Ads/AdsConsent.swift) and [AdRequestRule](../ios/Core/Sources/TWDomain/Ads/AdRequestRule.swift). Respect UMP readiness, the existing ATT/TCF personalization decision and non-personalized request parameters. UMP owns the ATT prompt. Keep usage analytics opt-in separate. On loss of eligibility, discard pending and ready creatives for the affected format. Propose `TW_ADMOB_NATIVE_IOS` and `TW_ADMOB_INTERSTITIAL_IOS` via the private release config, and reuse Android's `tw_native_enabled` and `tw_interstitial_enabled` keys. Confirm iOS targeting, defaults and fetch behavior in the release environment. Never repurpose a banner unit or copy an Android unit into an iOS build.

## User scenarios and acceptance checks

| Issue criterion | User, prerequisite and ordered actions | Expected result and failure coverage |
| --- | --- | --- |
| AC1 · Read content on an iPhone | A reader has populated forecasts, air data and a saved place. Open all four screens, scroll past each anchor and interact with charts and tabs. Repeat with missing AQI, no chart, empty/search/edit states, narrow width and large text. | At most one correctly sized, labeled card at each eligible position. All forecast content and safe areas remain usable. Delay the creative past the anchor, return no fill and rotate the device. No blank margin, scroll jump or late overlay. Verify with app-hosted layout checks and iPhone test-ad screenshots. |
| AC2 · Revisit a forecast | With an eligible ready test ad, open Hourly, read its details, tap Daily for the first time, read Daily details, then tap Hourly. Repeat starting on Daily. In separate deterministic runs supply 0.0999 and 0.10. | Both first visits open immediately. Only the eligible revisit draws. The lower draw can display once; the upper draw proceeds directly. Repeat without scrolling past the chart, without an ad, with a reselect and with an SDK failure. Assert draw count, show count and exactly one destination arrival. |
| AC3 · Retain the daily cap | After an eligible show, double-tap, switch city, relaunch and try the reverse direction. Advance through local midnight, repeat first visits, then roll the clock back. Exercise cold and warm notification/widget entry. | One shared allowance across cities, tabs and restarts. The later date starts with both first visits protected. A backward date cannot reopen an allowance. Test crash after reserve, confirmed pre-show failure, duplicate callbacks and midnight between reserve and display. A notification or widget opens its content directly. |
| AC4 · Control serving and measurement | On a fresh install exercise SDK/UMP readiness in both callback orders and vary ATT/TCF choices. Toggle each format off separately with a load in flight. Toggle optional usage analytics and observe the test adapter and telemetry. Inspect a private Release archive before distribution. | No early request, stale display or second ATT prompt. Requests follow the existing personalized/non-personalized rule. Each kill switch suppresses its own format. Only opted-in, recognized format events are sent. The release archive resolves valid iOS units of the intended formats, without logging IDs. |

Use `swift test --package-path ios/Core` for policy, consent, Remote Config and schema checks. Use the repository's [Xcode test command](../ios/README.md) for shell and adapter integration, including existing screenshot and privacy regressions. Adapt banner-specific assertions to the new behavior; retain unrelated Cordova reference fixtures and the selected-tab accent. Run the separate device smoke with Google test creatives and isolated test inputs. Verify dismiss, navigation and ad attribution without clicking live inventory.

## Release prerequisites and recovery

Debug implementation can start with test units. Before an authorized TestFlight or App Store release, the release owner must verify private iOS app and format-specific units against their AdMob registrations and check the effective remote settings. Those inputs and live serving were not verified during planning. Disable the affected format through its own remote switch if a release moves content, interrupts ineligible navigation or bypasses consent. With either format disabled, the weather app remains usable. After release, compare impressions and estimated revenue by format and revenue per active user by version, alongside consent coverage, retention and crash health under [#2654](https://github.com/WizardFactory/TodayWeather/issues/2654). Record the actual store version, rollout state and serving evidence separately.
