# Parity checklist (AN-18)

This checklist records how the native app in `android/` reproduces the Cordova 1.1.1 app (#2897, part of #2877). It covers the screens S01–S12 with their dialogs, and the shell and app-wide elements that have no spec ID (X1–X11). Removed and unreachable items are listed at the end for completeness.

**Parity oracle.** The Cordova source at the pull request's base revision, the [Cordova user manual](../docs/user/cordova-app/README.md) and the rewrite specification ([screens](../docs/rewrite/screen-specifications.md), [overlays](../docs/rewrite/screen-overlays.md)). Where they disagree, the current source wins ([spec](../specs/android-native.md#behavior-to-retain)).

**Columns.**

- **ID:** S and O IDs are the rewrite specification's. X IDs are local to this checklist.
- **Cordova reference:** pages of the [manual](../docs/user/cordova-app/manual.pdf) (page N is step N of `manual.json`) and the spec section. "(text)" marks a page that describes the item without showing it.
- **Native evidence:** test classes, with the method where one test is specific (`Class#method`). Tests are JVM or Robolectric tests in `app/src/test` unless marked. (core-data), (core-domain) and (core-storage) mark those modules' `src/test`. (device) marks instrumented tests in `app/src/androidTest`, which run only through the scripts in `tools/` ([README](README.md)). A marker covers the classes between it and the previous semicolon or period. Reference sets are Cordova captures in `app/src/test/resources/<set>/` (charts: `core-domain/src/test/resources/chart-reference/`), compared within recorded tolerances. Historical sets are 384×832 dp at density 2 unless noted. The [four-size matrix](tools/parity-reference/README.md) adds separate 384×832, 360×780, 412×892 and 320×694 dp captures, measured WebView extents and 1096 declared Korean/English comparisons. Existing reference suites remain intact.
- **Accepted differences:** the A, B and C rows of [`tools/corpus/differences.md`](tools/corpus/differences.md), and the other A and D IDs of the rewrite [decisions](../docs/rewrite/decisions-and-open-questions.md), each with its decision and meaning. Kept anomalies are listed too: the native app reproduces them on purpose.
- **Status:** "Covered" when each element of the row has native evidence. "Covered; PR n adds …" when a later AN-18 pull request adds the rest. "PR n" when the evidence is still to come. "Not built" for removed or unreachable items.

**Decisions behind the accepted differences.**

1. **The AN-06 record** (#2885; [plan](../plans/android-native.md#an-06--spike-review-estimate-and-decisions-2885), [intent](../intent/android-native.md#an-06-decisions-recommended-defaults-ak-2026-11-08)). Cordova anomalies are kept unless AK approves a fix. A01 is fixed: a response applies to the place that requested it. The free-form weather-address fallback (the record's "weather-address 501"; see O03), A24, the 12:00 AM picker and D37 are kept. Text follows the system font scale, verified up to 1.3. Rows write "kept (AN-06)" or "fixed (AN-06)"; "kept (AN-06, AN-12)" names the sub-issue that applied the rule.
2. **Recorded differences:** the rows of `differences.md` marked "Differ (AN-xx)". Sub-issue AN-xx recorded each one under AK's acceptance of the recommended defaults on 2026-11-08 ([intent](../intent/android-native.md#source-and-authority)). Rows write "Differ (AN-xx)".

Layout changes for larger text that only the plan or the README records follow from the font-scale decision (X9). D41 (device classes and rotation) has no decision yet; see the note after the X table.

**Delivery.** AK decided on 2026-11-11 that AN-18 ships as four pull requests ([intent](../intent/android-native.md#an-18-decisions-ak-2026-11-11), [plan](../plans/android-native.md#an-18--parity-verification-large-screens-and-the-user-manual-2897)):

- **PR 1:** this checklist, the request-path tests (X11), and tests for the checklist's small gaps: the location glyph, O08 on S03, O09, O17 on S01 and S02, S01's banner and keyboard rules, and the status bar.
- **PR 2:** fit checks for every screen and dialog at phone, tablet and foldable sizes, in both orientations, in split windows and at font scale 1.3; a run on tablet and foldable emulators. Delivered in AN-18b, including the subsequent disabled-scroll and S01 reachability corrections.
- **PR 3:** Cordova captures and comparisons at 384×832, 360×780, 412×892 and 320×694 dp for representative states of each screen and its main dialogs, in Korean and English; native Compose popups matching the original appearance for O03 `weather`, O08, pollen X2 and O15; the missing theme states. The matrix entry in each affected row links its native comparator and maintained capture contract. No Ionic or Cordova runtime is used by the native app.
- **PR 4:** the [native user manual](../docs/user/android-app/README.md): 44 illustrated steps, editable source, actual API36 captures and a rendered PDF.

**D41, device classes and orientation.** The native app supports every device class and orientation (AN-07 AC3) and recomputes its sizes on rotation. A Cordova view kept the sizes of the orientation it opened in ([spec](../docs/rewrite/screen-specifications.md#device-classes-and-orientation)); the hourly chart's opening column (A49) stays kept. The rewrite left D41 open, and the AN-06 record has no decision on it. AN-18 PR 2 applies the existing AN-07 AC3 and AN-18 AC4 requirement: native content follows its current window, including split screen, instead of freezing the opening display dimensions. `WindowMetricsTest` verifies this on API 24 and 34. This is a deliberate difference for device/window support; A49 is unchanged.

**Four-size renderer limits.** The matrix uses API36 WebView references and SDK34 Robolectric native rendering. Pixel tolerances preserve independent geometry/text/fit checks. English S12's open-circle warning glyph is smaller in Robolectric's fallback font and can shift wrap positions while preserving the text and line count; per-case tolerances record that limit. Most card heights match exactly; some fractional CSS extents differ by one physical pixel. Captured weather backgrounds are input only for isolated dialog/photo-header comparisons. Notification popups use the actual native weather fixture. These checks do not establish API24 device parity or production-provider behavior.

**Differences without a screen.** B18 Differ (AN-16): `todayweather://N` opens place N, where 1.1.1 registered no scheme (`EntryLinkTest` (core-domain); `ShareTest#linksQueueTheirPlaceIndex`; `EntryLinkDeviceTest` (device)). B19 Differ (AN-16): the backup keeps the user's data only (`BackupRulesTest`; `BackupRestoreTest` (device)).

## Maintenance

- Update a row in the pull request that changes its screen or dialog, a test it names, a reference set or an accepted difference.
- A later AN-18 pull request replaces its "PR n" statuses with the evidence it adds.
- Record a new difference in [`tools/corpus/differences.md`](tools/corpus/differences.md) with the sub-issue that decides it, then name it in its row.
- Keep each test name and link resolvable: a renamed test or a moved reference set changes its rows. `ParityChecklistTest` (app) fails on a missing row, a row without evidence, a broken link or anchor, or a test that does not exist.
