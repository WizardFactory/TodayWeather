# Security and privacy inventory

This inventory records the current trust boundaries, credential locations and personal-data flows of the TodayWeather/TodayAir server and clients at source baseline `bd6640f2`, re-baselined 2026-09-25 from `ff7acf3996ccb66c912d2ed4710cf300197d6966`. Client, iOS widget and Apple Watch source is identical to `ff7acf39`, and so are the server routes, the push/alert models (`modelPush.js`, `alert.push.model.js`), `log.js` and the `v000803` gate; five forecast model files did change upstream (`modelShort.js` in 49afbbea; the mid land/temp models in 95fe711e) but hold no personal data. The upstream server changes that affect this inventory are listed in [section 7](#7-upstream-changes-since-ff7acf39). The static web PWA is covered in [section 3.2](#32-web-pwa-browser-data-web) and the last row of [section 4](#4-cors-sessions-and-http-hardening), at branch `webapp-docs-gap-corrections`. Rows are **observed source** unless labelled otherwise. **Library semantics** marks behavior inferred from the documented behavior of a pinned dependency; `server/node_modules` is not installed, so it was not executed. **Deployment observation** marks a dated AWS or host fact taken from [AWS/code correlation](../architecture/aws-code-correlation.md), [EC2 internals](../architecture/ec2-internals.md) or the [traffic report](../../reports/aws/api-traffic-2026-09-22.md). **Proposal** marks requirements and tests that do not exist yet. No server, collector, provider, database, AWS call, simulator or HTTP probe was run. Credential values, literals, key material, ad/analytics identifiers and private hostnames are never reproduced: rows give the variable or constant **name** and a `file#Lnn` location instead.

**How to use during a rewrite.**

1. Treat [section 1](#1-endpoint-authentication-classes) as the list of exposures a replacement must deliberately keep, replace or retire. None of the current checks is a control worth copying unchanged.
2. Build the secret-store schema and the rotation list from [section 2](#2-secret-and-credential-locations-names-only). Every hard-coded literal has been committed to Git and should be treated as exposed.
3. Answer the open privacy question in [missing evidence before release decisions](decisions-and-open-questions.md#missing-evidence-before-release-decisions) with [section 3](#3-personal-and-device-data): it lists what is collected, sent, stored and logged today.
4. Turn [sections 5 and 6](#5-rewrite-requirements-proposal) into acceptance criteria and tests before the replacement serves public traffic.

Related references: [API endpoint catalog](api-endpoint-catalog.md) (every mount, the [shared request pipeline](api-endpoint-catalog.md#shared-request-pipeline-and-exposure) and the [gate mechanics](api-endpoint-catalog.md#authentication-and-gating)), [configuration inventory](configuration-inventory.md) (per-name loading and defaults), [push notifications](../architecture/push-notifications.md), [push text and purchase validation](server-push-and-purchase.md), [client analytics and persistence](client-state-and-behavior.md#analytics-and-error-reporting), [external providers](external-providers.md).

### 1.1 v000803 POST gate

The request flow is in the [catalog](api-endpoint-catalog.md#authentication-and-gating). Security properties:

- **Credentials.** The login `id` and `password` are compared with a hard-coded literal pair ([L51-L52](../../server/routes/v000803/index.js#L51-L52)). Tokens are signed with RS256 only if `./config/jwt-private.pem` existed when the asynchronous `fs.exists` callback ran ([L8-L18](../../server/routes/v000803/index.js#L8-L18)). Otherwise the fallback is HMAC with a hard-coded literal secret ([L58](../../server/routes/v000803/index.js#L58)). No `.pem` file is in the checkout.
- **Password inside the token.** The signed payload includes the submitted `password` ([L56](../../server/routes/v000803/index.js#L56), [L58](../../server/routes/v000803/index.js#L58)). A JWT payload is only base64url-encoded (JWT format), so every issued token discloses the login literal.
- **Token logging.** The issued token is passed to `log.debug` ([L62](../../server/routes/v000803/index.js#L62)). With the checked-in logger (console `info`, or `error` under production; Logentries `info`, [log.js#L17-L33](../../server/lib/log.js#L17-L33)), debug lines are not emitted. The service host's `log.js` has local edits ([EC2 internals](../architecture/ec2-internals.md#deployment-identity-and-repository-differences)), so the deployed behavior is unknown.
- **No signature check.** The token branch calls `jwt.decode` ([L81-L86](../../server/routes/v000803/index.js#L81-L86)), which parses without verifying (jsonwebtoken 5.x library semantics). The only test is `idBearerToken[decode.id] === decode.app` ([L88](../../server/routes/v000803/index.js#L88)). Both operands come from unverified claims, and the map is a JavaScript array ([L22](../../server/routes/v000803/index.js#L22)). A forged, unsigned token can therefore satisfy the comparison without any prior login: one that omits both `id` and `app` compares `undefined === undefined`, and one whose `id` names a built-in array property can match that property's value. This is JavaScript semantics, checked with `node -e "var m=[], d={}; console.log(m[d.id]===d.app)"` and `node -e "var m=[]; m['x']='y'; console.log(m['length']===0)"` (both print `true`); it was not executed against the route.
- **Per-worker state.** The map lives in one process and is filled only by the worker that served the login ([L61](../../server/routes/v000803/index.js#L61)). With ten PM2 cluster workers (deployment observation), a legitimately issued token is rejected by the other nine workers until each serves a login, and every restart empties it.
- **Failure bodies leak stacks.** A missing `id`, wrong credentials and mismatched claims call `res.render('error', {error: err})` ([L45-L49](../../server/routes/v000803/index.js#L45-L49), [L70-L74](../../server/routes/v000803/index.js#L70-L74), [L97-L101](../../server/routes/v000803/index.js#L97-L101)). [`views/error.jade#L6`](../../server/views/error.jade#L6) prints `error.stack`, so these HTML 500 responses contain server file paths under any `NODE_ENV`. A token that does not decode makes `decode` null. `decode.id` then throws, and the error reaches Express's final handler ([error sink](server-response-assembly.md#error-sink-for-propagated-failures)).
- **Callers.** None: `grep -rln "/gather\|/req/\|bearertoken" client/www/js tw.ios/widget ta.ios/widget applewatch/www/js` returns no file. The catalog infers that CloudFront's default behavior does not forward a `bearertoken` header.

### 1.2 `/req` requester commands

### 3.1 Log sinks and levels

- **Application logger.** [`server/lib/log.js`](../../server/lib/log.js) always adds a console transport at `info`, raised to `error` when `NODE_ENV=production` ([L17-L25](../../server/lib/log.js#L17-L25)).
  - It adds a Logentries transport at `info` whenever `config.logToken[config.mode]` is non-empty ([L12](../../server/lib/log.js#L12), [L27-L33](../../server/lib/log.js#L27-L33)). Only `gather` and `service` have entries, and an unset token defaults to a non-empty placeholder ([configuration §1.3](configuration-inventory.md#13-observability)).
  - In production `service` mode, `info` lines therefore go to Logentries, a third-party service, and not to the console. Those lines include URLs with coordinates, device IDs, push bodies with tokens and receipt bodies. This is a source reading: the service host's `log.js` has local edits ([EC2 internals](../architecture/ec2-internals.md#deployment-identity-and-repository-differences)), so the deployed destinations are unknown.
  - `local`, `scrape` and `push` modes log to the console only. Under `NODE_ENV=production` that means `error` lines only.
- **Express final handler.** It writes `err.stack` to `console.error` for every 404 and unhandled error (library semantics; see the [error sink](server-response-assembly.md#error-sink-for-propagated-failures)). This bypasses the application logger. Deployment observation: PM2 captures stdout and stderr under `~/.pm2/logs`, rotated by `pm2-logrotate` with a 10 MB size limit and five retained files ([EC2 internals](../architecture/ec2-internals.md#startup-logging-and-operational-boundaries)).
- **New Relic (removed upstream).** At `ff7acf39` the agent was the first `require` in `app.js`, and `server/newrelic.js` set only `app_name`, `license_key` and `logging.level`, so every attribute and capture setting was an agent default. `c80ee014` removed the `require`, the file, the config key and the package ([app.js#L7-L23](../../server/app.js#L7-L23)). A process built from `bd6640f2` sends nothing to New Relic. The 2026-09-20 service host ran an older checkout with New Relic 4.13.0 installed (historical deployment, [EC2 internals](../architecture/ec2-internals.md#deployment-identity-and-repository-differences)). What that agent transmits was not verified.
- **Visual Crossing lines (#2585).** The requester logs failures at `error` and successes at `info`, with coordinates rounded to two decimals and the key scrubbed. `DsfController` logs slow or failed fetches and stored-record fallbacks at `error`; lock keys in its lines are rounded to two decimals. So under `NODE_ENV=production` these lines reach the console and PM2 logs. Daily provider usage is kept in Mongo (`vc.usage`: calls, records, failures, 429s, slow calls per UTC day) rather than in logs.
- **Edge and host logs.** nginx access and error logs, CloudFront standard logs and gateway Lambda logs are deployment-side. Their fields and retention beyond the cited observations were not inventoried.

## 5. Rewrite requirements (proposal)

None of these is implemented or decided. Each needs an owner and a decision record ([decisions and open questions](decisions-and-open-questions.md)).

1. **Separate operations from the public API.** Do not mount collection, test or requester routes on the public listener. Run scheduled work in a worker that calls functions directly, or through an authenticated internal endpoint on a private listener. Retire the version-prefixed `/gather` copies, which have no caller.
2. **Retire or replace the v000803 POST gate.** It has no caller. If any authenticated client API is needed, verify signatures with a pinned algorithm, keep keys in a secret store, never put passwords in token claims, and share validation state across processes or make it stateless.
3. **Retire `/req` or put an authenticated administrative interface in its place.** Remove the runtime key-injection command (`add_key`) and every hard-coded internal key.
4. **Remove committed literals and rotate.** Rotate every literal listed in [section 2](#2-secret-and-credential-locations-names-only) that ever reached an environment, and add secret scanning over the repository, its history and built client bundles.
5. **Drop the unused session middleware**, or back sessions with a shared store and a managed secret. API responses should not set cookies.
6. **Define an explicit CORS policy per route class.** Wildcard read access can stay for public `GET` data if intended. Write routes should not rely on CORS for protection.
7. **Bind push writes to device ownership.** Decide how a caller proves it owns a token before replacing or deleting records, for example a server-issued installation credential. Validate token and coordinate formats, and rate-limit the push routes.
8. **Redact and bound logs.** Use structured logs that never contain push tokens, receipts, device identifiers or full request bodies; truncate or omit coordinates. Define retention and access for every sink: application logs, third-party log services, PM2/stdout, nginx, CloudFront, Lambda and analytics.
9. **Define retention for stored personal data.** Push records store coordinates, names, tokens and device IDs with no expiry. Decide cleanup for disabled or unregistered tokens and for inactive devices.
10. **Return error bodies without stacks.** Use a documented error contract (see D03 in [decisions](decisions-and-open-questions.md#compatibility-and-operational-decisions)) and log through the application logger.
11. **Encrypt every hop.** Use HTTPS from the edge to the origin and from the gateway and workers to the service, and authenticated, encrypted database connections. Restrict ATS exceptions and the Cordova allowlists to the hosts the app needs, and set a real CSP.
12. **Client-embedded keys.** Keep provider keys out of the client unless the provider supports application restrictions. Stop mirroring configuration keys into user storage. Send only what the privacy decision allows to analytics ([client analytics](client-state-and-behavior.md#analytics-and-error-reporting)).

## Limitations

- **Source and library reading only.** Nothing here was executed against a running server. Library behavior (`cors`, `express-session`, `jsonwebtoken` 5.x `decode`, Express `finalhandler`, `in-app-purchase` verbose logging, and New Relic defaults for the historical agent) is taken from the pinned dependencies' documented semantics without installing them.
- **Deployment facts are dated.** CloudFront behaviors, HTTP origins, PM2 worker count, host logger edits and the deployed `API_SERVER` value come from the 2026-09-20 and 2026-09-22 observations. Recheck them before an operational decision. Gateway Lambda code, its logs and DynamoDB contents are outside this checkout.
- **Deployed configuration unknown.** Which secret names are actually set, whether the `.pem` and service-account files exist on any host, and where the host's modified `log.js` sends lines were not inspected.
- **Not covered.** Git-history secret scanning; Android widget and plugin code from external repositories; Apple Watch networking beyond the [configuration inventory](configuration-inventory.md#4-native-hard-coded-constants); Mongo access control; the separate gather and push hosts; third-party processors' own retention (Logentries, New Relic on older deployments, Google Analytics, Fabric, FCM and the APNs relay behind it, providers).
- **Counts are revision-bound.** The 10 URL-logging calls and 100 `req.sessionID` references come from the commands quoted above at `bd6640f2` (101 at `ff7acf39`; `controllerTown.js` lost one). The route counts come from the catalog; no route file changed between the two revisions. Multi-line log calls that do not start on the matched line are not counted.
