# External provider catalog

This catalog lists every upstream service the checked-in server calls, one row per endpoint family: host and path pattern, payload format, calling module and function, trigger, timeout and retry, credential **environment variable names** (never values), key rotation and quota/error detection, and reachability status. Evidence is **observed source** at baseline `bd6640f2` (re-baselined 2026-09-25 from `ff7acf3996ccb66c912d2ed4710cf300197d6966`; client source identical to `ff7acf39`). Rows whose code changed upstream were re-read and cite the commit; the others were carried over with anchors moved only where the lines are text-identical. No provider, database, collector or AWS API was called while writing it; a documented URL, key name or detection string does not prove that the provider still accepts the request.

Products, schedules and freshness are already covered elsewhere; this file links to them rather than repeating them:

- [Weather collection](../architecture/weather-collection.md): Manager minute schedule, scraper cadence, KMA fetch/normalize/persist, Visual Crossing/WAQI request-time fills.
- [Server data lifecycle](server-data-lifecycle.md): product and storage map, process modes, freshness boundaries, rewrite dependency inventory.
- [AWS/code correlation](../architecture/aws-code-correlation.md): the gateway geocoder Lambda (Kakao/Google/Dark Sky outside this checkout) and the KAQ image producer.
- [Push notifications](../architecture/push-notifications.md#provider-submission-and-app-handling): Firebase Admin and legacy GCM submission (direct APNs was removed upstream in 45b2eb3f). Push providers are not repeated here; see also [server push text and purchase validation](server-push-and-purchase.md).
- [Configuration inventory](configuration-inventory.md): every environment name with its default and secret classification. This file lists only the names each provider row uses.
- [Gather source reconciliation](../architecture/gather-source-reconciliation.md) (upstream #2555): the KMA endpoint migration in K1–K4, response validation, service-key encoding and the period caveats of the new categories. [Historical ASOS recovery](../architecture/weather-collection.md#historical-asos-recovery-2564) (upstream #2564): scheduling and operator contract for H1.

**How to use during a rewrite.** Treat each row as an integration to re-establish or retire deliberately: obtain current provider documentation and credentials, record a raw fixture for each active row, and decide how the replacement detects quota and authentication failures. The legacy code often treats every non-success response as "retry later", so provider outages, expired keys and exhausted quotas look alike in its logs. Do not reproduce hosts from this table without confirming that they are still the provider's supported endpoints; several are HTTP-only (including the migrated KMA forecast host), one is a raw IP address, one is a provider test host, and source comments already mark the Daum API as unavailable (G8).

## Legend

| Field | Values used below |
| --- | --- |
| Trigger | **Manager minute**: `Manager.checkTimeAndRequestTask()` in `gather`/`local` mode, usually by self-HTTP to `/gather/<name>` ([schedule](../architecture/weather-collection.md#schedule-as-implemented)). At startup one forced pass (`putAll`) also queues every Manager-minute task except the rain hit-rate job, regardless of minute or hour gates ([Manager L2352](../../server/controllers/controllerManager.js#L2352)). **Scraper**: `Manager.startScrape()` jobs in `scrape`/`local`. **Startup**: once from `Manager.startManager()`. **Request-time**: inside an API request. **Route only**: an HTTP handler exists but no internal dispatcher calls it. |
| Timeout | The value passed to the HTTP client. "None set" means `request`, `axios` or `get-pixels` defaults with no explicit timeout in repository code. |
| Credential | Environment variable names read by [`server/config/config.js`](../../server/config/config.js). List-valued names hold a JSON array string that callers `JSON.parse`. |
| Status | **Active path**: reachable from startup or a mounted route used by the current collectors or API. **Legacy route only**: reachable only through an older mounted route. **Legacy module**: code exists but no reachable caller was found. **Viability unverified**: an added qualifier when the source itself gives a specific reason to doubt the host or contract (historical provider contract, versioned path, test host, undocumented endpoint, forced legacy TLS). Nothing was checked live. |

Dead-code findings in this file come from `grep -rn` over `server/` excluding `node_modules` and `server/test`; they state that no caller was found, not that a deployed revision lacks one.

## Domestic air: AirKorea and KAQ

All AirKorea rows share one requester instance, [`Keco`](../../server/lib/kecoRequester.js), configured at startup with the key list ([Manager L2305-L2307](../../server/controllers/controllerManager.js#L2305-L2307)). Requests go through [`_jsonRequest`](../../server/lib/kecoRequester.js#L192) (`request` with `json:true`, no timeout; HTTP ≥ 400 → error).

**AirKorea key rotation, shared by A1–A3.** Each logical call starts with the **last** key in `AIRKOREA_SECRET_KEYS` and steps to the previous key when [`_checkLimit`](../../server/lib/kecoRequester.js#L678-L689) matches `LIMITED NUMBER OF SERVICE REQUESTS EXCEEDS ERROR` or `DEADLINE HAS EXPIRED ERROR`. Only string bodies, which the JSON parse leaves as text, are checked. After the first key is exhausted the call fails with `EXCEEDS_LIMIT`. The rotation position is not remembered between calls. `setServiceKeys` logs the whole key list at `info` level ([L87-L90](../../server/lib/kecoRequester.js#L87-L90)).

### Image-derived hourly air forecast

The app always sends `airForecastSource=kaq` ([service.weatherutil.js#L87](../../client/www/js/service.weatherutil.js#L87); push settings set the same value at [service.push.js#L165](../../client/www/js/service.push.js#L165)). The read uses the latest stored map case as `'modelimg' + <stored map_case.asp body>`, then `modelimg_CASE4`, and takes the first of the two with records dated after now − 1 day. The series is then graded by the requested standard ([glossary §5](domain-glossary.md#where-each-standard-is-applied)). Every stored value comes from the colours of the A7 GIFs. **Calibration dependence (source reading, not executed).** Five `size` keys (`map_width`, `map_height`, `gap_width`, `gradient_step_width`, `gradient_step_height`) and `so2_pixel_pos` are read, but the checked-in `config.js` never defines them, so no environment variable can supply them either ([configuration inventory §1.7](configuration-inventory.md#17-configuration-paths-referenced-but-never-defined)). With `KAQ_KOREA_IMAGE_SIZE_WIDTH`/`HEIGHT` unset, `size.width`/`height` default to `'0'`, so `_isValidImage` rejects every GIF as `INVALID_IMAGE` before any projection ([parser L69-L93](../../server/lib/kaq.finedust.image.parser.js#L69-L93)). When those two values do match the GIF size but the undefined keys stay undefined:

- **No value is derived.** The pixel spacing is `NaN`, so `x` and `y` are `NaN`. Each pixel read then returns `undefined` (ndarray semantics, not verified here because `server/node_modules` is absent). No legend entry matches exactly, and the CIEDE2000 difference is `NaN`, which never passes `< 2.6`. Every frame is dropped.
- **SO2 can throw.** When the CASE4 SO2 GIF passes the size check, `getImagePos('CASE4_SO2')` reads `.left` of `undefined` inside the `get-pixels` callback. The resulting `TypeError` is raised from a library callback, and `server/` registers no `uncaughtException` handler (`grep -rln "uncaughtException" server --exclude-dir=node_modules` returns nothing). SO2 is the last CASE4 pollutant, and station values are written only after all five images are read. If the throw ends the process, that run stores nothing.
- **The `modelimg` case throws on construction.** `config.image.kaq_korea_modelimg_image` is also undefined, and the constructor's `getDefaultCoordi('modelimg')` reads `.coordi` from it ([L44](../../server/controllers/kaq.modelimg.controller.js#L44), [parser L42-L46](../../server/lib/kaq.finedust.image.parser.js#L42-L46)). How that throw propagates through the `async` and Mongoose callbacks was not traced.

The deployed gather configuration is unknown. The service host's `config.js` has tracked edits whose calibration keys were not recorded, and the gather host was not inspected ([EC2 internals](../architecture/ec2-internals.md#deployment-identity-and-repository-differences)). The earlier KAQ OCR failures also remain open there. A rewrite should either obtain the deployed calibration and characterize the decoder with a synthetic GIF, or replace this source with a provider API (proposal).

## Legacy world routes and modules

An older world stack is still mounted beside the active overseas (DSF-named) path: `/ww` and `/req` ([app.js L105-L106](../../server/app.js#L105-L106)), plus the non-`KR` branch of the legacy `/geo/:lat/:lon` route (G4). It runs through [`ControllerRequester`](../../server/controllers/worldWeather/controllerRequester.js) and [`ConCollector`](../../server/controllers/worldWeather/controllerCollector.js). Reachability rules that decide the status column:

- **Collector timer.** `ConCollector.doCollect()` ([L2015-L2025](../../server/controllers/worldWeather/controllerCollector.js#L2015-L2025)) has no caller, so `global.collector` is never set. Each request builds a new collector, whose `ControllerKeys` counters start from zero (see [per-request key counters](#world-weather-air-and-time-zone)).
- **`/req/:category/:command`** ([routeRequester L26](../../server/routes/worldweather/routeRequester.js#L26)). `checkKey` sets `validReq = false` when `key` is missing, but `runCommand` never reads that flag ([L31-L41](../../server/controllers/worldWeather/controllerRequester.js#L31-L41), [L133-L151](../../server/controllers/worldWeather/controllerRequester.js#L133-L151)). The only gate is that the category is in `all, met, owm, wu, dsf` and the command in `get_all, get, req_add, req_two_days, add_key` ([L14-L15](../../server/controllers/worldWeather/controllerRequester.js#L14-L15)), so any caller can make `req_add` and `req_two_days` spend provider quota. `get_all` starts `runTask` only for category `WU` in upper case, which the lower-case list rejects, so the WU/DSF collection functions behind `runTask` cannot be reached over HTTP. `add_key` needs `global.collector` and always answers `Fail`.
- **`/ww/010000/{current,forecast}`** (`queryWeather`, [L169](../../server/controllers/worldWeather/controllerWorldWeather.js#L169)). When the city or coordinate is not in the stored geocode list ([L213-L236](../../server/controllers/worldWeather/controllerWorldWeather.js#L213-L236)), it sends a self-HTTP request to `config.url.requester` + `req/all/req_add` ([`requestData`](../../server/controllers/worldWeather/controllerWorldWeather.js#L3336-L3388)). `config.url.requester` is `http://<OPENSHIFT_NODEJS_IP or 127.0.0.1>:<OPENSHIFT_NODEJS_PORT, PORT or 3000>/` ([config L74](../../server/config/config.js#L74)), the request has a 20 s timeout, and the `key` value is a hard-coded literal at [controllerWorldWeather.js#L3341](../../server/controllers/worldWeather/controllerWorldWeather.js#L3341).
- **Legacy `/geo/:lat/:lon`, non-`KR` result.** `location2address` sets `version = '010000'`, `category = 'current'` and `gcode` ([geo.controller L656-L663](../../server/controllers/geo.controller.js#L656-L663)). When stored legacy DSF data is from another local day or older than 15 minutes, or stored AQI is older than 60 minutes ([L842-L902](../../server/controllers/worldWeather/controllerWorldWeather.js#L842-L902)), it calls `reqDataForTwoDays` directly ([L932](../../server/controllers/worldWeather/controllerWorldWeather.js#L932)).

## Limitations

- **Source only.** Every row is observed source at `bd6640f2`. No request was sent, so host availability, credential validity, response shape and current quotas are unverified. The upstream offline tests for K1–K4, K7 and H1 (`server/test/offline`) were not run; upstream's own live ASOS check is its claim, not re-verified. Rows marked "viability unverified" have an additional reason for doubt (a retired API version, test host, undocumented endpoint or forced TLS 1.0). Rows without that mark still need a live contract check before reuse.
- **Deployment.** The inspected EC2 host runs a 5bca407 checkout with configuration edits ([service EC2 internals](../architecture/ec2-internals.md)). Which provider rows run in production, and with which keys, was not correlated with provider-side usage logs. The public `/geocode` path is served by a Lambda outside this checkout.
- **Reachability.** "Legacy module" means no caller was found with `grep` over `server/` (excluding `node_modules` and `server/test`) and a reading of comment blocks. Dynamic dispatch through string names (`Manager._requestApi`) was followed by hand for `/gather/<name>` only. Standalone scripts under `server/utils/` were not catalogued row by row.
- **Timeouts and retries** are the values written in repository code. Library defaults (`request`, `axios`, `get-pixels`, AWS SDK) were not measured.
- **Quota detection** lists only the strings and codes the code checks. Provider-side quota semantics (daily or monthly, per key or per account) are not documented here and must come from current provider documentation.
