## 1. Request boundary and route selection

The checked-in Express application mounts `/v000903`, not `/weather/v000903`. The mobile client constructs the latter public prefix. The gateway implementation is outside this checkout. The 2026-09-20 deployed-source inspection recorded CloudFront → API Gateway → Lambda and coordinate dispatch to EC2 KMA address or DSF coordinates; that is historical deployment evidence, not proof of a present deployment or an implementation contained here. Native clients and older API versions remain compatibility inputs. See [gateway evidence](../architecture/aws-code-correlation.md) and [mobile routing](../architecture/mobile-api.md).

| Direct Express route | Current handler | Additional work before composition |
| --- | --- | --- |
| `/v000903/kma/addr/:region[/:city[/:town]]` | `ControllerTown24h` through v000903 KMA router | Query defaults; parameter checks; town/grid lookup ([location resolution](#location-resolution-ordered)) |
| `/v000903/kma/coord/:loc` | Same KMA middleware list with `coord2addr` prepended | External `${API_SERVER}/geocode/coord/:loc` request, then copy `kmaAddress.name1/2/3` into address parameters |
| `/v000903/dsf/coord/:loc` | Reused v000902 DSF router | Defaults; `category=current`, `days=2`, `gcode=:loc`, `aqi=airUnit`, `validVersion=true` |
| `/v000903/kma/special` | Special-weather controller | Separate warnings response; explicit `Cache-Control: max-age=300` ([§8](#8-weather-warnings)) |
| `/v000903/nation/:nation` | Reused v000803 nation router | Regional air read, then parallel HTTP requests for 15 fixed Korean cities ([§6](#6-nationwide-screens-regional-air-plus-http-fan-out)) |

Older mounted versions (v000901, v000902) use different middleware lists and response shapes; their callers are listed in [§7](#7-mounted-version-variants-and-callers).

Coordinate geocoding uses three attempts and a 3-second per-request timeout. It is not part of domestic weather-provider collection.

`checkQueryValidation` mainly supplies missing or literal `'(null)'` defaults; its name does not imply exhaustive validation of supplied enum values. Defaults are Celsius, m/s, hPa, km, mm and `airkorea`; domestic `airForecastSource` defaults to `airkorea`. The domestic version is derived from `req.baseUrl`. Parameter compatibility includes swapped `KR` address fields and rejection of selected unsupported country names. `getAllDataFromDb` redirects an out-of-Korea resolved coordinate to the unversioned gateway path `${API_SERVER}/weather/coord/...` (step 6 below). ## 2. Domestic product load and request-local state

The controller mutates a request-local assembly context (`req.short`, `req.currentList`, `req.midData`, etc.). It does not query one prebuilt whole-weather JSON document. `ControllerTown24h` invokes `ControllerTown.call(this)` and replaces selected behavior: track both files when moving functions.

`getAllDataFromDb` resolves address → grid `coord={mx,my}` and geographic `gCoord={lat,lon}`, then launches **two parallel groups**:

1. Town group, serial `async.mapSeries`: `modelShort` → `modelCurrent` → `modelShortest` → `modelShortRss`.
2. Medium group: resolve region/forecast code, then serial `modelMidForecast` → `modelMidLand` → `modelMidTemp`. Temperature-zone lookup can replace the original city code and stores `req.regId` for reuse.

Each successful read is attached under `req.model...`. Later individual getters reuse this value or read again if it is missing. Town preload failures are explicitly logged and tolerated; a medium group failure stops that group, but the outer completion still logs and calls `next()`. This is best-effort assembly, not an all-or-nothing transaction. The unused `checkDBValidation` returns immediately and is absent from the v000903 list; it is not evidence that normal weather reads trigger `/gather` recovery.

`DB_DATA_VERSION` selects storage adapters. At `config.db.version === '2.0'`, current/short/shortest/short-RSS use the `kma.town.*` controllers; otherwise the reader takes the legacy path. Medium reads have a separate v2 switch in `_getMidDataFromDB`. These adapters return the older assembly representation `{pubDate, ret}` even when the underlying schema uses individual `fcsDate`/`pubDate` Date records. The writer has stricter `1.0`/`2.0` cases; do not mistake reader fallback for support of arbitrary versions.

Upstream additions to the adapter contract (`95fe711e`, `49afbbea`):

### Station selection and merge

Source reading unless marked otherwise. Station distances use MongoDB `$near` with `$maxDistance` on the planar `2d` indexes of [`MsrStnInfo`](../../server/models/modelMsrStnInfo.js#L43-L46) and [`KmaStnInfo`](../../server/models/modelKmaStnInfo.js#L12-L15). They are therefore measured in coordinate degrees, not kilometres (library semantics).

**AirKorea observations (`getKeco`, item 24).** [`getKeco`](../../server/controllers/controllerTown.js#L2562-L2570) passes `new Date()` to [`getArpLtnInfo`](../../server/controllers/kecoController.js#L389-L435).

1. Candidates: up to 6 `MsrStnInfo` stations nearest to `gCoord`, within 1°.
2. History: for each station, in distance order, the `Arpltn` records whose `date` is later than now − 24 h, newest first ([`_getArpLtnList`](../../server/controllers/kecoController.js#L129-L166)). A station with no such record is dropped, so the positions below count only stations with data.
3. `current.arpltn` ([`_mergeArpltnList`](../../server/controllers/kecoController.js#L218-L257)): walk each station's newest record in order.
   - The first record that passes [`_checkDateTime`](../../server/controllers/kecoController.js#L194-L209) becomes the base. It copies every field that is neither `undefined` nor `-1`.
   - Each later passing record fills any of `co`, `khai`, `no2`, `o3`, `pm10`, `pm25`, `so2` whose `<p>Value` is still undefined, unless the donor value is `-1`. It copies `<p>Value` and `<p>Grade` and sets `<p>StationName` to the donor station.
   - The walk stops once all seven values exist. If no record passes, `current.arpltn` is `undefined`.
4. **Source anomaly: cumulative freshness window.** `_checkDateTime` is commented "use within 8 hours", but it subtracts 8 h from the shared `Date` on every call. The k-th station visited is therefore accepted only when its `dataTime` is later than now − 8·k h. With the 24 h query window, the third and later stations are accepted at any age up to 24 h. `dataTime` text is parsed in the process time zone. For `24:00`, the date part is parsed as a date-only ISO string (UTC midnight) and then moved with local `setDate(+1)`/`setHours(0)` ([L196-L199](../../server/controllers/kecoController.js#L196-L199)), so it becomes 00:00 of the next day only in process zones at or east of UTC; west of UTC it lands 24 h early (source reading plus a one-line Node check, not a checked-in probe). The [time-zone probe record](../../reports/rewrite-verification/probes/server-kmatimelib-timezones.json) shows that parse shape, `2026-03-08 15:00`, giving 06:00Z under `Asia/Seoul` and 15:00Z under `UTC`.
5. **Synthetic execution** of the three extracted helpers ([probe](../../reports/rewrite-verification/probes/server-airkorea-station-merge.js), [record](../../reports/rewrite-verification/probes/server-airkorea-station-merge.json); `TZ=Asia/Seoul`, now 12:00 KST; 5/5 checks match):
   - The 9-hour-old nearest station was rejected. A 14-hour-old station became the base, and a 22-hour-old station supplied `pm10`.
   - In a variant where the 22-hour-old station also lacked `pm10`, `pm10StationName` was still set to it, with no `pm10Value`. Only a `-1` donor value is skipped, not an absent one.
   - Not executed: the `getKeco` assignment, the `$near` query, the 24 h window and the comparator in step 6.
6. `arpltnStnList` ignores step 4. It holds the first three station series from step 2, re-sorted with a comparator that inspects only its first argument. It is meant to move back a station whose newest record lacks both `khaiValue` and `pm10Value` and to move `도시대기` (urban) stations forward, but the final order depends on the engine's sort. `arpltnList` is only the first series after that sort (`list: arpltnList[0]`, [kecoController.js#L425](../../server/controllers/kecoController.js#L425); [getKeco](../../server/controllers/controllerTown.js#L2568-L2569)). `makeAirInfo` reads that one series and `makeAirInfoList` reads the three; each uses a series' newest record, up to 24 h old, as `last` ([§7](#response-consequences)). `airInfo.last` and `airInfoList[0].last` can therefore come from a different station and time than `current.arpltn`.

### Error sink for propagated failures

Source plus Express 4 library-semantics analysis; awaiting characterization (a proposed V07 case). [server/app.js](../../server/app.js#L145-L175) ends with a 404 middleware that always calls `next(err)` with `status = 404`. It is followed by a development handler (registered only when `app.get('env') === 'development'`) and a production handler, both declared as `function(err, req, res)` (three parameters). Express 4 treats middleware as error-handling only when it declares four parameters. It skips three-parameter functions while an error propagates. Ordinary requests never reach them either, because the 404 middleware converts every fall-through into an error. No four-parameter error middleware exists under `server/`. The deployed Express was 4.13.4 ([EC2 internals](../architecture/ec2-internals.md)).

- Every `next(err)`, every synchronous throw inside a middleware and the 404 fall-through therefore end in Express's built-in final handler. It returns status `err.status` (or 500) with `Content-Type: text/html`. The body is the HTTP status text (`Not Found`, `Internal Server Error`) when `NODE_ENV=production`, the 2026-09-20 host value, and an escaped stack trace otherwise.
- These handlers therefore never render `views/error.jade` (its only other uses are direct `res.render('error')` calls in the v000803 POST gate, [v000803 index](../../server/routes/v000803/index.js#L46)), and the production handler's `log.error(err)` never runs. Express writes `err.stack` to stderr with `console.error`, not to the application logger.
- A throw inside an asynchronous provider or database callback bypasses this sink entirely (see [§5 step 3](#5-world-weather-request-time-cache-fill-then-merge)).
- Routes that send their own status and body are unaffected, for example the 400 texts in [location resolution](#location-resolution-ordered) and the `/kma/special` 501 text.

## 5. World weather: request-time cache fill, then merge

[World sequence](diagrams/server-world-cache-sequence.html) is a bounded view of the following logic. Its overseas weather (DSF-named, Visual Crossing since #2585) and AQI branches run concurrently; the drawn vertical order does not create a cross-branch dependency.

1. `queryTwoDaysWeatherNewForm` sets request clock `cDate`, parses geocode and starts `DsfController.getDsfData` and `_getWaqiFromAll` with `async.parallel`. A propagated branch error goes to `next(err)` and the [error sink](#error-sink-for-propagated-failures). A `:loc` that does not split into two comma-separated parts returns 400 text `It is not valid request` when no `city` query is present. With a `city` query it instead throws synchronously on `req.geocode.lon` in `getDsfData`, which also ends in the error sink.
2. `DsfController` reads the records of the last 3 days (`dateObj` at or after `cDate` − 3 d) for exact Mongo coordinate `[lon,lat]`, sorted by `dateObj` ([`_findDataFromDB`](../../server/controllers/worldWeather/dsf.controller.js#L337-L399)). It compares local calendar dates: a record's own day uses its stored offset; today and yesterday use the offset in effect now, computed once per read: the newest record's stored offset, moved across a later daylight-saving change by `Intl` with the stored IANA zone (`address.country`) only when `Intl` reproduces that stored offset (stale or unknown runtime zone data keeps the stored offset). Yesterday and today must be local-midnight records; current is at most 15 minutes old and on today's local date (the newest wins); the newest other record up to 3 h old is kept as `stale`. A stored yesterday counts only when it was fetched after that local day ended (`pubDate` at or after the start of local today). It then holds mostly observations, although its latest hours can still be forecast values when stations report late. Hours missing from an accepted record (for example on a daylight-saving change) are left to the merge step and no longer force a refetch; malformed records are skipped.
3. If all three records exist, no provider is called. Otherwise [`_checkProvider`](../../server/controllers/worldWeather/dsf.controller.js#L857-L874) skips the call while the `~provider` marker in `vc.fetch.locks` is active (10 min after a 401/403 or a 429 whose body names a daily/monthly/usage limit; other 429s back off only that location) or while the optional `VC_DAILY_RECORD_LIMIT` budget would be exceeded by the call's cost (25 or 1 records, against the UTC day's `vc.usage`). [`_requestDatas`](../../server/controllers/worldWeather/dsf.controller.js#L1030-L1113) then takes a per-location lock in `vc.fetch.locks` (`_id` `"<lon>,<lat>"`, `expireAt` 10 s ahead; an expired lock is taken over and its `failed` flag reset; a lock-store error lets the worker fetch anyway), re-reads the records with the later of `cDate` and now, and makes **one** Visual Crossing Timeline call: `combined` (yesterday through +7 days, 25 cost records) when yesterday is missing, else `forecast` (today through +7 days, 1 record). The request is answered within 2.5 s (`responseMs`); the holder's call may run to 8 s (`fetchTimeoutMs`, under the lock TTL), and records that arrive later are still stored for the gateway's next attempt ([budgets](../../server/controllers/worldWeather/dsf.controller.js#L43-L57)). [`_fetchVc`](../../server/controllers/worldWeather/dsf.controller.js#L998-L1028) converts the body with `vcConverter` into Dark Sky-format yesterday/today/current documents, formats them with the unchanged `_parseData`, then saves yesterday, today and current in that order (current last) and releases its own lock (matched by `expireAt`). Each call that reaches the network adds to the UTC day's `vc.usage` counters. After a failed call the holder sets `failed: true` and moves `expireAt` 2 s ahead. This limits a failing location to one attempt per 2 s. The gateway Lambda retries an error immediately, a fast 5xx included ([Lambda excerpts](../architecture/deployed-lambda-excerpts.md)), so such a retry within the 2 s gets the fallback or the error without a provider call. Every save is an upsert on `geo` + that record's `dateObj` ([`_saveData`](../../server/controllers/worldWeather/dsf.controller.js#L526-L540)); save failures log and continue. The zone comes from Visual Crossing `timezone` (`address.country` holds it) and the offset in effect at request time from the latest hour row, not from the range-start `tzoffset`; no Google time-zone lookup runs on this path. A worker that does not get the lock re-reads every 250 ms for up to 2.5 s, continues once current and today exist, and stops at once when the lock is flagged `failed` ([`_waitForRecords`](../../server/controllers/worldWeather/dsf.controller.js#L968-L989)). `getDsfData` uses the selected current record's time (cached within 15 minutes, a stale record, or the fetch time) as `cWeatherDate` for later alignment. Failures:
   - **No fresh data but a stored current record** (provider timeout or error, the 2.5 s response budget exceeded, invalid body or conversion error, missing key, the provider marked down or the budget reached, a waiter that sees `failed` or finds nothing within 2.5 s of its request time) → [`_fallback`](../../server/controllers/worldWeather/dsf.controller.js#L952-L961) serves the fresh current record, else the `stale` one up to 3 h old, with any stored yesterday and today, and logs the fallback at `error`.
   - **Otherwise** (no current or stale record to serve, or an output-formatting exception) → an `Error` object → `async.parallel` → `next(err)` → [error sink](#error-sink-for-propagated-failures) (HTML 500). The former string-valued errors, the `err.message` strict-mode `TypeError` and the Google time-zone `ReferenceError`/numeric-fallback throws on this path were removed with `_reqData`/`_getTimeOffset` in #2585.
4. AQI prunes old records, reads cache, tests 60-minute freshness, tries a stored station/feed ID on stale data, then geographic WAQI fallback. Absence is tolerated in several inner paths, but a propagated AQI error still fails the outer parallel join. This is not a blanket best-effort guarantee for every AQI error.
5. Convert the stored current/hourly/daily and sunrise/sunset timestamps into the response's local-time representation using `timezone.min/ms`; a stored offset of 0 (UTC+0) is used as an offset, and a `null` sunrise or sunset (polar day) is left out. Then combine daily records by date, current observation, and hourly records; the merges skip the −100 missing-value sentinel for temperatures, wind direction, pressure and daily humidity (hourly and current humidity turn it into 0). `hourly` is a **three-hour display series** (00/03/06/09/12/15/18/21/24) derived using the selected hour and two preceding hourly inputs. `shortest` takes up to three subsequent hourly items. Yesterday at matching hour joins `thisTime`; if absent, a date-only placeholder is appended.
6. Merge AQI readings matching `thisTime` through `_compareDate(..., 6)`: same UTC day-of-month and `(weather−air)` hours ≤ 6, with no lower bound. This is not a symmetric ±6-hour window; see the lifecycle anomaly table. Convert pollutant indices back into values, grades and localized strings for requested air standard. AirKorea combined-index calculation can add 50/75 points when multiple pollutants exceed the threshold.
7. Sort time arrays, normalize icons, convert units, form `arpltn` and singular `airInfo`, compute summaries with shared domestic summary helpers, then `sendResult`.

Sources: [world controller](../../server/controllers/worldWeather/controllerWorldWeather.js) (`queryTwoDaysWeatherNewForm`, `_getWaqiFromAll`, `mergeDsfHourlyData`, `mergeAqi`), [DSF-named cache](../../server/controllers/worldWeather/dsf.controller.js), [Visual Crossing requester](../../server/lib/VC/vcRequester.js), [converter](../../server/lib/VC/vcConverter.js), [AQI collector](../../server/controllers/worldWeather/controllerAqi.js), [world units and summary](../../server/controllers/worldWeather/controller.ww.units.js).

The world envelope contains `source:'VC'`, `daily`, `hourly`, `thisTime` (expected yesterday then current after sort), `shortest`, `pubDate.VC`, `location:{lat,lon}`, `timezone`, `units`, and conditional `airInfo`.

- **`source` is always `'VC'`** (it was `'DSF'` before #2585). [`dataSort`](../../server/controllers/worldWeather/controllerWorldWeather.js#L2134-L2179) (DSF item 9) dereferences `req.result.thisTime` and then sets `req.result.source = 'VC'` unconditionally. The merge stages write `pubDate.VC`. If no merge stage created `req.result`, the synchronous `TypeError` there ends in the [error sink](#error-sink-for-propagated-failures) (HTML 500).
- **`sendResult` fallbacks are unreachable on the v000901/v000902 DSF chains.** [`sendResult`](../../server/controllers/worldWeather/controllerWorldWeather.js#L89-L111) always receives `req.result`, so its `{result:'Unknown result'}` branch cannot run. No stage on these chains leaves a `req.error` that reaches it; the malformed-coordinate cases in step 1 end earlier. It still logs when `thisTime.length !== 2`.
- **`airInfo`.** [`makeAirInfo`](../../server/controllers/worldWeather/controllerWorldWeather.js#L2109-L2132) (DSF item 12) builds `{source:'aqicn', last: <last thisTime entry>.arpltn}`. It adds `<pollutant>ActionGuide` for each of `pm25`, `pm10`, `o3`, `no2`, `co`, `so2`, `aqi` that has a `<pollutant>Grade`. It is present only when the **last** `thisTime` entry has `arpltn`; errors are logged and skipped.
- **Consumers depend on `source`.** The app takes its world parser whenever `source !== 'KMA'` (decision D02). The iOS widgets read `current` when `source == "KMA"`, else `thisTime` ([widget](../../tw.ios/widget/TodayViewController.m#L2486-L2530)). Current apps show the Visual Crossing attribution only for `source == 'VC'`. Released app versions do not recognise `VC` and keep a city's stored `source`: cities stored as `DSF` (every non-KR current position in released TodayWeather iOS builds, and overseas cities stored before the switch) show "Powered by Dark Sky" over Visual Crossing data until the app is updated, and other overseas cities show no attribution; widgets and push show none. The alert worker reads `current` for `KMA`, `thisTime[1]` for `VC` or legacy `DSF`, and throws `Unknown source` for any other value ([alert worker](../../server/controllers/alert.push.controller.js#L123-L149)).
- **Gateway changes.** The 2026-09-20 deployed Lambda excerpt `importGeoInfo` adds `name`, `country`, `address`, and replaces `location` with `{lat, long}` when its geoinfo has them. It does not remove `source` (deployment observation; [Lambda excerpts](../architecture/deployed-lambda-excerpts.md)). See the public-envelope [example](examples/client-world-response.json).

These paths are historical behavior rather than a recommended error contract. Provider and output property names are mapped in [client contracts](client-data-contracts.md).

## 6. Nationwide screens: regional air plus HTTP fan-out

`/v000903/nation/:nation` reuses [route.nation.js](../../server/routes/v000803/route.nation.js). Its chain is `checkQueryValidation` → `getSidoArpltn` → `getWeather` → sender. [Nation fan-out sequence](diagrams/server-nation-fanout.html).

1. Supply the same query-unit defaults and derive API version from `baseUrl`.
2. Load regional air through `KecoController.getSidoArpltn`, recalculate each region using the requested air standard, and attach `req.air`. A read or conversion error reaches `next(err)`.
3. `async.map` requests weather for **15 fixed Korean city/address entries** over HTTP to `config.apiServer.url/<version>/kma/addr/...` (older versions use `/town`; absent version defaults to v000901). Query fields and `Accept-Language` are forwarded; no `User-Agent` header is set. Each child has a 9-second timeout. This is a configurable API-server fan-out, not 15 in-process calls or one Mongo aggregate. [Source](../../server/routes/v000803/route.nation.js#L32-L73)
   - **Deployed routing (observation, 2026-09-20).** `API_SERVER` was `http://todayweather.wizardfactory.net`, the public CloudFront host ([EC2 internals](../architecture/ec2-internals.md), [AWS correlation](../architecture/aws-code-correlation.md)). Each origin-reaching nation request therefore sends 15 children back through the public edge. `/v000903/kma/...` follows CloudFront's default behavior to the same service origin, so children can be edge-cached and add edge hops to the parent's latency and failure coupling.
   - **30-day correlation (aggregate, not per-request proof).** In the [2026-08-23..09-22 traffic window](../../reports/aws/api-traffic-2026-09-22.md), `/v000903/nation/KR` had 86 cache misses + 2 refresh hits = 88 origin-reaching requests (its 12 `502` cache errors are not counted), and 88 × 15 = 1,320. That equals the number of `/v000903/kma/addr/{location}` requests; all 1,320 had unidentified ("other") user agents and HTTP 200, and 30 of them were CloudFront refresh hits. The first observations were 2026-08-24T06:40:07Z (children) and 06:40:08Z (nation); both paths were last observed at 2026-09-22T13:54:02Z ([route CSV](../../reports/aws/api-traffic-2026-09-22-routes.csv)). When inventorying external callers of `/v000903/kma/addr` ([§7](#7-mounted-version-variants-and-callers)), treat these as internal fan-out.
4. Remove only top-level `airInfo` and `airInfoList` from each child weather object, then attach the weather array. Other child fields, including nested enrichments, are retained. Any child network error or HTTP status ≥400 causes the aggregate callback to call `next(err)` → [error sink](#error-sink-for-propagated-failures) (HTML). With `async` 2.x, this happens on the first error while other children are still in flight. The code does not return a documented partial-city success contract.
5. Return `{nation:'KR', weather, air}` with whichever of the two attached fields exist. The no-result `501` branch is effectively unreachable: `getSidoArpltn` and `getWeather` either attach an array (possibly empty) or call `next(err)` ([sender](../../server/routes/v000803/route.nation.js#L150-L167)). The path `:nation` value does not choose another country: city list and returned nation are hard-coded to Korea.

A rewrite must decide whether to preserve failure coupling, request multiplication, per-child unit/locale shaping and city order. Nationwide weather and regional air must not be conflated with `airInfoList` from a single city's nearby stations. These are separate screens/contracts in [client contracts](client-data-contracts.md).

## 8. Weather warnings

Both warning consumers read the latest scraped `KmaSpecial` documents ([model](../../server/models/modelKmaSpecialWeatherSituation.js)). The scraper stores `announcement` via `kmaTimeLib.convertKoreaStr2Date`, which calls `new Date(y, m, d, h, min)` on the Korean announcement text in the **scraper process's local time zone** ([scraper](../../server/lib/kmaScraper.js#L1519-L1532), [time helper](../../server/lib/kmaTimeLib.js#L352-L361)). Synthetic execution in the [time-zone probe record](../../reports/rewrite-verification/probes/server-kmatimelib-timezones.json) confirms this: `2026년 03월 08일 15시 00분` becomes 06:00Z under `Asia/Seoul`, 15:00Z under `UTC` and 19:00Z under `America/New_York`. Otherwise this section is source observation; no database was read. Client consumption: [national overview and warnings](client-data-contracts.md#national-overview-and-warnings) and [screen S12](screen-specifications.md#s12--weather-warningsbulletins).

### `GET /v000903/kma/special`

Handler: [route](../../server/routes/v000903/route.kma.v000903.js#L72-L83) → [`getCurrent`](../../server/controllers/kma.specialweather.controller.js#L97-L133).

1. `async.map` over types `[4, 1, 2, 3]` (flash, special warning, preliminary warning, information); the result order is preserved.
2. Each type reads its latest document: `find({type}, {_id:0, __v:0}).sort({announcement:-1}).limit(1)`. A type with no document fails with `data is empty`.
3. `name` is set with `res.__`: `LOC_TYPE_WEATHER_FLASH`, `LOC_TYPE_SPECIAL_WEATHER`, `LOC_TYPE_PRELIMINARY_SPECIAL`, `LOC_TYPE_WEATHER_INFORMATION`. The locale comes from `i18n.init` ([configuration](../../server/app.js#L62-L73), [mount](../../server/app.js#L96); cookie `twcookie`, then `Accept-Language`; library semantics).
4. Flash only: the document is dropped when the stored, **unshifted** `announcement` + 10 h is earlier than the service clock ([parser](../../server/controllers/kma.specialweather.controller.js#L49-L95)).
5. `announcement` is shifted by −9 h and serializes as an ISO UTC string. The shift is correct only if the scraper ran in UTC, so that Korean wall-clock time was stored as UTC. Under that assumption a flash stays visible until about 19 h after its real KST announcement. If the scraper ran in KST, the output is 9 h early and the flash window is 10 h. The scraper host's time zone is not recorded in [EC2 internals](../architecture/ec2-internals.md).
6. Nested `situationList[]._id` and `info[]._id` are deleted.
7. `comment` receives line breaks from a character scan ([`_insertLineChange`](../../server/controllers/kma.specialweather.controller.js#L21-L47)). `\n\n` is inserted before every `<`, `*`, ASCII `o`, `-` and `※` not at index 0; `\n` before every `[`; and `\n` before each occurrence of `weatherStr + levelStr` for situations whose `weatherStr !== '없음'`. Markers match anywhere in the text, not only at line starts.
8. Success sets `Cache-Control: max-age=300` and returns a JSON array of 3–4 objects. **Any** error returns HTTP 501 with `err.message` sent as a string, which Express labels `text/html`: a Mongo error, a missing type, or an exception in steps 3–7 such as a missing `comment`. There is no partial list.

Wire object: `{type, name, announcement, imageUrl?, situationList: [{weather, weatherStr, level, levelStr, info: [{timeStr?, location}]}], comment}`. Codes come from the model's `parseSituationType` and `strArray2SituationList`:

| Field | Values |
| --- | --- |
| `type` | 1 special warning · 2 preliminary · 3 information · 4 flash |
| `weather` | 1 강풍 · 2 풍랑 · 3 호우 · 4 대설 · 5 건조 · 6 해일 · 7 폭풍해일 · 8 지진해일 · 9 한파 · 10 태풍 · 11 황사 · 12 폭염; 0 unknown hazard or `없음`; −1 unparsed |
| `level` | 1 주의보 · 2 경보 · 3 예비특보; 0 with `weatherStr:'없음'`; −1 unparsed (`weatherStr` holds the raw text) |

Source anomaly: `parseSituationType` tests `해일` before `폭풍해일`/`지진해일`, so codes 7 and 8 are unreachable and both become 6.

### Domestic `current.specialInfo`

[`getSpecialInfo`](../../server/controllers/controllerTown24h.js#L1900-L1924) (v000903 KMA item 32) → [controller](../../server/controllers/kma.specialweather.controller.js#L333-L408):

- It reads only the latest **type 1** document; preliminary warnings, information and flashes never affect weather responses.
- Inputs: `town = {first: region, second: city, third: town}`, where region- and city-level requests carry `''`, and `stnName = req.current.nearStnName`. Any error (no type-1 document, Mongo error, missing `situationList`, missing `req.current`) is logged and the stage calls `next()` without the field. `current.specialInfo` is set only for a nonempty list.
- For each `situationList[].info[].location`, [`_findLocationByTown`](../../server/controllers/kma.specialweather.controller.js#L205-L331) returns a name or nothing. Each match yields `{weather, weatherStr, level, levelStr, locationName}`, and one town can collect several.
- Match rules, in order:
  1. If `first` contains `특별시`, `광역시` or `특별자치시` and is not 인천, the bare name (for example `서울`) must occur anywhere in the location string; otherwise there is no match.
  2. If `second` contains `울릉` and the location contains `울릉도` → `울릉도.독도`.
  3. If `third` contains `흑산` and the location contains `흑산도` → `흑산도.홍도`; `추자` + `추자도` → `추자도`; `삼산` + `거문도` → `거문도.초도`; `백령`/`대청`/`연평` + `서해5도` → `서해5도`.
  4. Otherwise the target is `제주도` for 제주 regions, bare `인천` for 인천광역시, else the full province name. No occurrence → no match. A province immediately followed by `,` (whole province listed) → the province name.
  5. Remove `(흑산면제외)`. Choose a sub-zone from the nearest station ([`_getAreaName`](../../server/controllers/kma.specialweather.controller.js#L163-L194), for example `대관령` → `강원중부산지`, `성산` → `제주도동부`), else from `second` (`수원시장안구` → `수원`, `연천군` → `연천`). If neither exists (region-level request), match the province text up to `(`.
  6. Inside the province's parentheses: when the text contains `제외`, the town matches (as the province name) only if its target is **not** listed. Otherwise it matches when listed, returning the entry up to the next `,`. A result containing `신안` becomes `신안(흑산면제외)`.

- Sorting: `b.weather − a.weather`, that is, descending hazard code (12 폭염 before 3 호우 before 1 강풍). Level is ignored, so a 주의보 of a higher-coded hazard precedes a 경보 of a lower-coded one.

## Rewrite boundaries to preserve deliberately

- Separate raw observation, forecast, corrected display value and localized text. Preserve source/publication/time provenance even when they currently share one object.
- Treat units, AQI standard, locale, geography and API version as response-shaping inputs when defining caches.
- Keep the 24:00/yesterday/three-hour accumulation rules covered by frozen-clock examples before simplifying them.
- Define product completeness and stale-data policy explicitly; a successful legacy status code is not sufficient equivalence evidence. The upstream publication limits (short and short RSS 0–24 h, medium land/temperature 0–36 h at 06:00/18:00 KST) and `midData.dailyStatus` are the current baseline; treat them as inputs to that policy, not as a finished contract.
- `historyStatus`, `dailyStatus`, `observationType` and `historyObservation` are additive; `client/www/js` and the iOS widgets do not read them. Missing observed or forecast values stay unknown rather than zero, except for the `-0` case in [§4](#4-domestic-response-envelope-and-failures).
- Preserve older mounted contracts behind adapters until actual mobile/widget callers are inventoried. [§7](#7-mounted-version-variants-and-callers) lists the known callers and the singular-air, icon-name and warning differences.
- Replace historical providers only after documenting equivalent time, rain, snow, index and history semantics. Provider name substitution alone is insufficient.

For proposed acceptance work, see [verification matrix](verification-matrix.md) and [rewrite playbook](rewrite-playbook.md).
