# Native consumers and Cordova plugins

Source baseline: `bd6640f2` (re-baselined 2026-09-25). `client/`, `tw.ios/`, `ta.ios/` and `applewatch/` are identical to `ff7acf3996ccb66c912d2ed4710cf300197d6966`, where they were inspected on 2026-09-24; server statements were rechecked against `bd6640f2`. This reference covers the product perimeter outside the shared Angular source: the iOS Today widgets, the Android widget plugins, the Apple Watch project, the Cordova plugin set of each build variant, the native preference keys shared with the app, and the response fields the iOS widgets read. It also records the static web PWA in `web/`, a **non-native** consumer added upstream, in [§5](#5-non-native-consumer-web-pwa-web). Statements are **observed source** unless labeled **historical source** (read from git history with `git show <rev>:<path>`), **deployment observation** (dated, from the linked architecture documents), **inference** or **unverified**. Nothing here was built, installed or run on a device or simulator. No plugin repository outside this checkout was fetched, and no server, provider or AWS resource was called.

How to use this during a rewrite:

- Treat every row of the [consumer inventory](#1-consumer-inventory) as a compatibility obligation until release evidence retires it. Record retirement in the [decision register](decisions-and-open-questions.md).
- Before changing the unversioned `/weather/coord` path, the v000901 KMA/DSF shapes, icon names or the `cityList`/`units` preferences, check the [widget field dependencies](#4-ios-widget-field-dependencies) and [shared preference keys](#3-shared-preferences).
- Before dropping or replacing a plugin, check its call sites and absent-plugin behavior in the [plugin matrix](#22-plugin-matrix). Absent-plugin behavior is what development builds and the screenshot harness exercise; it is not production parity.
- Obtain the [external plugin repositories](#24-external-repositories-to-acquire) before scoping Android widgets. Without them, the Android widget contract is unknown.

Related references: backend chains per caller are in [server response assembly §7](server-response-assembly.md#7-mounted-version-variants-and-callers). Full storage schemas and migrations are in [client state: persistence](client-state-and-behavior.md#persistence-and-native-preferences). Widget deep links are in [app entry links](client-data-contracts.md#app-entry-links), and plugin-dependent dialogs are in [screen overlays](screen-overlays.md).

### 1.1 Unreachable and historical paths inside the iOS widget source

Do not count these as live contracts:

- **World constant.** `WORLD_API_URL` (`ww/010000/current/2?gcode=`, [L33](../../tw.ios/widget/TodayViewController.m#L33)) is used only by `makeGlobalRequestURL` ([L1464-L1519](../../tw.ios/widget/TodayViewController.m#L1464-L1519)). That function is reached only through `processGlobalAddress` ← `parseGlobalGeocode` ← `getGeocodeFromGoogle` ← `parseGlobalAddress` ← `getAddressFromGoogle`, and `getAddressFromGoogle` has no call site ([TW L937](../../tw.ios/widget/TodayViewController.m#L937), [TA L982](../../ta.ios/widget/TodayViewController.m#L982)). The Google geocoding URLs are therefore unreachable too. The widget moved to `weather/coord` in commit `04df1714` (2017-12-22, "use weather/coord api in ios widget #1845", historical source).
- **Alternative renderers.** `processWeatherResultsAboutGlobal` runs only for the unreachable global request type. `processWeatherResultsWithShowMore` is dispatched only inside a commented-out block ([L1095-L1102](../../tw.ios/widget/TodayViewController.m#L1095-L1102)). Both KMA-address and coordinate responses go to `processWeatherResultsByCoord` ([L1109-L1115](../../tw.ios/widget/TodayViewController.m#L1109-L1115); TA [L1134-L1139](../../ta.ios/widget/TodayViewController.m#L1134-L1139)).
- **Daum.** The `getAddressFromDaum` call is commented out ([TW L2180](../../tw.ios/widget/TodayViewController.m#L2180), [TA L2202](../../ta.ios/widget/TodayViewController.m#L2202)). `DAUM_SERVICE_KEY`, a hard-coded literal at [WidgetConfig.h#L16](../../tw.ios/widget/WidgetConfig.h#L16), has no reference (`grep -rn DAUM_SERVICE_KEY tw.ios/widget ta.ios/widget` matches only the two `#define` lines). Commit `cf45412e` (2018-02-11) records deleting the Daum-key functions.
- **Preference observer.** `userDefaultsDidChange` reads `addr1`–`addr3` and requests `v000901/kma/addr` ([TW L684-L704](../../tw.ios/widget/TodayViewController.m#L684-L704)). Nothing registers it as an observer (`NSUserDefaultsDidChangeNotification` has 0 matches in either widget).
- **TodayAir `cityList` write-back.** `updateCurLocation` rewrites `cityList` in the shared suite ([TA L629-L681](../../ta.ios/widget/TodayViewController.m#L629-L681)). Its only caller is `parseGlobalGeocode`, which is unreachable, so current source never writes app-owned preferences from a widget.
- **Compiled-out test paths.** TodayAir defines `EMUL_TEST 0` ([L24](../../ta.ios/widget/TodayViewController.m#L24)), which disables test code at L434, L2357 and the fixed-coordinate URL at [L2511-L2513](../../ta.ios/widget/TodayViewController.m#L2511-L2513). A commented `TEST_SERVER` constant exists in both widgets.

### 3.3 Android old-suite migration

On Android, `TwStorage.init` opens the old suite when localStorage is not empty. For each of `units`, `cityList`, `daumServiceKeys` and `purchaseInfo` that localStorage lacks, it copies the old-suite value into localStorage, stores it in the new suite and removes it from the old suite ([service.storage.js#L57-L101](../../client/www/js/service.storage.js#L57-L101), [L228-L240](../../client/www/js/service.storage.js#L228-L240)). A key already present in localStorage is left in the old suite. Consequence (inference): a native reader still bound to the old suite, such as the historical widget, sees a stale `cityList` or none at all after this migration. The full restore order is in [client state](client-state-and-behavior.md#persistence-and-native-preferences).

### 4.3 Compatibility checklist

For the unversioned coordinate path and `v000901/kma/addr`, as long as installed widgets remain in use:

1. Keep both paths, the `lat,lon` coordinate order and the tolerance for `(null)` unit values.
2. Keep CamelCase `skyIcon` values, or ship widgets that bundle the new names.
3. Keep `source`, the gateway's top-level `name` and `country`, the `[yesterday, current]` world `thisTime` pair, a `daily[]` that starts with yesterday, and `YYYYMMDD` `date` strings in current and daily rows. Keep daily dates contiguous from yesterday for the show-more labels. At `bd6640f2` KMA `midData.dailyData` omits incomplete dates by design (§4.2).
4. Keep the `khai*` aliases on world `arpltn`, and the `pm10*`, `pm25*` and `o3*` members on both sources.
5. Decide whether grade strings stay Korean for widget requests. The TodayWeather coloring and the TodayAir headline depend on them.
6. Decide the error envelope. Installed widgets cache any JSON object and stop rendering when it has no weather rows.

The transport is the same for all five:

- **Method and credentials.** Only `GET` is sent; any other method is rejected locally ([L98-L99](../../web/src/direct-api.ts#L98-L99)). Requests use `credentials: "omit"` and `redirect: "error"`, so any 3xx fails.
- **Headers.** `Accept: application/json` and a fixed `Accept-Language: ko` ([L114-L121](../../web/src/direct-api.ts#L114-L121)). Server prose and geocode names are therefore requested in Korean whatever the browser locale: through the gateway's `_getLanguage` for weather and geocode (2026-09-20 source), and through Express `i18n` for nation and warnings ([language negotiation](client-data-contracts.md#language-negotiation)).
- **HTTP cache.** Both geocode requests set `cache: "no-store"`; the other three use the browser default.
- **Retry.** A request is repeated once, after 1 second, when `fetch` rejects without an abort (this includes a 502 without CORS headers) or the status is 502. Other statuses, body errors and aborts are not retried ([L108-L137](../../web/src/direct-api.ts#L108-L137)).
- **Origin.** The origin is `VITE_WEATHER_API_ORIGIN`, which must be HTTPS and defaults to the public API host ([transport-config.ts#L18-L30](../../web/src/transport-config.ts#L18-L30)).
- **Limits.** There is one 15-second abort covering both attempts ([api.ts#L15-L21](../../web/src/api.ts#L15-L21)). The response `Content-Type` must contain `json`, and bodies are capped at 2,000,000 bytes. A non-2xx JSON body is shown only through a string `error.message` ([L15-L57](../../web/src/direct-api.ts#L15-L57)).
- **Coordinates.** They are rounded to three decimals and sent in `lat,lon` order ([weather-core#L143-L168](../../packages/weather-core/src/index.ts#L143-L168)).
- **Local operations.** Catalog search, places and capabilities resolve in the browser. Notifications send no request ([L143-L174](../../web/src/direct-api.ts#L143-L174)). Demo mode reads `web/src/demo/*.json` instead of the network.

**Not called:** push, push-list, check-purchase, the photo feed, `/weather/.../addr`, `/v000903/kma/addr` and `/gather/*`.

### 5.3 Rewrite consequences

- Keeping `/weather/v000903/coord`, `/geocode/v000903/{coord,addr}`, `/v000903/nation/KR` and `/v000903/kma/special`, with wildcard CORS on those paths, keeps the PWA working. It shares no push, purchase, widget or preference contract with the native clients.
- Keep the response `units` truthful and the requested `airUnit` echoed. The PWA converts weather bodies from the response `units` and rejects a mismatched air standard; nationwide bodies must stay in the requested canonical units because their `units` are not read.
- Error bodies need CORS headers too, or the browser sees only a generic network failure. The 2026-09-24 review found that historical Lambda error responses omit them ([existing-infrastructure review](../webapp/existing-infrastructure-review.md#migration-findings-and-continuing-hosting-requirements)).
- A 502 or network failure makes the PWA repeat the same `GET` once about a second later, so these reads must stay idempotent and a quick duplicate is normal client behavior.
- The PWA shows KMA forecast amounts from `r06`/`s06` with a fixed 3-hour (short) or daily (no duration) label. If a rewrite stores forecast amounts with their accumulation period (D45), the web should read that period instead of assuming it.
- Browser notifications are unavailable by decision, not a parity path ([notification boundaries](../webapp/technical-design.md#notification-and-parity-boundaries)).
