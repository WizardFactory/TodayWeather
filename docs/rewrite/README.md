# Server and client rewrite reference

This package records the current TodayWeather/TodayAir behavior before a rewrite. Source baseline: `bd6640f2` (re-baselined 2026-09-25; client and native source identical to `ff7acf3996ccb66c912d2ed4710cf300197d6966`, on which the package was analyzed 2026-09-23 and extended by the 2026-09-24 gap review and its 2026-09-25 final round; see [re-baselined to `bd6640f2`](#re-baselined-to-bd6640f2)). It contains **16 screen definitions (S01–S16) plus 19 overlay, dialog and native hand-off definitions (O01–O19), per-element binding tables, 50 simulator screenshots (two of them on iPad), request/response, storage and notification examples, four server diagrams, server push-text and purchase-validation rules, API endpoint, data model, external provider, configuration, security/privacy, localization and native-perimeter inventories, a domain glossary with unit-conversion rules, eight checked-in probe records, and migration/verification guidance**.

Production application code was not changed. Screenshots use synthetic data in an isolated native WKWebView; the 27 captures from 2026-09-24 add overlays, loading states, S02 states, national-map layers, themes, en-US and Ionic Android mode (an iOS WKWebView in Android styling, not an Android device), and two 2026-09-25 captures show S03/S04 on an iPad Pro 11-inch in portrait (landscape was not captured). Captures keep their original dates and `ff7acf39` source commit; they remain valid at `bd6640f2` because the client source is identical. Server analysis is source-based, supplemented by synthetic execution of extracted functions where a document says so; the [probes directory](../../reports/rewrite-verification/probes/) holds eight probe records: six from Node scripts that re-run offline with plain `node` (re-run at `bd6640f2`), and two from the WKWebView capture harness (dated 2026-09-24, `ff7acf39`). Historical deployment observations are explicitly dated. This package is not a specification of a newly chosen framework or a claim that the legacy deployment has been retested.

## How the documents connect

Follow one user flow end to end: **S01 location selection → public weather URL → gateway boundary → KMA or world assembly → raw response → WeatherUtil conversion → WeatherInfo city → S03/S04/S05**. The public `/weather/v000903` prefix is not an Express mount in this repository. Backend storage objects, wire JSON and client chart models are three distinct shapes.

For rewrite acceptance, map each screen and overlay to its required fields and element bindings, each field to the producing server stage, and each stage to its data producer/freshness/failure behavior. The API catalog, native consumer inventory and version-routing diagram identify callers that still depend on older mounted contracts, and the web PWA section lists the v000903 contracts a browser client depends on. Use explicit decisions for incompatible changes. Examples are executable characterization inputs, not an exhaustive new schema.

## Evidence vocabulary and maintenance

**Observed source** means checked at the baseline revision (`bd6640f2`; client lines are the same at `ff7acf39`). **Synthetic execution** means a parser, extracted function, probe or test shell ran with fixtures in isolation. **Historical deployment** means an earlier dated observation. **Proposal** means a decision/test/migration step has not yet been implemented. Preserve those distinctions when quoting this package. Runtime behavior is described as observed only when a probe or capture shows it; source anomalies are not confirmed production bugs.

On route/model/parser/screen changes, update the affected contract, screen or overlay definition, element bindings and example together; regenerate diagrams and capture evidence as applicable. Record a new revision deliberately, as the `bd6640f2` re-baseline did: move only text-identical line anchors automatically, re-verify statements about changed code, and mark removed defects "resolved upstream in `<commit>`" instead of deleting them. Do not relabel old screenshots or AWS observations as current without revalidation. Recheck native status bar/safe area, live API/CORS, provider availability, production release configuration, user preference migrations, widgets and purchase/push before treating a rewrite as production-equivalent.
