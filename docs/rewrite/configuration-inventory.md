# Configuration and build-variant inventory

Source baseline: `bd6640f2`, re-baselined 2026-09-25 from `ff7acf3996ccb66c912d2ed4710cf300197d6966` (first inspected 2026-09-24). Client, iOS and Apple Watch source is identical to `ff7acf39`, so sections 2–4 carry over unchanged. Section 1 was re-verified against the upstream server changes: New Relic and direct APNs were removed, ASOS history settings were added and the server now targets Node 16 ([§1.9](#19-upstream-configuration-changes-since-ff7acf39)). [Section 5](#5-web-pwa-web-configuration) covers the static web PWA at branch `webapp-docs-gap-corrections`. Everything here is **observed source** unless it is labelled otherwise. No server, collector, build, simulator, provider, database or AWS call was run. This file lists configuration **names**, consumers and default behavior. It never reproduces credential values, ad or analytics identifiers, service-account file contents or private hostnames. Where a literal is hard-coded in source, the file and line are cited instead. Deployed values observed on the service host are **historical deployment** evidence; they stay in the [service EC2 internals](../architecture/ec2-internals.md#resolved-application-configuration) and are only linked from here.

**How to use during a rewrite.**

- Build the replacement's configuration schema from sections 1 and 2. Classify each input, decide whether it must be present at startup, and fail fast when it is absent. The legacy code substitutes non-empty placeholder strings instead of failing. The only exception is the `ASOS_HISTORY_*` settings added upstream, which default to off, `undefined` or empty (§1.2).
- Keep every **Secret** and **Private ID** row in a secret store or private release repository, never in fixtures or documentation. Where each secret lives and how exposed it is today is summarized in [security and privacy inventory §2](security-and-privacy-inventory.md#2-secret-and-credential-locations-names-only). Test fixtures should use obviously fake values of the same shape: a JSON array string for the `*_KEYS` names and a URL for endpoints.
- Use section 3 to decide which product/platform variants the replacement build must reproduce, and which Gulp side effects to drop on purpose.
- Rows marked unused or dead should be retired only after a deliberate decision in [decisions and open questions](decisions-and-open-questions.md). Other documents cover provider endpoints ([external providers](external-providers.md)), process modes ([server data lifecycle](server-data-lifecycle.md#process-modes-and-startup-dependencies)) and push/purchase flows ([server push and purchase](server-push-and-purchase.md)).

## Legend

| Column | Values |
| --- | --- |
| Class | **Secret**: authenticates or signs (API keys, tokens, passwords, license keys, private keys, service-account files, database connection strings that can embed credentials). **Private ID**: not a credential by itself, but account- or deployment-specific (ad units, analytics IDs, app IDs, distribution IDs, bucket names, private hosts). **Endpoint**: base URL or address the code calls or listens on. **Behavior**: selects a mode, version, geometry or UI behavior. |
| Mode | **Import**: read while a module that `app.js` loads is being imported. Route mounts do not depend on `SERVER_MODE`, so this applies in every mode. **gather** / **scrape** / **push**: startup work of that mode (`local` runs gather and scrape). **Request**: read while serving an HTTP request. **Route only**: reached only through a maintenance handler such as `/gather/*`. **Operator**: a manually run command that does not import `app.js`, such as `server/bin/backfill-history.js`. **Offline**: `server/utils` scripts or `server/test` only. |
| Unset | The effective value when the variable is absent. "Placeholder" means a non-empty English sentence or dummy string. Truthiness checks therefore treat it as configured. |

## 1. Server environment names

**Count at `bd6640f2`.** `grep -rhoE "process\.env\.[A-Za-z_0-9]+" server --include='*.js' --exclude-dir=node_modules --exclude-dir=test | sort -u | wc -l` returns 68 names. [`config.js`](../../server/config/config.js) reads 66 of them; the command with only that file returns 66. The remaining two are outside `config.js`:

- `NODE_ENV` is read live only in [`lib/log.js#L21`](../../server/lib/log.js#L21). The commented-out APNs gateway block in `controllerPush.js` that also mentioned it was deleted upstream (`c80ee014`).
- `S3_BUCKET` appears only in comments ([`controller.s3.js#L50`](../../server/s3/controller.s3.js#L50), [`#L86`](../../server/s3/controller.s3.js#L86)), so no live code reads it.

That leaves **67 names read by live code** at `bd6640f2`. Since #2585, `config.js` also reads `VC_SECRET_KEY` and `VC_DAILY_RECORD_LIMIT` (68 names in that file). Without `--exclude-dir=test`, the command returns 75. The extra seven names are read only by the new `server/test/offline` harnesses: `TZ`, `TW_REPO`, `TW_SMOKE_NOW`, `TW_SMOKE_OUTPUT_DIR`, `TW_SMOKE_CONTEXT`, `TW_DAILY_EVIDENCE` and `SMOKE_POLICIES` (Offline; they are not listed below). At `ff7acf39` the unfiltered command returned 66, `config.js` 64 and live code 65. The difference is −2 removed (`NEW_RELIC_LICENSE_KEY`, `APN_KEY_ID`) and +4 added (`ASOS_HISTORY_*`); see [§1.9](#19-upstream-configuration-changes-since-ff7acf39). `OPENSHIFT_NODEJS_IP`, `OPENSHIFT_NODEJS_PORT` and `PORT` are each read three times in `config.js`. The triple read of `APN_KEY_ID` is resolved upstream (§1.5). Libraries can read further names on their own: Express derives `app.get('env')` from `NODE_ENV`, and the AWS SDK has its own environment conventions. Those library behaviors are not verified here because `server/node_modules` is not installed in this checkout.

## 3. Gulp product build and release variants

[`client/gulpfile.js`](../../client/gulpfile.js) defines 16 tasks (`grep -c "gulp.task(" client/gulpfile.js`). Nine are product build/release tasks; they are the matrix below. The other seven are `default`, `sass` and `watch` (Sass only), `install` and `git-check` (Bower), `build` and `rmplugins` (see the oddities below). The file reads `./tw.package.json` and `./ta.package.json` synchronously when it loads ([L14-L15](../../client/gulpfile.js#L14-L15)), so Gulp must run in `client/`. Every command was **read, not executed**; `ionic state reset|restore` semantics are Ionic CLI 1.x behavior and were not verified. Plugin effects and JavaScript surfaces are documented in [native consumers and plugins §2.1–§2.3](native-consumers-and-plugins.md#2-build-variants-and-cordova-plugins); this section records the inputs each task selects.

**Shared sequence.** Every product task:

1. Copies a product package file over `package.json` and a `config*.xml` variant over `config.xml`.
2. Copies `../<tw|ta>.ads.client.config.js` over `www/client.config.js` (section 2).
3. Replaces `resources/` with `<tw|ta>.resources`.
4. Runs `ionic state reset`, then task-specific plugin commands, then `yarn install`, `bower install` and `gulp sass`, and finally `ionic build <platform> [--release]`. Exception: the min16 task adds the Crosswalk plugin after `gulp sass` ([L135](../../client/gulpfile.js#L135)).

The iOS tasks additionally swap in `import_today_ext/<tw|ta>.empty.package.json` before the reset, copy `../<tw|ta>.ios/*` into `platforms/ios/`, restore the product package file and run `ionic state restore --plugins` (TW [L73-L78](../../client/gulpfile.js#L73-L78)). The iOS platform, the Today widget and the entitlements therefore come from the checked-in native trees, not from Cordova generation.

The tasks overwrite **tracked** files in place: `client/package.json`, `client/config.xml`, `client/www/client.config.js`, `client/www/js/controller.purchase.js` and the 59 files under `client/resources/` (`git ls-files client/resources | wc -l`). Running any task leaves the working tree modified. At this revision `client/package.json` equals `tw.package.json`, and `client/resources/` equals `tw.resources/` (`diff -rq client/resources client/tw.resources` prints nothing).

## Limitations

- **Source only.** No server, collector, Gulp task, Cordova/Ionic command, native build, simulator, provider, database or AWS call was run for this inventory. Library conventions (AWS SDK credential chain and `AWS_REGION`, npm `engines` and `overrides`, `.nvmrc` version managers, Ionic `state reset|restore`, Cordova `build.json`, Firebase plugin file lookup) are described as unverified.
- **Deployed values unknown.** The release copies of `server/config/config.js`, the Firebase service-account files, the six external client release files, signing material and CI secrets are not in the repository. Which names are actually set in production, and to what shape, is unknown. The only deployed-host observations are the timestamped ones in [EC2 internals](../architecture/ec2-internals.md#resolved-application-configuration).
- **Counts are revision-bound.** The 68/66/67 server names (75 with the offline test harnesses) and the 37 `DB_DATA_VERSION` comparisons come from the commands quoted above at `bd6640f2`. The 22 client keys, 16 Gulp tasks and client reader lists were counted at `ff7acf39`; the client tree is identical at `bd6640f2`. The ASOS history settings were traced through `server/lib/history`, the Manager, `controllerTown` and the backfill command only. Dynamic property access (for example `config.keyString[name]`) would not appear in a `process.env.<NAME>` or `clientConfig.<key>` grep; none was found in the files read, but no exhaustive dynamic-access search was made.
- **External plugin and widget code.** Configuration consumed inside external Cordova plugins or the Android widget repositories (for example preference keys or plugin variables beyond the Gulp commands) is not covered.
- **Dead-code classification** relies on caller searches in `server/` or `client/www/js`, excluding tests. A route or script outside these trees that calls the same function would change the result.
