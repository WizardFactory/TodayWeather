# Persistent data model reference

Source baseline: `bd6640f2` (re-baselined 2026-09-25 from `ff7acf3996ccb66c912d2ed4710cf300197d6966`; client source identical to `ff7acf39`). Rows that describe server code changed between the two revisions were re-read at `bd6640f2`; each upstream change is cited by commit. This document covers what the Mongoose model files do **not** state: derived collection names, who writes and reads each model, the identity key each writer upserts on, declared indexes, `DB_DATA_VERSION` applicability, retention, reference-data provenance and time encodings. Field lists stay in the linked model files; sentinel defaults are in the [domain glossary](domain-glossary.md#1-kma-products-categories-and-sentinels). Evidence levels follow the [package vocabulary](README.md#evidence-vocabulary-and-maintenance). Most rows are **observed source**. Collection names and time-helper results come from **synthetic execution**: pure library or helper code run in Node v24.21.0, with no MongoDB, provider, collector or server started. No live database, export or index listing was inspected.

**How to use this during a rewrite.**

- Before migrating or replacing a store, find its row in [§1](#1-model-and-collection-inventory). Take the collection name from that row, not from the file name.
- Use the identity-key column as the de-duplication key when you export or import data. No Mongoose model declares a unique index, so duplicates are possible. The two native history collections added upstream ([§1.8](#18-historical-observation-store-native-collections)) are the exception: their key is MongoDB's unique `_id`.
- Use [§2](#2-retention-and-pruning) to assign each cleanup rule to one owning role. Several rules run only in `gather` mode, one runs on every world request, and one never runs.
- Rebuild grid and area lookups from [§3](#3-reference-data-provenance), not from a live `towns` snapshot alone.
- Before comparing any stored date with "now", read [§4](#4-time-representations). Four encodings coexist and some depend on the host time zone.

Related: [server data lifecycle](server-data-lifecycle.md) (product ownership, schedules and freshness), [server response assembly](server-response-assembly.md) (read order), [configuration inventory](configuration-inventory.md) (`DB_DATA_VERSION`, `MONGOLAB_MONGODB_URL`), [external providers](external-providers.md) and [push notifications](../architecture/push-notifications.md). Upstream design notes for the changes since `ff7acf39`: [daily forecast validity](../architecture/weather-collection.md#daily-forecast-validity-issue-2560) (mid RSS retirement, `dailySource`), [historical ASOS recovery](../architecture/weather-collection.md#historical-asos-recovery-2564) and [gather source reconciliation](../architecture/gather-source-reconciliation.md).

## 1. Model and collection inventory

**Counts and derivation.**

- `grep -rn "mongoose.model(" server/models | wc -l` gives **49** registrations in 49 of the 51 files under `server/models`. [`modelUtil.js`](../../server/models/modelUtil.js) and [`dateUtil.js`](../../server/models/dateUtil.js) are helpers.
- No model passes a collection argument or a `collection` schema option, and nothing overrides `mongoose.pluralize` (`grep -rn "pluralize\|collection:" server/models server/app.js server/config`).
- Collection names are therefore produced by `mongoose-legacy-pluralize` 1.0.2. That is the pinned dependency of `mongoose` 5.1.2 ([server/package.json](../../server/package.json)); the lock file added upstream in c80ee014 resolves both versions ([package-lock.json](../../server/package-lock.json), entries `node_modules/mongoose` and `node_modules/mongoose-legacy-pluralize`). It is called through `utils.toCollectionName` (mongoose 5.1.2 `lib/index.js` L383-L386).
- The count and the "no collection option" result were rechecked at `bd6640f2` (still 49 in 51 files; upstream changed five model files but added none). The two history collections in [§1.8](#18-historical-observation-store-native-collections) are opened through the native driver with literal names, so no pluralization applies to them.
- Since #2585 two models pass an explicit collection name as the third `mongoose.model` argument, so no pluralization applies: `VcFetchLock` → `vc.fetch.locks` and `VcUsage` → `vc.usage` ([§1.6](#16-world-weather)). The grep above now gives 51 registrations in 51 of 53 files.
- The names in the tables were produced by running that package's function over the 49 names (synthetic execution against `ff7acf39`; the model names are unchanged at `bd6640f2`; the harness is not checked in). The function lower-cases every name and pluralizes the last word, so `kma.town.short.rss` → `kma.town.short.rsses`. A name that ends in a digit is left unchanged, so `KmaStnHourly2` → `kmastnhourly2`.

**Indexes.**

- No schema declares a `unique`, `sparse` or TTL (`expires`) index. `unique` appears only in comments, for example [modelKmaStnInfo.js#L8](../../server/models/modelKmaStnInfo.js#L8) (`grep -rn -i "unique\|expires" server/models`).
- Every idempotent write is therefore an `update(query, doc, {upsert: true})` or a find-then-save on a non-unique key. Concurrent or overlapping jobs can create duplicates. This follows from MongoDB behavior; it was not observed.
- Several models declare a `text` index on an identifier (`stnId`, `regId`, `areaNo`, `stationName`, `location`). Text indexes do not serve the equality lookups the code performs.
- Geo fields are `[longitude, latitude]` with an inline `index: '2d'`.
- The code never sets `autoIndex`, so Mongoose's default index build on model compile applies in every process that loads a model. This is the library default, not observed on a host.

**Column meanings.**

- *Writer*: the live write path, with the process mode that normally triggers it. Every `/gather/*` route is also reachable in any mode ([lifecycle](server-data-lifecycle.md#process-modes-and-startup-dependencies)).
- *Identity key*: the filter each writer upserts or finds on.
- *DB ver.*: the value of `DB_DATA_VERSION` under which the path is used ([config.js#L17](../../server/config/config.js#L17)). "both" means not gated. Tables 1.3–1.6 omit the column because none of their paths reads the setting. At `ff7acf39` all `config.db.version` comparisons were in the six files listed in the [configuration inventory](configuration-inventory.md). At `bd6640f2` they are in five: 95fe711e removed the branch from `kma.town.mid.rss.controller.js` (`grep -rln "db.version" server --include='*.js' --exclude-dir=node_modules`, excluding `server/test`). The history store ([§1.8](#18-historical-observation-store-native-collections)) is shared by both versions.
- *Date encoding*: each persisted date field is classified in [§4.2](#42-persisted-date-fields-by-collection), a separate table so these rows stay readable.
- *Status* values:
  - **serving**: read on a current request path.
  - **1.0 only / 2.0 only**: read and written only under that DB version.
  - **gather only**: written and read only by collection jobs.
  - **no live writer**: the code still reads it, but its writer is commented out or unreachable.
  - **dead**: required, but no reachable read or write.
  - **legacy world**: reachable only through the older world stack.

## 2. Retention and pruning

Apart from `vc.fetch.locks` (#2585, TTL on `expireAt`), no collection has a TTL index, so every other deletion below is application code. A rule runs only while its owning job runs. `grep -rnE "\.remove\(" server/controllers server/lib` lists every Mongoose deletion call (28 at both `ff7acf39` and `bd6640f2`), and each call was checked for a callback or `.exec()`. The only native-driver deletion is the history lease release (`deleteOne`, [§1.8](#18-historical-observation-store-native-collections)). "now − N d" means `new Date()` followed by the local-time `setDate(getDate() − N)`. On a host with daylight saving time, that span is one hour shorter or longer than N × 24 h across a transition: 239 h for 10 days across the spring change and 241 h across the autumn change in the [§4.4 probe](#44-synthetic-probe).

### 3.3 Grid projection (`coordinate2xy`)

[coordinate2xy.js](../../server/utils/coordinate2xy.js#L21-L33) implements the KMA Lambert conformal conic grid used for `mCoord {mx, my}`:

- Earth radius 6371.00877 km, grid 5 km.
- Standard parallels 30° and 60°, origin 126° E / 38° N.
- Offset `xo = 42`, `yo = 135`; bounds `MAX_X = 149`, `MAX_Y = 253`.

Synthetic check (harness not checked in): the file's own usage example (lon 127.1201305, lat 37.37258333) returns `{x: 62, y: 123}`, as its comment states. Callers:

- The seed and update scripts.
- The request-time town insert, through [convertGeocode.js](../../server/utils/convertGeocode.js).
- `kmaScraper`: station grid for the rain hit-rate job ([kmaScraper.js#L1176-L1182](../../server/lib/kmaScraper.js#L1176-L1182)). Its station-address town insert, `addStnAddressToTown` ([L1396-L1444](../../server/lib/kmaScraper.js#L1396-L1444)), has no caller.
- `controllerManager` requires the module ([L15](../../server/controllers/controllerManager.js#L15)) but never calls it.

A rewrite must reproduce this projection bit-for-bit, or store the precomputed `mCoord` values. Otherwise grid keys in `towns` and in the KMA collections stop matching.

## 4. Time representations

Domestic code uses several time encodings at once, in memory and in MongoDB. MongoDB stores a `Date` as UTC milliseconds without a zone. Whether a stored `Date` is a real instant therefore depends on which helper built it and, for some helpers, on the `TZ` of the process that wrote it. The process time zone is not configured in runtime code: at `bd6640f2`, `grep -rn "process.env.TZ\|TZ=" server --exclude-dir=node_modules` finds only the offline tests added upstream, and the CI workflows pin `TZ: UTC` (plus an `America/Los_Angeles` run) for those tests only. The host time zone is not recorded in [EC2 internals](../architecture/ec2-internals.md). The upstream test notes call UTC "the server timezone confirmed by the operator" ([server/test/offline/README.md#L48](../../server/test/offline/README.md#L48)); that is an operator statement, not an inspected host setting. The new history and mid-forecast policy code avoids the question by computing KST explicitly (E2 row).

### 4.5 Fixture and migration rules

- Run every characterization fixture that touches stored dates three times: with `TZ=Asia/Seoul` pinned, under `TZ=UTC`, and under a DST-observing zone such as `America/New_York`. Include one run whose clock crosses that zone's DST change. Record the zone with the fixture, as the [lifecycle inventory](server-data-lifecycle.md#rewrite-dependency-inventory) already requires.
- A comparison that differs between runs marks E4 data or mixed operands. Decide the intended semantics; do not copy whichever result the reference host happened to produce.
- Before migrating E4 fields (`kmastn*`, `kmaspecials`, air `date`, life/health, KASI), find out the writer host's zone. Converting them to true instants requires that offset. The same collection may contain values written under different zones if hosts or `TZ` changed over time.
- Keep E1 strings as strings, or convert them explicitly as KST (`+09:00`). Do not convert them with a zone-less parser.

## Limitations

- **Evidence level.** Everything here is observed source at `bd6640f2`. Rows on code that did not change since `ff7acf39` were carried over; their anchors were moved mechanically only where the target lines are text-identical. Three parts are synthetic execution in Node v24.21.0 against `ff7acf39`, on inputs unchanged at `bd6640f2` (`kmaTimeLib.js`, the model names and `coordinate2xy.js` are not in the upstream diff): the time probe (checked in, [§4.4](#44-synthetic-probe)); collection-name derivation, using the published `mongoose-legacy-pluralize` 1.0.2 and `mongoose` 5.1.2 package sources; and the grid check. The naming and grid harnesses are not checked in. No MongoDB instance, export, index listing, provider, collector, script or server was run.
- **Not checked.** Actual collection names, index state, document counts, duplicates, E4 offsets, and whether `healthdaykmas` or `dsfforecasts` grew on any host. Whether any host sets the `ASOS_HISTORY_*` flags, holds `asos_history` data, or still holds mid RSS documents. None of the upstream offline tests under `server/test/offline` was run for this document.
- **Reachability.** "No live writer", "dead" and "no caller" statements come from repository-wide `grep` of call sites. Dynamic dispatch through strings was checked only where the code builds model names: the `midArray`/`dbType` maps and `Db20Collections`.
- **Push and legacy world models** are summarized only as far as needed for ownership. See the linked documents.
- **Not traced.** Air-reader date comparisons in `kecoController` and the world city CSVs' relation to `geocodes`.
