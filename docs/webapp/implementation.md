# Webapp implementation and release status

Issue: [WizardFactory/TodayWeather#2558](https://github.com/WizardFactory/TodayWeather/issues/2558). Initial implementation prepared on 2026-09-24; updated to a static-only client. The full mobile parity release remains open; this is an executable integration candidate, not a deployed or production-approved release. Behavior below includes the PWA audit fixes on this branch (`webapp-pwa-audit-fixes`, based on `b8a3c504`, 2026-09-26).

## Run locally

Use Node >=22.12 (verified with 22.22.2) from the repository root. These npm workspaces are independent of the historical `client/` and `server/` packages.

```sh
npm ci --ignore-scripts
npm run dev
```

Open http://127.0.0.1:5173. The default is **direct/live**: the browser calls the existing public API and the launcher starts only Vite. Set a loopback `WEB_ORIGIN` for another development host/port. For explicitly labelled synthetic data use `VITE_WEB_MODE=demo npm run dev`; changing cities does not make demo fixtures real observations.

```sh
# Build only the static client. No API process is needed.
npm run build
npm start
```

Open http://127.0.0.1:4174 to exercise the production bundle, service worker and snapshots. Live failures never substitute demo responses; a previously received snapshot may be shown with a disconnected/stale notice for up to 24 hours. The preview is a local file server, not a production requirement.

Deploy `web/dist` to **app.tdywx.xyz** using the [S3 + CloudFront runbook](../../infra/web/static/README.md): Option A reuses the existing distribution and bucket; Option B uses the template with a planned alias cutover. The deployment method awaits AK's decision. No AWS resources or DNS were created by this implementation.

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
# Unmocked, read-only smoke against the public API (local preview of web/dist)
node scripts/web-live-smoke.mjs --json test-results/web-live-smoke.json
```

Browser tests own a static-only server on port 4174 and intercept external API reads with synthetic raw provider fixtures. Their global setup stops the run when `web/dist` is older than `web/src`, `web/public`, `web/index.html`, `web/vite.config.ts`, `scripts/web-precache.mjs`, any `web/.env*` file or the core sources; rebuild first (`WEB_E2E_ALLOW_STALE_DIST=1` skips the check for deliberate runs against an older build). They assert that the browser makes no `/api/` requests, and a context-level fallback aborts any public API request that no test route handles, so a test that removes its page routes still cannot reach the real API; they do not prove live provider freshness. Set `PLAYWRIGHT_EXECUTABLE_PATH` for a preinstalled browser. CI also publishes `web-static-dist`, retained for 90 days. The [live smoke](../../infra/web/static/README.md#live-smoke) is the only check that calls the real API; it runs daily and on manual dispatch in the **Web live smoke** workflow, never on pull requests, and after a deployment with `--base https://app.tdywx.xyz`.

Only direct transport is supported. Omit `VITE_WEB_TRANSPORT` or set it to `direct`; `proxy` is rejected. `VITE_WEB_MODE` selects `live` or labelled `demo` data at build time; a live build contains no demo fixtures. The UI is Korean-only by AK's decision: there is no translation catalog or browser-locale override, and API requests send `Accept-Language: ko`. The former web API workspace, notification sender and Docker deployment recipe have been removed. Node runs build/development/preview tools only.

Four settings subpages are consolidated into `/settings`; weather/air overview is available in the same product. Supported interfaces preserve the user actions, not the old Cordova navigation structure. The paid tier is not represented as implemented.

Accessibility and time presentation: the closed mobile menu is `inert` and out of the tab order; opening it takes focus; Escape, the close button or the backdrop return focus to the menu button (`aria-expanded`); widening the window past 680 px closes it. View, pollutant and nationwide tabs expose `aria-pressed`, and toasts use a persistent `#toast-region` live region. Focus moves to `main` after a route change, after the menu has closed and `inert` is removed when the link was in the menu; the in-page weather view tabs keep focus on the pressed tab, but Back/Forward always moves focus to `main`, also onto a history entry that a view tab created. KMA/AirKorea times are labelled KST and overseas times "(현지 시각)"; last-receipt times in notices are shown in KST. Staleness notices compare KST times exactly (3 hours for observations, 24 hours for forecast publication and warnings); overseas times use a date-only rule counted from the end of that date at UTC−12, so a fresh reading is never flagged ([details](../architecture/web-client.md#display-parity)). A CORS-readable 429 or 503 is not retried: 429 shows a rate-limit message with the `Retry-After` wait only when the API exposes that header (otherwise a generic wait, assumed to be 60 seconds), and 503 shows a generic temporary-outage message. With a stored snapshot, a 429 shows the snapshot with the rate-limit notice and does not request again automatically (focus, reconnect, remount) before the retry time; the refresh button still requests immediately. A 429 or 503 without CORS headers looks like a network failure and gets the single network retry ([request flow](../architecture/web-client.md#request-and-data-flow)).

## Architecture and contracts

See [implemented architecture](../architecture/web-client.md) and its [interactive diagram](diagrams/webapp-implementation.html). The [technical design](technical-design.md) and [hosting diagram](diagrams/webapp-architecture.html) use the same static-only boundary. The default runtime is a static PWA on private S3/CloudFront with direct calls to the existing public API. It requires no new persistent Node service or API Lambda.

- `packages/weather-core/`: source-aware, unit-aware normalization without mutating provider payloads. KMA `-50` temperatures and negative nonnegative metrics become unavailable; valid zero remains zero. Daily rows older than the source's yesterday are excluded by source date. KMA rain is marked as observed (`rn1`: current 1 hour, past short 3 hours, past-day accumulation), approximate (shortest 1-hour category lower bound) or server-calculated forecast (`r06`/`s06`: 3-hour short rows, daily totals from today) per [D45](../architecture/web-client.md#precipitation-and-snow-d45). Zero snowfall stays in data but is hidden in the UI, while positive values below 0.1 mm (0.01 in) display as `<0.1` (`<0.01`).
- `web/`: React/TypeScript UI, versioned local preferences, IndexedDB snapshots keyed by location and all units (age pruning, deletion and the 30-entry bound read keys and values in one transaction), query cancellation and explicit stale/demo notices. A snapshot-backed result is stale at once and refetches on focus or reconnect, except a rate-limited snapshot still inside its `Retry-After` wait. Normalization cache-key revision v3 separates new weather query/snapshot keys from older normalized values; favorites and settings are preserved. Snapshots are shown first while refreshing, deleted with their place and pruned after 24 hours. Coordinates are rounded to three decimals; sharing uses a curated public city ID rather than exact current location.
- `web/src/direct-api.ts`: fixed public API operations, bounded reads, JSON/schema checks, canonical physical units and local normalization; local catalog and capabilities. Network/CORS failures receive Korean retry guidance without guessing their cause; a readable 429 raises a rate-limit error carrying the `Retry-After` wait (60 seconds when unreadable) and a 503 a generic outage message; cancellation and timeouts retain their own handling. The overseas catalog remains available, but error messaging cannot repair upstream availability.
- `web/src/demo/`: browser-owned synthetic raw fixtures, selected only by explicit demo mode and bundled only in demo builds.
- `infra/web/static/`: private S3/OAC, CloudFront/TLS/DNS template, route function and guarded dry-run uploader whose preflight names each destination mismatch and rejects error-to-page mappings. Deployment method selection and AWS changes remain separate operator tasks.
- `scripts/web-live-smoke.mjs` and `.github/workflows/web-live-smoke.yml`: unmocked read-only smoke of the static app and public API, before deployment (local preview) or after it (`--base`).

The service worker caches the shell and hashed assets, not API responses. Activation is user initiated for updates; only the newest complete previous shell cache is retained for existing tabs, and incomplete caches are deleted unless another worker is still installing. The app checks for a new worker hourly and when the page becomes visible. Only the tab whose user pressed "업데이트" reloads; other open tabs drop their now-stale "새 버전이 준비됐습니다" offer and show "새 버전이 적용됐습니다" with a "새로고침" button. Pressing "업데이트" when no worker is waiting only hides the offer and records no reload request, a request left over from before a page load is cleared, and the next controller change consumes the request even in a page that had no controller yet, so a later release never reloads a tab its user did not update. Browser snapshots are separate and expire after 24 hours. Maps and warnings require a network connection. Losing browser storage loses local favorites and snapshots.

## Evidence from live reads

Bounded public reads on 2026-09-24 returned HTTP 200 for health, domestic coordinate weather, reverse geocode, national data and warnings. Raw probe receipts are local, ignored SDLC records. A successful response does not establish data quality:

- Seoul's KMA current temperature was 25.2 C, while its yesterday temperature used `-50`; the upstream summary reported an invalid +75 degree comparison. The client computes comparisons from validated values instead.
- Daily data mixed April 2025 rows with September 2026 rows. The adapter excluded historical rows from the future forecast.
- Nationwide air included a 2021 observation timestamp; it is visibly stale. Domestic weather did not include an air station list.

No provider freshness repair, legacy server mutation, database migration or mobile release has been performed. A public release with maximum parity must resolve these upstream and device gates, plus the explicit feature gaps above; keep #2558 open.

Not covered by any automated check: an interrupted upload (recovery is to retry the same complete artifact), pressing "업데이트" when no worker is waiting, a page without a service-worker controller consuming the reload request, TLS, the real-gateway error cases of V42 (JSON error, gateway/Lambda error, redirect), a real 429/503 and whether the API exposes `Retry-After`, the browser path of a 429 without the expose header and of a `Retry-After` HTTP date (both covered by unit tests only), CORS from the real `app.tdywx.xyz` origin before deployment, and monitoring or rollback triggers. The unit-switch test changes the unit only after the weather has rendered.

Deferred: a unit change while a weather request is still in flight (the stored snapshot and the shown units after the response lands), a browser test of the air-station staleness path (the 3-hour limit and zone label on air station times), screenshot comparison, a browser test of the default KMA main journey against a stored response, an end-to-end run of a demo build, Safari/Firefox/Edge runs, automated accessibility (axe) scanning, and the WAQI "(현지 시각)" label, which cannot be verified while overseas weather returns 501 (the server may set WAQI times from UTC). Backend follow-ups are listed in the [release gaps](#release-gaps).

The rewrite [verification matrix](../rewrite/verification-matrix.md) V01–V41 describe legacy server/app behavior; V42 is the web consumer contract. The live smoke covers its KR success paths and records the current non-KR failure as a warning; its error, redirect and unit-mismatch cases are covered only by the mocked tests above.
