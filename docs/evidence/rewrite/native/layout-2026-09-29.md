# Post-deployment mobile layout verification — 2026-09-29

## Scope and evidence

TodayWeather Cordova branch after c5bcc0f1; Android API 36 emulator screen sizes use wm size/density (3x DPR), iOS 26.5 uses actual simulator profiles. Live public v000903 weather for Seoul and Tokyo. Test ad units. All push registration/settings writes intercepted; this is S09 layout coverage, not production push registration or notification receipt.

**iOS limitation:** the normal simulator artifact repeatedly aborted in GULMutableDictionary (NSInvalidArgumentException: key cannot be nil) during startup. The same layout run completed after setting FIREBASE_ANALYTICS_COLLECTION_DEACTIVATED=true in an ad-hoc signed temporary app copy. The production configuration was not changed. All final iOS layout captures use that copy; this does not establish release startup/Analytics health. Native notification permission requests are also skipped in layout mode to keep system prompts out of screenshots.

## Reproduced fix

At 320px, the English AQI grade Moderate wrapped as Moderat/e. tab-air.html now uses 55% of the numeric font size for textual AQI grades only; ionic.app.scss allows line breaks between words. Pollutant numeric sizing is unchanged. The harness asserts nonempty live air and checks that grade words do not fragment.

## Checks

- Full existing layout walk through S01–S12/S14 and push settings, page overflow and screenshots.
- Seoul and Tokyo current air value/grade, publication time, pollutant strips (both ends), bottom cards, and any available air chart endpoints.
- Hourly/daily weather chart initial/current column, bounds, vertical clipping, and Android touch gestures without switching city. iOS chart scrolling is programmatic, not physical touch evidence.
- Android CDP selection now targets https://localhost explicitly; AdMob page targets otherwise received the gestures. iOS native uncaught exceptions are recorded by the driver.

## Capture/runtime caveats discovered in visual review

The first Android 412x869 run displayed a native "TodayWeather is not responding" dialog. Logcat records an input-dispatch timeout waiting 5155 ms for a focus event. DOM checks continued under the native dialog, so this run is not a clean native pass. A separate full repeat passed 75/75 checks with zero native/unclassified errors and no ANR dialog. The root cause of the initial ANR is not established by a screenshot or by that later pass.

The Android 360x800 S09 image showed another screen despite the DOM check reaching push settings. iOS 440x956 and 420x912 also had late Seoul-air captures. The Android full repeat passed 75/75 with zero native/unclassified errors. Supplemental iOS `capture-air` runs passed 12/12 each and keep states visible for eight seconds; originals remain in local evidence. Do not infer a rendered screen solely from a screenshot filename.

The iOS 420x912 run includes an initial no-scenario launch timeout before the three actual layout scenarios ran. Cold simulator migration and installation took several minutes on some profiles. This is reported separately from the completed screen checks.

## Remaining observations

- Supplier attribution is present in the API but is not displayed by this client.
- Google grid observations have no station name; the domestic station card still shows a grade without a station name.
- English ruler labels use ellipsis at narrow widths. Existing hourly date-label and chart-legend presentation limits remain.
- Current-only overseas air has no history/forecast chart. Domestic chart padding may show a single current observation, not a newly supplied historical series.
- airStatus.pending is not consumed by the app; no automatic retry was added.
