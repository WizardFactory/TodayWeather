# Static web client

Repository evidence: local web implementation prepared 2026-09-24 for [#2558](https://github.com/WizardFactory/TodayWeather/issues/2558), with display, state, privacy and deploy-preflight corrections merged in `23a61491` (PR #2582, 2026-09-26) and the PWA audit fixes on this branch (`webapp-pwa-audit-fixes`, based on `b8a3c504`, 2026-09-26). This document describes executable source and a prepared hosting topology; it does not claim the web app has been released. Issue [#2646](https://github.com/WizardFactory/TodayWeather/issues/2646) changes the canonical destination to `app.todayweather.ai` and prepares reuse of existing hosting, with operator-provided resource identifiers and separate production authorization. There is no isolated staging path: the build and uploader are fixed to `app.todayweather.ai` ([release gaps](../webapp/implementation.md#release-gaps)).

The new root npm workspace contains `web` and `packages/weather-core`. It does not reuse Cordova startup or import `server/app.js`; running local web tooling does not start historical gather/scrape jobs. The [implemented diagram](../webapp/diagrams/webapp-implementation.html) has [editable source](../webapp/diagrams/webapp-implementation.json). The [technical design](../webapp/technical-design.md) records the same static-only runtime and future parity boundaries.

## Request and data flow

`web/src/api.ts` defaults to direct/live transport. `web/src/direct-api.ts` maps fixed operations to the existing public HTTPS API, enforces a 15-second abort and 2 MB JSON read limit, and normalizes raw payloads in the browser. Requests omit credentials and reject redirects; existing public API CORS must permit the web origin. Network/CORS failures show Korean retry guidance; a browser cannot distinguish their exact cause. Cancellation and timeout handling remain separate. Catalog search and disabled static notification capabilities resolve locally. No `/api/web/v1` requests or new API backend are needed.

Each upstream GET is retried at most once, after 1 second, when `fetch` rejects without an abort or the response status is 502. A CloudFront 502 without CORS headers reaches the browser as a network failure, so both cases are covered. Other statuses, non-JSON or oversized bodies and aborts are not retried; the wait itself is abortable, and the single 15-second budget covers both attempts. A CORS-readable 429 or 503 is not retried. A 429 shows "요청이 많아 잠시 제한되었습니다. N초 후 다시 시도해 주세요." with the `Retry-After` seconds or HTTP date, but a cross-origin page can read that header only when the API sends `Access-Control-Expose-Headers: Retry-After`, which the live API responses observed on 2026-09-26 did not carry (a real 429 was not observed; backend follow-up). Without a readable value the message asks the user to try again shortly and the app assumes a 60-second wait. A 503 shows a generic temporary-outage message ("날씨 서비스를 일시적으로 이용할 수 없습니다…") and discards the body. A 429 or 503 without CORS headers (for example a CloudFront-generated error, or `nation` and `kma/special` outside the #2584 paths) is indistinguishable from a network failure: it gets the single network retry and the generic connection message. Reverse and address geocode requests use `cache: "no-store"` because they carry the user's position or search text.

`infra/web/static/stack.json` prepares a separate private S3 bucket and CloudFront distribution. The hostname is the `AppDomainName` parameter (default `app.todayweather.ai`, which is already an alias of an existing distribution; the [static runbook](../../infra/web/static/README.md#deployment-decision) selects reuse for this task and retains planned cutover as a separate alternative). OAC grants only that distribution object reads. Its viewer-request function rewrites known SPA links to `index.html`, serves only the shell files (`index.html`, `sw.js`, `theme.js`, manifest, icon, `release.json`), `assets/` and `icons/`, and preserves API/unknown/missing asset errors. Shell files revalidate, hashed assets are immutable, and old assets survive upload. The CSP allows connections to the existing API and uses `style-src 'self'` without `'unsafe-inline'`: inline `<style>` elements and markup `style` attributes are blocked, while style properties React sets through the CSSOM (chart bar heights, icon positions) still apply. The local static preview serves the same function and CSP, and the browser-test fixture fails a test on any CSP console violation. The template creates resources rather than adopting them; reuse attaches the existing route function code and new app-specific policies to the verified destination. Shared policies must not be modified in place. No production deployment is implied by the template.

`scripts/deploy-web-static.mjs` is a dry run unless `--execute` is given; the dry run prints the artifact's `release.json` `commit` and `builtAt`, and `--execute` refuses, before any AWS call, a build whose `commit` ends in `-dirty`. Before any upload it reads the destination and stops with a message naming the failed condition unless the distribution has the `app.todayweather.ai` alias, its default behavior targets the bucket's S3 origin, that origin has OAC and an empty `OriginPath`, the behavior uses `redirect-to-https`, no `CustomErrorResponses` entry sets a `ResponsePagePath`, a default-behavior viewer-request function's LIVE code equals `infra/web/static/route-request.js` (whitespace-normalized), and a response headers policy's CSP `connect-src` includes the API origin. Cache policy, certificate and DNS remain manual [Option A checks](../../infra/web/static/README.md#option-a-reuse-the-existing-distribution-and-bucket). The uploader and the build's `release.json` fix the site to `app.todayweather.ai`, so a different `AppDomainName` also needs those constants changed.

Only direct transport is supported: unset `VITE_WEB_TRANSPORT` or set it to `direct`; `proxy` is rejected. The former Node adapter and its Docker recipe are removed. `VITE_WEB_MODE=demo` loads browser-owned raw fixtures from `web/src/demo/`; live is the default. The mode is a build-time constant, so a live build contains no demo fixture chunks. Each build writes `release.json` with `schemaVersion`, `siteOrigin`, `transport`, `mode`, `apiOrigin`, `commit` (`GITHUB_SHA`, else local `HEAD` with a `-dirty` suffix when the working tree has uncommitted changes, else `unknown`; on `pull_request` runs `GITHUB_SHA` is GitHub's temporary merge commit, so those artifacts are not deployment candidates) and `builtAt` (honoring `SOURCE_DATE_EPOCH`).

Weather uses `/weather/v000903/coord/{latitude},{longitude}`; reverse/address lookup uses `/geocode/v000903/{coord|addr}/...`; nationwide and warning reads use `/v000903/nation/KR` and `/v000903/kma/special`. These reuse existing contracts without changing native paths. No `/gather/*` call exists.

The direct client requests canonical Celsius, m/s, hPa, km and mm physical units plus the selected air standard. `packages/weather-core/src/index.ts` converts to display units exactly once, accepts `source` `KMA` or `VC` (a missing source with `pubDate.VC` is overseas; `DSF` is rejected), rejects other weather sources or mismatched returned air standards and preserves observed/publication/fetch timestamps separately. KMA sentinel temperatures become null before comparison/conversion. Raw source wall times are not relabelled as UTC. KMA `stnDateTime` (`YYYY.MM.DD.HH:MM`) and the space and hyphen forms normalize to `YYYY-MM-DD HH:MM`; `YYYYMMDDHHMM` publication times become `YYYY-MM-DDTHH:MM`, so the observation-age notice can apply. Sunrise and sunset keep only `HH:MM`. Beaufort conversion uses the server `unitConverter` band edges. Daily rows start at the source's yesterday: yesterday's row is kept for comparison and older rows are dropped without a notice (the former "과거 예보…" notice is removed). Nationwide weather is converted as canonical request units; any per-item `units` in that body is ignored.

Geocode results are named like the app: `name`, else the `getShortenAddress` token rule applied to `address` (two to five space-separated tokens; `특별시`/`광역시`/`특별자치시` become `시` and `특별자치도` becomes `도`; parts joined by a space), else the full address, else `선택한 지역`. For weather responses the requested place wins: its ID, coordinates and name are kept, the response `name` is used only when the stored name is `선택한 지역`, and response `address`/`country` only fill empty stored values.

## Languages

`web/src/i18n/` holds one catalog per UI language — Korean (`ko.ts`, the source and key contract), English, Spanish, Japanese, German, Portuguese and French — each typed as the Korean key set, so a missing or extra key fails the build. Korean ships in the main bundle; the others are lazy chunks that the service worker precaches with the other assets. `main.tsx` loads the saved language, else the first supported browser language (primary subtag), else English, before the first render. Changing Settings → Language switches immediately and persists `settings.language` (`null` follows the browser).

`t()` fills `{name}` placeholders. `setLanguage` applies only the latest choice: a language that finishes loading after a later choice, including a return to the current language, is discarded. With no snapshot in the current language, the newest snapshot (`fetchedAt`) of the same place and units in another language is shown. `web/src/locale.ts` reads the country from the device language's region (the first browser language, or a later tag in the same language; other languages' regions are ignored): it sets the automatic units ([table](../webapp/specification.md#supported-languages-and-screen-sizes); `settings.userUnits` records explicit choices, and state saved before this change keeps all its units) and the regional conventions — a managed country with a supported browser language formats hours, dates and numbers with `Intl` in the device locale `<device language>-<country>`, so date order, clock and decimal mark do not change with the UI language; only the weekday and AM/PM words are replaced with the UI language's (`formatToParts`; numbers via `setNumberLocale` in `packages/weather-core`), otherwise the international standard applies (`HH:mm`, `MM-DD`, decimal point). The hourly chart widens its minimum point spacing for longer regional hour labels; Korean keeps the app's seven relative-day words, other languages use `Intl.RelativeTimeFormat` for two days either side. Overseas (VC) rows send the wind bearing in degrees; weather-core turns it into one of 16 compass points and the UI shows the code in the UI language (`wind.<code>`), while direction text sent by the server (KMA) is shown as received. Catalog cities show `city.<id>`/`cityArea.<id>` (`web/src/places.ts`); search matches localized, stored Korean and id names. Korean strings produced by the data layer and kept in snapshots ("선택한 지역", the two notices, station and warning fallbacks) are translated at display time by `coreText()`.

Every API request sends the selected language as `Accept-Language`; weather snapshot keys and the nation, warnings and place-search query keys include it. Server-provided text is displayed as received, so it follows the selected language only where the backend supports it (backend language support is a separate issue).

## Local state and privacy

Weather query identity includes place ID, rounded coordinates, all six unit settings, language and schema. Normalization cache-key revision v3 (precipitation basis and air forecast fields) uses new query/snapshot keys; older snapshot keys are ignored and pruned by age, while local favorites and settings are unaffected. Requests are abortable. Preferences are versioned and validated in `localStorage` key `tw.web.v1.preferences`; snapshots are records in IndexedDB database `tw.web.v1.snapshots` with a 24-hour maximum age and 30-entry bound. Expired snapshots are pruned at startup and after each write, and deleting a place (or replacing the current-location entry) deletes every snapshot keyed to its ID. Settings offers "이 브라우저의 오늘날씨 데이터 삭제", which after confirmation removes the preferences key and the snapshot database and resets state. Backup import asks for confirmation before replacing places and settings, then deletes the snapshots of every place it removed; cancelling keeps the favorites and says so. Age pruning, deletion with a place and the 30-entry bound (oldest `savedAt` first) all take keys and values from one read-only IndexedDB transaction, so keys and values cannot misalign; the deletes that follow run in separate transactions, so a snapshot rewritten between that read and its delete can still be removed. The early script `web/public/theme.js`, loaded from `<head>` (allowed by CSP `script-src 'self'`), applies the saved theme and its `theme-color` meta before first paint; `main.tsx` repeats the theme before the first React render, and the app keeps `theme-color` in sync when the theme changes.

The weather page renders a valid stored snapshot immediately while the network request runs ("저장된 자료를 먼저 표시하고 있습니다"); a refresh failure while live data is visible shows "최신 자료로 갱신하지 못했습니다" with the last receipt time. Offline/error snapshots retain source timestamps and display a disconnected notice. Empty air results replace previous air data instead of silently retaining it. Demo mode is explicit and never a fallback for live failures. A result served from a snapshot is stale immediately (live results stay fresh for 10 minutes), so it is refetched when the window regains focus or the network reconnects; the `online` event also refetches every active snapshot-backed query, because a page first loaded offline does not refetch by itself, except a rate-limited one whose retry time has not passed. A rate-limited weather request (429) with a stored snapshot shows that snapshot with the rate-limit message in place of the disconnected notice, and the snapshot stays fresh until the retry time (the `Retry-After` wait, or 60 seconds), so regaining focus does not request again before then. Without a snapshot the 429 or 503 message is shown in the error state with a retry button; a 503 with a snapshot shows the ordinary disconnected notice. The "마지막 수신" times in these notices are shown in KST. Favorites cards preview temperature, icon, AQI grade and save time (KST) from stored snapshots only; they make no network request.

Selecting a place always opens its weather in the preferred view; the `locations` startup setting applies only to `/` and otherwise opens hourly. There is one current-location entry: a new fix replaces it in place. A fix that lands on a saved favorite's coordinates selects that favorite and retires the old current entry; choosing a place at the current entry's coordinates promotes the entry to that saved place, so later fixes cannot remove it. When 30 favorites are saved, a new place is shown without saving and a toast explains why. A `storage` event for the preferences key (or a storage clear) re-reads state, so tabs stay consistent. Geolocation and address lookups are superseded by a newer lookup, a list selection or unmount; superseded results never navigate. Geolocation uses `maximumAge: 0`, and permission denial shows inline guidance with a retry button. Submitting the search form (Enter) selects a catalog place whose name or ID matches exactly, else the only place whose name starts with the text; otherwise it resolves the text as an address through geocode when live and at least two characters long. Address substrings never select a catalog place.

## Precipitation and snow (D45)

Server source and three read-only live KMA coordinate responses sampled 2026-09-26 01:06 KST (a local SDLC record, not committed) show that the server's KMA forecast `r06`/`s06` are split or summed hourly categories that currently undercount, and that the `*Str` strings apply a retired bucket table ([D45](../rewrite/decisions-and-open-questions.md), [period contract](gather-source-reconciliation.md#period-contract-and-consumer-limitations)). By product decision (2026-09-26) the web shows past rain as observations and future rain as the server-calculated forecast, each with the rain probability; correcting the server calculation is tracked under D45:

| KMA field | Meaning used by the web | Display |
| --- | --- | --- |
| `current.rn1` | Observed 1-hour amount | `N mm · 1시간 관측` |
| `shortest[].rn1` | Approximate 1-hour forecast: the lower bound of a category on the deployed server, a representative amount after #2583 (see below) | `약 N mm`; `1 mm 이하` for 1 (it also covers "1mm 미만"); `30~50 mm` or `50 mm 이상` for the top categories; `· 1시간 예보(근사)` |
| `short[].rn1` (the server fills past and current slots) | Observed 3-hour total; the slot ending after the current observation is still accumulating | `N mm · 3시간 관측`; the in-progress slot shows `N mm · 지금까지 관측` |
| `short[].r06` (rows without a valid `rn1`) and `short[].s06` | Server-calculated 3-hour forecast | `N mm · 3시간 예보`; snow `적설량 N mm · 3시간 예보` |
| `midData.dailyData[].rn1` for yesterday | Observed accumulation | `N mm · 관측 누적` |
| Daily `r06`/`s06` for today and later | Server-calculated daily forecast | `N mm · 예보`; snow `적설량 N mm · 예보` |
| `rn1Str`, `r06Str`, `s06Str` | Retired bucket text | Never shown |

Overseas (VC) data keeps `rn1`, else `r06`, and `sn1`, else `s1d`, else `s06`: current values are 1 hour, hourly rows are labelled 3 hours because the server sums three provider hours, and daily rows 24 hours. Rain and snow display as mm with one decimal (`<0.1` below 0.1) or inches with two decimals (`<0.01` below 0.01); zero snowfall remains in data but is hidden. Rows without an amount show `강수확률 N%`. The help page explains the observed/forecast split and the approximation. The nationwide rain view labels its values as the latest 1-hour observation. An empty nationwide list shows "지역별 관측 자료가 없습니다" instead of rows. The server-side D45 fix is out of scope here.

Server change #2583 (source, not yet deployed) makes `short[].r06`/`s06` 3-hour totals of hourly forecasts, daily `r06`/`s06` day totals, and `shortest[].rn1` a representative amount for a category (0.5 for `1mm 미만`, 40 for `30.0~50.0mm`, 50 for `50.0mm 이상`) instead of its lower bound. `approxAmount` maps those amounts to the same labels as before. New `r06Hours`/`s06Hours`/`r06Approx`/`s06Approx` and `rn1Hours`/`rn1Approx` fields are not read by the web ([amount contract](mobile-api.md#forecast-precipitation-amounts-issue-2583)).

## Display parity

- **Air grades.** `airkorea` and `airkorea_who` use four grades (좋음/보통/나쁨/매우나쁨); `airnow` and `aqicn` use six (좋음/보통/민감군주의/나쁨/매우나쁨/위험), each with the app's grade colors. Grades above the scale clamp to its last grade, missing grades show `정보 없음`, and a provider `<code>Str` label wins. Values show `㎍/㎥` for PM and `ppm` for gases (AQI has no unit); standard names are localized.
- **Air hourly chart.** 24 slots from index−12 to index+11 around the first row at or after the station's `observedAt` (fallback: the last row), with dates on the first bar and at each date change. Rows with a `pubDate`, or dated after the latest observation (the server's AQI forecast rows have no `pubDate`), are forecasts and are drawn distinctly with an observed/forecast legend. The summary card shows up to four AQI forecast points at or after the observation.
- **Stations and attribution.** A pollutant's `<code>StationName` is shown when it differs from the station name. The station picker is hidden when the only station has no name (modeled providers such as `google` report no station). The credit follows the station's `source` (`airCredit` in `web/src/air.ts`): KMA responses whose air has no `source` or `source: "airkorea"` show "대기오염정보: 환경부/한국환경공단" with "인증되지 않은 실시간 자료이므로 자료 오류가 있을 수 있습니다." on the summary card and the air page; air from another provider of the air provider chain ([#2628](https://github.com/WizardFactory/TodayWeather/issues/2628): `google`, `openweather`, `visualcrossing`, `aqicn`), domestic fallback or overseas, shows "대기질 정보: {attribution}" with the API's plain-text `attribution` (else the `source` id) and no AirKorea disclaimer; the air page adds, when `forecastSource` is present, "예보자료: KAQ" or "AIRKOREA" with the matching provider description and forecast publication time. Overseas (`VC`) responses show "해외 날씨 (Visual Crossing)" and a "Weather Data Provided by Visual Crossing" link to https://www.visualcrossing.com/ in the weather page footer. The help page carries the same air source, disclaimer and KAQ description, and says that other countries, and Korea without AirKorea data, use another provider named under the air card. `airStatus: {state: "pending"}` (a request that ended before the air providers answered) is ignored; the next refresh shows the air.
- **Weather details.** The hourly section shows the KMA forecast publication time (`shortPubDate`, "예보 발표", labelled KST) and flags it when it is more than 24 hours old. Details add UV (`ultrvStr (ultrv)` from today's daily row or current; overseas `uvIndex`), discomfort (`dsplsStr (dspls)` when `dspls` > 60) and food poisoning (today's `fsnStr`); wind shows direction and speed, also on the nationwide map. The yesterday difference keeps one decimal in °C and rounds in °F.
- **Dates and icons.** Day labels use 엊그제/그제/어제/오늘/내일/모레/글피 relative to the response's current date, followed by the date; the hourly chart positions points by time, keeps neighbouring points at least 52 SVG units apart so hour labels never touch, and marks midnight. A missing rain probability shows `—`. Icon priority is lightning > rain-snow > rain/shower > snow > cloud with moon > cloud with sun > moon > sun > wind > cloud.
- **Time zones and staleness.** `isOld` in `web/src/format.ts` reads a time without an offset as KST (+09:00) for KMA and AirKorea data and compares its age exactly with the limit; an explicit offset or `Z` is respected, and an unknown format is never flagged. Overseas (`VC`) wall times carry no offset, so they keep a conservative date-only rule: the limit is counted from the latest moment that local date ends anywhere (23:59:59 at UTC−12), so a fresh overseas reading is never flagged, and an old one is flagged later than its exact age would imply. Limits: 3 hours for the current observation ("관측 시각이 오래된 자료입니다…"), air stations and nationwide rows; 24 hours for the forecast publication and warning bulletins. Stamps say which zone applies: KMA/AirKorea times end in " KST", overseas times in " (현지 시각)", and warning instants with an offset are converted to KST.
- **Air links and units.** `/air/:locationId?pollutant=<code>` opens the air page with that pollutant selected (`aqi` otherwise). Nationwide air values show their unit; a missing nationwide weather or air value shows `—` without a unit. The help page has a units section (`/help#units`) listing the unit choices, canonical requests and air units.
- **Phones and Safari.** On touch screens and at ≤ 680 px, form fields use 16px text (iOS Safari zooms into smaller focused fields) and icon controls have a 44px touch area. `color-scheme` follows the theme and selects are drawn by the page, so Safari shows readable dark-theme selects. The body and the fixed sidebar and toast respect `env(safe-area-inset-*)` because `index.html` sets `viewport-fit=cover`. Nationwide map markers use short names ("서울특별시" → "서울") at non-overlapping positions.
- **Warnings.** A bulletin keeps an integer `type`; types 1 and 2 show a `<참고사항>` line. Warning image links permit only the exact KMA hosts and are upgraded to HTTPS. KR warning timestamps carrying an explicit UTC offset or `Z` render in `Asia/Seoul` with a KST label; naive KMA wall times retain their existing meaning.

## PWA and notifications

Root package scope leaves existing Cordova CommonJS tools unchanged; only the web workspaces declare ESM. The development launcher derives Vite host/port from one loopback `WEB_ORIGIN` (default `http://127.0.0.1:5173`), with strict port selection.

`web/public/sw.js` receives a build digest and hashed asset list from `scripts/web-precache.mjs`. Installation precaches the app shell (including `theme.js` when the build has it) and then writes a completion marker; if precaching fails, the new cache is deleted. A new worker waits for an explicit update action. Activation keeps only the newest complete previous shell cache for old tabs (one with the marker, or an older cache that holds `index.html`) and deletes every other previous cache; incomplete caches are also deleted, except while another worker is installing, because that cache may belong to a newer release still being filled. An open app calls `registration.update()` every hour and whenever the page becomes visible again, so a long-open tab still discovers a new release. Unknown routes and all `/api/` requests bypass shell fallback. Install and offline behavior require HTTPS or a local secure-context exception.

Navigation and accessibility: on narrow screens (≤680 px) the sidebar is an off-canvas menu. While it is closed it is `inert`; opening it moves focus to its first item and makes the page behind it `inert`, and Escape, the close button or the backdrop close it and return focus to the menu button, which exposes `aria-expanded`. Widening the window past 680 px closes an open menu. View, pollutant and nationwide mode tabs expose `aria-pressed`, and navigation links rely on `aria-current`. Toasts are announced through a persistent `#toast-region` live region. After a route change focus moves to `main` (not on the first load); when the change came from the open menu, focus moves only after the render that closes the menu and removes `inert`. The in-page weather view tabs navigate with a `keepFocus` state, so focus stays on the pressed tab. History keeps that state, so it is honored only for new navigations: Back/Forward (a `POP` navigation) always moves focus to `main`, also onto an entry a view tab created. There is no mobile bottom navigation.

The notification route explains that browser notifications are unavailable, recommends using the existing mobile app and links back to weather. No store link is provided. It does not request permission, register a push subscription, save a rule or send a test notification. Favorite deletion updates local state and local snapshots without server-side cleanup. Web Push scheduling is a future feature requiring a separate design; native push endpoints and workers are unchanged.

The [static recipe](../../infra/web/static/README.md) prepares hosting only. No web server, notification store, timer, queue, VAPID secret or session cookie is part of the browser deployment. Node is required only by local/CI tooling.

## Verification and release boundaries

The shell digest includes worker, manifest, icons, HTML and asset bytes. Unhashed reads use the current cache; previous caches are consulted only for old hashed assets. The CloudFront navigation function is exercised by the static browser suite. A first service-worker claim does not reload an already usable page; it preserves ongoing interaction. A later controller replacement reloads only the tab that pressed "업데이트" (marked in its `sessionStorage` key `tw.web.v1.update-requested`); other open tabs keep their state, drop their now-stale "새 버전이 준비됐습니다" offer (unless an even newer worker is waiting) and show "새 버전이 적용됐습니다. 새로고침하면 최신 화면을 볼 수 있습니다." with a "새로고침" button. "업데이트" with no waiting worker only hides the offer and sets no reload request, every page load clears a request left from before it, and a controller change consumes the request even in a page that had no controller yet (for example after a hard reload), so a later controller change cannot reload a tab whose user did not choose that update.

For a first-release rollback to a non-PWA placeholder, the operator-only `infra/web/static/recovery-worker.js` is published as `/sw.js`; it is excluded from the normal Vite build. It skips waiting, deletes only `tw-shell-*`, claims app windows, unregisters and navigates same-origin windows to the scope root. It leaves localStorage, IndexedDB and other cache namespaces intact. Keep the recovery script available with `no-cache` for returning clients; offline devices cannot be forced to receive it. The isolated Chromium recovery test covers actual install/offline/recovery in two tabs and a fresh browser. See the [ordered rollback procedure](../../infra/web/static/README.md#first-release-rollback-to-a-placeholder).

Tests exercise the production bundle using only a static file server with the production CSP, intercept raw external API fixtures (a context-level fallback aborts any public API request no test route handles) and reject local `/api/` requests and CSP violations on every page. Domain/storage/transport tests cover normalization, invalid payloads, cancellation, retry, 429/503 handling, local persistence, release identity and each deploy preflight mismatch. A browser-test global setup fails when `web/dist` is older than the web or core sources, `web/vite.config.ts`, `scripts/web-precache.mjs` or a `web/.env*` file. ## Mixed KMA forecast and text-only air fallback

The core adapter merges KMA `short` (three-hour) and `shortest` (one-hour) points into a timestamp-sorted unique timeline, including midnight rollover. Valid nonempty shortest fields take precedence at matching timestamps; missing/sentinel fields retain valid short fields. Rain amounts, durations and their observed/approximate basis are merged together, so a retained three-hour observation is never labelled as a one-hour forecast. Unique shortest points with `rn1=-1` retain null precipitation. Weather views still select current/future points for display.

Optional `Weather.airSummary` preserves only a trimmed string (maximum 500 characters) from `current.summaryAir`. It does not create stations, numbers, grades, air timestamps or availability. When no station is available, both weather and air views show this provider wording with an explicit unverified-observation-time caveat and, for KMA, the air source attribution. React renders it as text. Existing numeric station data remains primary. Snapshot validation rejects malformed/overlong summaries; offline/stale notices remain in force. Nationwide air is not substituted for missing city measurements.
