# Deep-link edge fallback

The [link-host stack](../../infra/deeplink/stack.json) defines a dedicated CloudFront distribution and a versioned private S3 origin. This page describes the repository implementation before production qualification. See the [request sequence](diagrams/deeplink-edge.html) and its [editable source](diagrams/deeplink-edge.json).

The [viewer-request function](../../infra/deeplink/route-request.js) passes only `/.well-known/apple-app-site-association` and `/.well-known/assetlinks.json` through to S3. It returns `302` (`Cache-Control: no-store`) for `/`·`/open` and all recognized content routes, sending browsers directly to the matching route at `app.todayweather.ai`. When `?fallback=store` is present on a recognized route (used by mobile "Open in app" actions and the desktop WebApp QR code), the function redirects iOS and Android User-Agents (`Vary: User-Agent`) directly to App Store or Google Play, falling back to `app.todayweather.ai` for desktop or unknown User-Agents. Unsupported methods (`405`), malformed paths (`400`) and unknown routes (`404`, including removed `/open.html` and `/assets/*`) receive distinct edge responses.

The [operator runbook](../../infra/deeplink/README.md) covers association file generation, deployment checks, smoke testing and rollback. See the [rollout plan](../../plans/deeplink.md) for PWA deployment and native verification.
