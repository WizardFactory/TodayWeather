# server2 operational logging audit

Baseline: master2ded7c9a, 2026-10-17. Implementation status at audit: planned. No common logging API/dependency exists. Existing metrics are useful aggregates, not a cross-task incident trace. The declared scope is `server2/config/tasks/Logging.json`; this audit does not assert deployed logging.

| Subsystem | Evidence (under server2/src/) | Gap | Required implementation |
| --- | --- | --- | --- |
| HTTP/gateway/listener | lib.rs, runtime_services.rs, gateway/mod.rs, listener.rs | No per-request terminal/cancellation identity; socket admission errors silent | Generated request root, safe route/method/status, owned-task inheritance; listener rejection classification |
| Native geocode/world/domestic | geocode/mod.rs; world/{engine,source,air_chain}; domestic/kma/source/* | Shared acquisition owners outlive waiters; unrelated traces cannot identify shared work | Owned-work context with explicit join links; cache/acquire/fallback classifications, no coordinate/key fields |
| Provider/quota | providers/acquisition.rs, providers/transport.rs, world transports, geocode/provider.rs, budget/store.rs | Attempts/rotations exist in counters but lack incident cause/action chain | Classified attempts, funding refusal, existing retry/rotation/fallback decisions; actual attempt numbers |
| S3/catalog/disposable cache | storage/{transport,catalog_transport,store,catalog}; cache/disk.rs | Ambiguous writes and reconciliation outcomes not reconstructable | Read/write/verification/publication outcomes; existing reconciliation/void compensation; cache failure classification |
| History/summary/warnings | history/capture.rs, summary/{recorder,lookup,transport}, warnings/{collector,service} | Detached jobs and derived computation lose triggering context | Inherited/background operation context, restore/lookup/publication events; pure formatting excluded |
| Push registration writer | push/{service,durable}.rs | Command queue has no context; may have committed versus rejected outcomes not logged | Carry originating context in Command, restore/journal/snapshot/reconcile/void outcome classes, no registration IDs |
| Push delivery/notice | push/deliver/{supervisor,alarm,alerts,warnings,fcm,ledger}; notice/* | A few plaintext diagnostics; success/acceptance/durable result distinction absent | Worker cycles/send/OAuth/claim/result stages; accepted is not delivered/confirmed; failed/unknown remain no-retry |
| Startup/shutdown/CLI | main.rs, process.rs, bin/server2-notice.rs | Plaintext start/stop and terminal errors; no common output/filter/drop accounting | NDJSON operational stderr, safe startup failure and drain result; preserve bounded stdout readiness/CLI machine output protocol |

All production tokio task creation and blocking handoffs are inventoried in the local `logging-sites` capture. Logging must not move a deadline, add a retry, change side effects, delay cancellation, change the existing shared-flight owner, or restart a failed/unknown notification. A join records the owner's generated operation ID rather than transferring the owner's trace to the joining caller. Queue context is captured when admitted, not when dequeued.

Exclusions: pure parsers/formatters and per-record/item CPU loops do not emit their inputs or one log per cell; the surrounding bounded stage explains outcomes. Health/metrics polling is debug severity. Legacy runtime remains untouched. Verification example/CLI stdout results and the single bounded `server2 public=… metrics=…` stdout readiness protocol remain for existing callers; operational stderr becomes NDJSON. No raw request/response/URL/provider text, coordinates, credentials, registration IDs or notification text enter the event API. Panic payloads are excluded. Logs are best-effort diagnostics, not a durable delivery ledger.

Verification must cover normal HTTP, async+blocking+queue/shared-owner continuity, injected HTTP failure and retry/fallback, cancellation/unknown side effect, existing journal void/reconciliation, sensitive synthetic values, floods and a stalled/erroring sink, severity filtering and shutdown. Local-only runs cannot establish EC2 retention/collector installation or production performance.
