# Narrative read failures must not become cached absence

Source: [#2819 narrative item](https://github.com/WizardFactory/TodayWeather/issues/2819). AK ordered corrections before seven-day shadow and authorized continuation through pre-merge. The current service flattens a failed stored read into None and caches it for30seconds. One transient timeout therefore suppresses a stored narrative for later callers even after storage recovers. Cache only a completed read's presence or confirmed absence. Preserve the accepted optional deadline: the timed-out request may omit the field, but it must not poison later requests.

AC1: a failed/late/corrupt read does not create a negative cache entry and next demand retries. AC2: confirmed absence and fresh value retain30s cache, office isolation, original deadline/lock and expiry. AC3: actual test-first and owned S3 recovery smoke, exact paths/docs, independent review and current CI. No blanket always-present field guarantee, stale prose fallback, provider acquisition, runtime mode, live sends, deployment or merge.
