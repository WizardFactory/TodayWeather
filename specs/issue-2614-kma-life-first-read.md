# Acceptance for no provider race during the first life read

Tests named `first_read_tests::*` are lib tests (`src/domestic/kma/source/life_first_read_tests.rs`, a child module of `life_input` that reuses the `distinct_tests` doubles); `life_s3::*` and `full_response::*` are in `tests/domestic.rs`. They run over an isolated in-memory S3 on a paused clock, or over the S06 loopback S3 peer, with provider doubles; no provider or AWS is reached.

- **GATE:** with the first read held past the head start, no UV or pollen provider call is made while it runs: for a stored slot (and none after it, the fold holding the slot), for a missing slot whose needed-first fold is already installed at the head start (the interim fold does not end the rule), and for oak pollen in season, stored or missing. On the path without a head start (`load`) nothing is acquired while the read runs; the read waiter stops at its 3 s bound and the request answers then, without waiting for the read again. Checked by `first_read_tests::a_stored_slot_is_asked_neither_during_nor_after_a_slow_first_read`, `first_read_tests::a_missing_slot_is_acquired_by_the_first_request_after_the_first_read`, `first_read_tests::pollen_in_season_waits_for_the_first_read_as_uv_does` and `first_read_tests::the_path_without_a_head_start_acquires_nothing_during_the_first_read`.
- **END:** the rule ends when the first owned read ends, however it ends: a failure after the head start (the request answers when it fails), a failure before it (the request that waited acquires at once), the owner deadline 120 s after the read started with no waiter left, and a panic. A request cancelled before its head start, requests whose waiters stop at their bounds (Pending) at once and a minute later, and a read refused for capacity (Busy) do not end it; after Busy, the first owned read that starts holds the rule until it ends. Checked by `first_read_tests::a_first_read_failing_after_the_head_start_holds_the_race_until_it_fails`, `first_read_tests::a_first_read_failing_before_the_head_start_acquires_as_before`, `first_read_tests::the_first_owned_read_opens_the_race_however_it_ends` and `first_read_tests::the_path_without_a_head_start_acquires_nothing_during_the_first_read`.
- **AFTER:** once the first read has ended, requests decide as before. The first request after it acquires a missing slot or pollen issuance, and a later read that misses the head start is raced as before, with the UV call at the head start: after a committed first read with the memo expired, as the second attempt after a failed first read (never committed), and after the owner deadline. Checked by `first_read_tests::a_missing_slot_is_acquired_by_the_first_request_after_the_first_read`, `first_read_tests::a_later_read_missing_the_head_start_is_raced_as_before`, `first_read_tests::a_first_read_failing_after_the_head_start_holds_the_race_until_it_fails`, `first_read_tests::pollen_in_season_waits_for_the_first_read_as_uv_does` and `first_read_tests::the_first_owned_read_opens_the_race_however_it_ends`.
- **REGRESSION (T9):** `life_s3::a_restart_over_identical_uv_acquisitions_reads_before_the_head_start` (KMA-LIFE-DISTINCT) is unchanged. Its forced-slow variant, every LIST taking 1 s, asks no UV during or after the first read and answers today's UV from it: `life_s3::a_slow_restart_over_identical_uv_acquisitions_asks_no_uv`. The slow life read test of KMA-RESTART-RACE, renamed from `a_slow_life_read_starts_uv_at_the_head_start` (the name in the [restart-race spec](issue-2614-kma-restart-race.md)) to `life_s3::a_slow_first_life_read_starts_no_uv_or_pollen`, now expects no UV or pollen call and no UV or weeds on the first answer, while food poisoning still races. The whole-answer test `full_response::a_slow_restart_answers_every_stored_family_first` now expects food poisoning as the only raced life dataset and no `current.ultrv` on the first answer.
- **KEPT GUARDS:** `life_s3::the_needed_first_read_lists_the_life_families_together` also asserts that the request answers before the head start: a slow first read no longer starts the UV acquisition its "no UV asked" check relied on. `distinct_tests::an_identical_acquisition_is_not_published_and_answers_at_once` makes its first read through the owned read (`LifeInputs::read_life`), as requests do, instead of the bare read function. The other KMA-LIFE-DISTINCT lib tests are unchanged.
- **MUTATIONS:** each temporary change is caught: the flag set after the read's await instead of by the guard (the panic case of `the_first_owned_read_opens_the_race_however_it_ends`), the rule ending at the first commit (the failing-read and owner-deadline cases), the rule for raced requests only (the path without a head start), waiter outcomes ending the rule (Pending a minute later, Busy), no race for later reads (the later-read, failing-read and owner-deadline cases), the interim fold ending the rule (`a_missing_slot_is_acquired_by_the_first_request_after_the_first_read`), no rule at all, and the four families listed one after another (the NEEDED-FIRST test's bound).
- **PLACEMENT:** the placement gate passes against `server2/config/tasks/KMA-LIFE-FIRST-READ.json` (base: master), and the artifact policy passes on the outgoing commits.

Failure paths: a first read that fails, reaches its owner deadline or panics ends the rule, so the provider path resumes at the next request's decision; a read refused for capacity starts no owned task and no 120 s bound until an owned read starts.
