# Forecast coverage specification
Input: [intent](../intent/issue-2676.md). Scope: legacy server only.

A forecast coordinator per Manager/product snapshots requested publication strings and owns a bounded run. Same-publication callers join; another publication receives busy until completion/deadline. Coordinate and DB reads have three-second wait bounds and maxTimeMS:2000. Read failure terminates without unchecked HTTP. Nine-minute forecast deadline cancels collector/retry admission; late callbacks are ignored and cannot clear a newer run. Already issued Mongo operations may settle; no new write is admitted after expiry.

Coverage uses exact top-level publication (DB1 string / DB2 UTC BSON) and coordinate. Short expected slots start the hour after base and run hourly through +2 days for early publications, +3 for17/20/23, then the final day at00/03/06/09/12/15/18/21. Ultra-short is the next six hourly slots. Short requires TMP/SKY/REH/PTY/POP/PCP/SNO and wind fields in each slot; TMN06/TMX15 only when that publication supplies them. Ultra-short requires T1H/SKY/REH/PTY/RN1/wind/LGT; POP is required for publications at/after202606231100. WAV is conditional and not a completion requirement. Finite zero and signed temperature/wind/lightning remain valid; schema sentinels and provider +/-900 missing values are incomplete. Extension-day precipitation/wind codes remain existing numeric storage; no API conversion changes.

All parsed rows must match requested publication and coordinate. Validate the complete batch before writer admission so incomplete provider horizons/categories do not relabel older data. DB1 controlled writes fully replace overlapping requested forecast slots rather than merging missing fields from old publications, preserving outside slots and retention limits. DB2 continues existing per-slot upserts. Both writer paths stop new save/update admission after cancellation, retain the original publication, and propagate write errors. Coverage is read back after collection including error outcomes; errors never produce successful completion. Persisted complete grids are skipped after coordinator recreation without process coverage caches or schema markers. DB1 coverage cannot reconstruct per-field provenance for pre-existing legacy arrays; newly admitted forecast batches are validated before relabeling.

Keep #2604 concurrency, retry ceilings, rotation and rejection logic. Actual onPageRequest attempts accumulate in run control across passes/pages; sanitized coverage/result records contain product, publication, expected/complete/pending and attempts. No shared quota cooldown extension to these products.

No schema migration, deployment or backfill. Rollback reverts code; existing documents remain readable. Tests use synthetic full-grid adapters and real loopback HTTP/temporary Mongo4.4 with Node16/Mongoose5.1.2. Production readback remains separately gated. Reject document-exists and >=publication shortcuts: neither proves exact complete forecasts.
