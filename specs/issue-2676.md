# Forecast coverage specification
Input: [intent](../intent/issue-2676.md). Scope: legacy server only.

A forecast coordinator per Manager/product snapshots requested publication strings and owns a bounded run. Same-publication callers join; another publication receives busy until completion/deadline. Coordinate and DB reads wait `GATHER_FORECAST_READ_TIMEOUT_MS` (default three seconds) with maxTimeMS one second shorter; coverage records report read duration and read failure. Read failure terminates without unchecked HTTP. Nine-minute forecast deadline cancels collector/retry admission; late callbacks are ignored and cannot clear a newer run. Already issued Mongo operations may settle; no new write is admitted after expiry, and controlled writes are publication-fenced so a settling older write cannot replace a newer publication (DB2 `pubDate <= own` update with absent-slot `$setOnInsert`; DB1 compare-and-set on the read `pubDate`, refusing downgrades). Ultra-short publications are updated by KMA every ten minutes: per AK (2026-10-04) each process performs one full refresh walk per current ultra-short publication from `GATHER_SHORTEST_REFRESH_AFTER_MS` (default base+40min) within a one-hour window; `0` disables it.

Coverage uses exact top-level publication (DB1 string / DB2 UTC BSON) and coordinate. Short expected slots start the hour after base and run hourly through +2 days for early publications, +3 for 17/20/23, then the final day at 00/03/06/09/12/15/18/21. Ultra-short is the next six hourly slots. Short requires TMP/SKY/REH/PTY/POP/PCP/SNO and wind fields in each slot; TMN06/TMX15 only when that publication supplies them. Ultra-short requires T1H/SKY/REH/PTY/RN1/wind/LGT; POP is required for publications at/after 202606231100. WAV is conditional and not a completion requirement. Finite zero and signed temperature/wind/lightning remain valid; schema sentinels and provider +/-900 missing values are incomplete. Extension-day precipitation/wind codes remain existing numeric storage; no API conversion changes.

All parsed rows must match requested publication and coordinate. Rows outside the expected horizon are dropped before writes, except a valid row within one day after the final expected slot (production counts show one extra slot); each expected slot appears once. Validate the complete batch before writer admission so incomplete provider horizons/categories do not relabel older data. DB1 controlled writes replace required fields of overlapping requested slots rather than merging them from old publications, keep only conditionally absent same-day TMN/TMX and optional WAV, and preserve outside slots and retention limits. DB2 keeps per-slot documents with the publication fence above. Both writer paths stop new save/update admission after cancellation, retain the original publication, and propagate write errors. Coverage is read back after collection including error outcomes; errors never produce successful completion. Persisted complete grids are skipped after coordinator recreation without process coverage caches or schema markers, except the AC1 amendment: one scheduled ultra-short refresh walk per current publication per process. DB1 coverage cannot reconstruct per-field provenance for pre-existing legacy arrays, and DB2 cannot tell schema defaults (ultra-short `lgt=-1`) from received values; such legacy rows are trusted only for the publication current at deployment, and newly admitted forecast batches are validated before relabeling.

Keep #2604 concurrency, retry ceilings, rotation and rejection logic. Actual onPageRequest attempts accumulate in run control across passes/pages; sanitized coverage/result records contain product, publication, expected/complete/pending and attempts. No shared quota cooldown extension to these products.

No schema migration, deployment or backfill. Rollback reverts code; existing documents remain readable. Tests use synthetic full-grid adapters and real loopback HTTP/temporary Mongo4.4 with Node16/Mongoose5.1.2. Production readback remains separately gated. Reject document-exists and >=publication shortcuts: neither proves exact complete forecasts.
