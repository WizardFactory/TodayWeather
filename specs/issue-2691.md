# S06 specification: bounded complete S3 acquisitions

Owner /root/s05_raw_records; 2026-10-07; consumes [intent](../intent/issue-2691.md) and baseline `4864c9368e78061fbc65b57ac0abaaa3b9408eff`. Root owns the validated publication sequence and shared architecture; this is an internal storage feature, no route or AWS deployment.

## Canonical identity schema (AC1)

`CatalogId {source, kind, key_sha256, partition}` validates existing source/kind/key identity plus a bounded ASCII partition token. Its direct key is `index/v2/{source}/{kind}/{key_sha256}/{partition}.json`. The partition is caller-defined schedule/date/month/warning-type identity, never user coordinates. Provider keys preserve S05 upstream coarse-grid contracts.

`Catalog {schema:1, identity:CatalogId, generation:u64, entries:[Envelope]}` stores identities and provider envelope metadata only, no normalized or merged weather. Entries retain every revision, sorted by `(fetched_at_ms, raw_sha256, canonical identity)`; exact same identity with a different envelope is corrupt, never overwritten. Generation is checked on decode, bounded overflow fails. Canonical JSON is compact serde struct field order; arbitrary normalized bodies are not legal catalog fields (`deny_unknown_fields`). Catalog updates are union-only.

`GroupDeclaration {schema:1, partitions:[CatalogId], members:[GroupMember]}` contains the sorted unique full partition list and ordered members. Each `GroupMember {envelope:Envelope, catalogs:[CatalogId]}` declares its complete sorted unique partition ownership. The envelope has `fetch_group:None` in the declaration. Members are one source/kind/key acquisition; distinct identities remain distinct; nonempty ownership matches member namespace. All expected partitions must be represented exactly by the member ownership union.

Group SHA256 hashes the complete canonical declaration. Member SHA256 hashes the canonical ordered members, partition SHA256 hashes the canonical sorted partition list. Thus no self-reference exists. Descriptor key is `index/v2/groups/{group_sha256}.json`. Descriptor is immutable, conditional-create with Content-MD5, and exact bytes/hash validated on existing412 and read. Each raw envelope receives the resulting S05 `FetchGroupRef` before raw PUT. Raw metadata/ref and descriptor/envelope must agree at load.

Paged acquisitions require each page1..N exactly once in order, same declared N, all complete=true, no unexpected/duplicate/missing pages. Unpaged groups remain ordered by revision identity. No mixed paged/unpaged groups. A previously ungrouped or differently affiliated raw identity cannot be reassigned: fail safely on immutable metadata mismatch. Standalone ungrouped records can be discovered/read only when pagination is absent; an ungrouped paginated body never proves a complete acquisition.

## Publication, CAS and pinned read (AC1, AC3)

`CatalogTransport: ObjectTransport` adds bounded control JSON GET/conditional PUT and ListObjectsV2. Control reads preserve opaque ETag and optional version ID; ETag is only an If-Match token, never a raw integrity hash. No secret/signed URL diagnostics or credential auto-discovery. Existing HttpS3Transport signs real conditional headers/Content-MD5 and reuses coherent refreshable credentials; loopback peer does not establish AWS signature validity.

Publish: validate/prepare declaration and immutable descriptor → descriptor create/reconcile → every raw PUT → CAS union each partition → pin all siblings → verify descriptor, exact member/page/digest/catalog ownership and bounded raw loads → checked complete group result. Successful raw PUT alone is not successful group/client publication. Cancellation after A/new and before B leaves raw/A durable but unreadable as the new group; old complete groups remain eligible.

CAS is bounded read/union/IfMatch (or IfNoneMatch on404), completed PUT200 only.412/409 re-read/union without dropping concurrent revisions. Unknown transport/5xx/timeouts retain cumulative uncertainty; later rejection cannot erase a prior possible commit. Reconcile actual current catalog containing expected union; no extra provider fetch/new raw identity. Corrupt/Invalid remain fail-closed. First direct definitive PUT rejection retains its status. Whole deadline/caps prevent infinite conflict loops.

Reads pin every required sibling catalog exactly once per operation, retaining identity/generation/opaqueETag/version dependency tokens for S07. A descriptor group is eligible only when all declared members are present in the required siblings and raw metadata/bytes validate. A healthy B with only old entries cannot complete A/new. Incomplete groups are excluded from reads/packs/summaries. Valid older groups may still be returned with an explicit excluded-group count.

`LookupOutcome::Ready(CompleteSet)` is a checked nonempty eligible set with pinned dependencies. `LookupOutcome::Incomplete` cannot be treated as provider miss. Missing/empty/healthy catalog reads alone never return a proof of empty coverage. A complete empty result is available only from the repair API's fully scanned explicit candidate scope. CompleteSet fields are private/validated; consumer access is read-only.

## Full bounded repair (AC2)

Caller supplies `RepairScope {catalog, periods:[Period]}` covering the provider resolution's candidate periods; completeness is scoped to this supplied finite set, not the entire archive. Validate prefix identities and candidate count. Repair runs even when the target catalog looks healthy: LIST every relevant canonical raw prefix, follow opaque tokens until IsTruncated=false, then bounded GET/hash/envelope validation. Scope key/source/kind/date/slot/fullhash is recomputed; wrong-key/raw-hash objects are ignored as corrupt and prevent claiming complete empty coverage.

For grouped raw, GET/verify descriptor and the complete members/ownership set, including sibling members outside the scanned target period; only fully checked groups are repaired into every required catalog by CAS. Ungrouped unpaged singleton revisions repair directly. Descriptor orphan with missing body, unavailable sibling, corrupt object, repeated/missing continuation token, malformedXML, timeout or any count/byte cap yields `RepairOutcome::Incomplete`, never complete-empty. Successful fully scanned scope with no candidates yields `RepairOutcome::CompleteEmpty {scope}`; a nonempty restored checked set yields `Complete`. An exhausted, nonempty verified scan with successful identity-index unions but whole-history materialization Capacity yields `Indexed {scope, dependencies}`. Indexed is not a serving CompleteSet, not empty and not provider admission; readers obtain bounded checked pages afterward. Repair does not invent responses or authorize provider HTTP itself.

## Derived policies and resource bounds (AC1–AC3)

All complete acquisitions are ordered deterministically by `(fetched_at_ms, raw_sha256)` with full canonical identity tie-breaks; pages stay ordered. Immutable policy selects earliest whole acquisition; revisable policy selects latest; absent-only field merge fills only absent top-level properties (present null/zero/false remain); list replacement replaces the whole list with the latest parsed acquisition. Parsing is caller-supplied and memory-only; provider parsers/response caches are S07/later route scope.

Defaults: control JSON/XML <=1MiB, catalog entries<=2048, group members<=128, partition/prefix candidates<=16, LIST pages<=8 per prefix and total raw candidates<=2048, maxkeys<=1000, CAS attempts<=4, operation-wide retained control bytes<=8MiB and decoded raw output<=32MiB. Limit setters are validated with hard ceilings. Saturation/overflow fails safely. Global RSS is not claimed: caller input/results and other stores/concurrent operations also consume memory.

The caller passes an absolute monotonic deadline; it is capped by the configured <=3s default (<=9s hard ceiling). One outer timeout covers credential waits, descriptor/raw/catalog/siblings/repair and retries, not a fresh three seconds per object. Bounded I/O admission spans retained control buffers until bounded spawn_blocking parsing; CPU permits remain owned by started workers after cancellation. Raw gzip work reuses S05 bounded store permits. S06 does not implement single-flight ownership/caches/reservations.

## Corrective read contract (actual review S06-R1–R7)

Archival union retains every revision. Normal retained-history capacity exhaustion is `Error::Capacity`, never corruption. Full `lookup` and its `CompleteSet::fold` continue to require the entire eligible revision set; Capacity/Timeout cannot be interpreted as an empty provider miss. Only this complete-history API can fold absent fields over all history.

`lookup_page(id, order, cursor, maximum_acquisitions, deadline)` returns `PageOutcome::Ready(CompletePage)` or `Incomplete`. The private page exposes checked whole acquisitions, pinned dependencies, exclusion count and an optional opaque private continuation, but no fold method. `ReadOrder` is EarliestFirst or LatestFirst. Before pagination, verified descriptor metadata establishes each unique acquisition's representative: its ordered first expected envelope, including a first member owned by a different partition. Standalone records use their own envelope. Representatives sort by exactly the FullHistory identity_order tuple; direction and whole-group cursor offsets apply afterward. Every target catalog entry must match the complete descriptor envelope/reference/ownership before deduplicating group materialization. A page loads raw bodies and sibling pins only for selected acquisitions; metadata normalization still scans all target group descriptors under the control-byte and caller deadline bounds. Every old revision remains accessible via continuation; no pruning or normalized persisted projection is added.

The private cursor binds the CatalogId, target generation/opaque ETag/version, direction, canonical acquisition offset, visited group IDs and prior sibling dependency tokens. Continuation validates the target and all prior tokens before reading another page; drift returns Incomplete/restart, cross-ID/direction misuse is Invalid. Retained current-page pins/output remain bounded; prior token checks are ephemeral. Cursor size is bounded by the configured retained control-byte cap. Consumers must never fold one page as all-history, must collect every page under unchanged tokens and revalidate before serving a cross-page historical fold, or use safe fallback when total deadline/capacity prevents it. A page or Indexed result never establishes absence.

Before any descriptor/raw/catalog PUT, publication validates the complete new group's raw total, descriptor and minimum required catalog/control/pin bounds; an inadmissible group returns Capacity with zero PUTs. After catalog union, verify only the newly declared group with fresh pinned siblings and exact raw metadata, then return a checked set scoped to that new group. This return value is not the partition's full-history set. Unknown-write handling and no overwrite remain unchanged. Catalog entry/document ceilings still reject rather than silently prune; a caller must design schedule partitioning under these explicit limits.

Repair stores discovered verified envelopes, not bodies; each bounded raw body is discarded before full-group reload and retained-output accounting is reset after discarded acquisitions. Every revision is still scanned/hash checked/indexed. `Indexed` distinguishes successful archive index reconstruction from a serving-history result. The caller must map each supplied period to the target partition deterministically; foreign-owned grouped records are incomplete and ungrouped rows rely on this ownership assertion. This is not a complete geocode layout/expiry contract.

Control JSON/XML Content-Length is optional; malformed/duplicate headers fail. Stream chunks stay bounded, declared length must match when present. Empty truncated LIST pages follow a valid token under existing page/token-cycle caps. Empty-discovery corrupt-only/wrong-key/catalog-listed-missing-body outcomes require explicit wire regressions and never CompleteEmpty. Strict corruption failure remains selected policy (R4 recommendation not selected).

Targeted escape hatch: `lookup_acquisition(id, member_identity, deadline)` verifies that exact member's target catalog membership, then loads only its complete immutable group and required siblings. It returns a private page with `RevisionCoverage::Targeted` and no continuation, not exhausted history. `CompletePage` identifies Paged vs Targeted coverage and has no fold. This keeps any old/new acquisition obtainable even if prior cursor dependency growth makes a coherent full-history traversal exceed its deadline/metadata budget. Such traversal still safely fails Capacity/Timeout, not global corruption or provider miss.

`CompleteSet` coverage distinguishes `FullHistory` from `PublishedGroup`. Full partition lookup constructs only FullHistory; publication constructs only PublishedGroup. Its public fold method rejects any non-FullHistory coverage, including an absent-field merge on just the published acquisition. Consumers parse explicit scoped acquisitions directly when that is the desired operation. Publication does not purport to return every earlier revision.

## External review corrective contract (S06-H1/H2)

Same-fetch full-hash ties and differing page fetch times must produce exactly the FullHistory acquisition order across paginated EarliestFirst/LatestFirst results and cursor boundaries. No raw-member min/max shortcut defines a paged acquisition representative. Descriptor normalization is metadata-only but requires upfront GETs and can reach Capacity/Timeout on mature partitions; lookup_acquisition remains the exact bounded escape. A page never promises three GETs independent of history. No descriptor/member/page schemas or persisted normalized values change.

Repair caches bounded verified descriptors and expected envelopes while checking every discovered raw envelope, including additional rows claiming an already visited group. Compare the full FetchGroupRef and full expected envelope, exact member identity and target ownership before deduplicating full-group body reads/catalog CAS. Any undeclared/mismatched/foreign affiliation yields Incomplete, never Complete, Indexed or CompleteEmpty. Cache retention is charged by existing serialized control/deadline bounds; no new unbounded metadata/RSS promise.

## Mixed-scope repair progress (actual review S06-R11)

An invalid discovery marks the explicit scope Incomplete without blocking unrelated independently verified complete orphan groups. Cache descriptor metadata separately from eligibility: a group is eligible for body verification/CAS only after at least one discovered envelope exactly matches its expected descriptor member and target ownership. Every discovered envelope still undergoes the full H2 comparison before deduplication. A foreign/mismatched-only claim cannot authorize group publication.

A valid declared member and an additional false claim may reference the same group; only descriptor-declared expected members are reloaded and verified, never the stray. Fully verified eligible groups may be union-indexed even when other discoveries were invalid. After bounded repairs the scope still returns Incomplete, never Complete, Indexed or CompleteEmpty. Indexing a safe acquisition does not prove complete scope coverage or authorize a provider miss. Missing/corrupt required group bodies remain unindexed; deadline/operation bounds and uncertain-write errors remain unchanged.

Wire regressions require valid orphan plus corrupt raw, ungrouped paginated raw, foreign-owner group, and undeclared/changed-reference claims in the same prefix: mixed repair Incomplete; fresh targeted lookup of the valid acquisition succeeds with every expected page only. Foreign-only group's catalogs receive zero repair PUTs. Distinct maintained release smoke demonstrates the mixed repair and exact targeted recovery.
