# Spec: Android tab-switch jank

Consumes [intent](../intent/android-tab-switch-jank.md) and the task investigation (simpleperf of tab switches on the R8 release).

## Shared decoded images

1. Every asset image that the app's screens decode through `ChartImages` (theme weather and icon images, the attribution image, the national map and its labels) comes from one cache per activity, shared by all tabs and visits: the existing `ForecastChartImages`, provided at the app root instead of only inside forecast tabs.
2. An asset path is opened and decoded at most once while its entry stays in the cache. A missing asset is remembered as missing, as today.
3. The cache is bounded by decoded bytes: 1/16 of the app's memory class, at least 4 MiB and at most 16 MiB. Eviction only means a later decode; nothing else changes.
4. Images, sizes, positions and filtering are unchanged; screenshot and parity references stay valid.

## App baseline profile

5. The release build packages an app baseline profile (`assets/dexopt/baseline.prof`) that covers cold start and visits to Hourly, Daily, AQI and Locations with one saved place, merged with the libraries' profiles.
6. The profile is generated by a Macrobenchmark `BaselineProfileRule` journey in a new `:baselineprofile` module on a connected emulator or device, and the generated rules are committed in the app's sources. Generation needs a device and network (production weather), so it runs manually, not in PR CI; PR CI only builds the module.
7. The app's semantics expose test tags as resource IDs (`testTagsAsResourceId`) so the journey can find tabs and start-page controls in any locale. Nothing visible changes.

## Non-goals

Keeping tab pages composed between visits, changing AdMob behaviour, image downsampling.
