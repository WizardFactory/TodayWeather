# Contract: supported collection and nationwide fallback
Inputs: intent/issue-2636.md and investigation at base 39a3336. Status: scoped implementation specification.

## Collection
Use HTTPS B552584 observation/statistics service routes for existing station/sido methods. Normalize raw or percent-encoded service keys once, encode once, never log keys/URLs/bodies. Select one configured key per operation; do not rotate through keys to bypass quota. Supported JSON success is response.header.resultCode 00 with body.items array and consistent nonnegative integer pagination. Reject empty/incomplete/malformed batches before writes. Fetch all pages within a bounded page/row budget, retaining requested sido in the internal compatibility envelope `{list, parm:{sidoName}}`.

Each HTTP attempt has a whole-attempt deadline, byte limit, no redirects and at most one transient retry (timeout/reset/5xx). Authentication, quota and schema errors terminate without retry. Preserve existing legacy helper behavior outside observation methods, but remove shared secret logging. Eliminate observation outer retry multiplication. Bound overlapping scheduled runs per process and log sanitized UTC started/completed/failure timestamps with operation, province, counts and stable codes. Station save and province aggregate acknowledgement must both precede success.

Validate identity and KST observation time (including 24:00), accept only finite nonnegative concentrations, grades 1–4, and omit provider missing/invalid fields. Invalid identities/times reject the batch. A row with no usable concentration is unavailable, not a valid write. Reject no-usable-data batches. Keep original dataTime and schema fields, grade mapping, and UTC Date representing that KST instant. Province aggregation uses latest urban-station time; no fallback write to AirKorea stores. No DB version change.

## Nation response (user amendment)
For each of the 17 map names, prefer latest usable AirKorea aggregate with valid observation age under eight hours (and no excessive future time). If absent, stale, invalid, or its DB read fails, query `airFallback.getArpltn` using a fixed documented representative city coordinate. The resulting point observation is labelled `source`, `attribution`, `coverage: representative-point`, `representativeCity` and coordinates; it is not described as a province mean. Keep legacy `sidoName`, empty `cityName`, dataTime and concentration fields and recalculate grades using existing airUnit conversion. Valid AirKorea receives `source: airkorea`, `coverage: province-average` in the nation response only.

Run at most four fallback calls concurrently under one `AIR_RESPONSE_DEADLINE_MS` response budget, covering DB lookup and fallback. Do not start new calls after expiry. Late existing calls may populate shared cache, but cannot modify returned data. Preserve successful air rows and weather when another province fails. Add `airStatus` with per-province availability/source/reason, distinguishing missing, stale, DB read errors and fallback failure/deadline. No new quota/provider logic or per-request collection writes.

## Verification and operations
Test fixtures cover URL/key escaping, service envelope, multi-page completeness, auth/XML gateway errors, malformed/empty/invalid rows, missing pollutants, KST/24:00/timezone independence, timeout/late callback, retry bound and sanitization, DB/aggregate error acknowledgement; nation preference/partial/stale/error/timeout, source and chosen unit. Additional local smoke uses real loopback HTTP, local Mongo, actual collection/parser/aggregate/nation middleware and shared fallback chain/cache, synthetic providers only. Production entitlement, scheduled readback and physical device checks remain a separately authorized runbook.

Rejected alternatives: hostname-only change (wrong contract), key cycling (quota bypass), serial unbounded nation calls, storing point fallback as province AirKorea average, synthetic zero values or claiming HTTP 200 proves recovery.
