# Acceptance for client validation

Tests are in `server2/tools/verification/test_kma_client_validation.py`.

- **CAPTURE:** `kma_client_validation.py capture` sends one GET with `Accept-Language: ko-KR,ko;q=0.9`, with no retry and no redirect, and writes the body as received and a metadata file (URL, UTC send time, status, duration, size, `date`, `age`, `x-cache`, `cache-control`, `x-amz-cf-pop`). Only HTTP 200 with a JSON object body exits 0; a non-200, non-JSON or failed answer exits 1 and is still recorded. Checked against a loopback HTTP server; tests never reach production. Checked by `CaptureTest`: `test_capture_writes_the_body_and_metadata_of_one_get`, `test_capture_without_a_label_names_both_files_after_the_path`, `test_error_answers_are_recorded_with_exit_one_and_no_second_request`, `test_a_refused_connection_is_recorded_with_exit_one`.
- **COMPARE:** `kma_client_validation.py compare --reference <file> --candidate <file>` matches `short` and `shortest` rows by `date` and `time`, `midData.dailyData` rows by `date`, other object arrays by index and objects by key; rows and fields only the candidate has are allowed. It lists every reference row the candidate lacks, every reference field the candidate lacks, and every value that is valid in the reference and invalid in the candidate (absent, null, an empty or blank string where the reference has a value, an empty scalar list where the reference list is not empty, a value of another kind (an object or array where the reference has a scalar, or the reverse; a boolean where the reference has a number or string, or the reverse; a number where the reference has text that is not a number), a string that is not a number where the reference is a number (a number and a numeric string are the same data), a temperature at or below -50, where the temperatures are `t1h`, `t3h`, `tmx`, `tmn`, `t1d`, `taMin`, `taMax`, `sensorytem`, `sensoryTem`, `dpt` and `heatIndex`, a wind component `uuu` or `vvv` at or below -100, or a negative number in a field that is never negative, which is every other numeric field except `fromToday`). Numeric strings, which legacy also sends (for example `reh` and `wsd` in short rows of the recorded `current-interpolated-strings` case), are read as JavaScript's `Number()` reads a decimal string, and the same rules apply to them. A number that reads as infinite, as a string (`"1e309"`) or as a JSON number that overflows (`1e309`), is invalid, and `"NaN"` is not a number. A reference value that is itself invalid requires nothing of the candidate. Valid values that differ are information only. It exits 0 with nothing missing, 1 with missing data, and 2 when the bodies are not comparable (another or unknown place, that is a `regionName`, `cityName` or `townName` that differs or is absent, null or blank in either body; different `currentPubDate`, `shortestPubDate`, `shortPubDate`, `midData.landPubDate` or `midData.tempPubDate`; not a KMA body; or unreadable); the differing place and publication fields are reported and the lists are written in every case. Checked by `CompareTest`: `test_identical_bodies_pass`, `test_missing_field_is_reported_by_path`, `test_missing_rows_are_reported_once_by_key`, `test_rows_match_by_key_and_extra_candidate_rows_pass`, `test_other_object_arrays_match_by_index`, `test_sentinels_null_and_empty_values_against_valid_reference_values_are_reported`, `test_empty_or_other_kind_values_against_valid_scalars_are_reported` (CV-empty-numeric), `test_scalars_of_another_kind_are_reported` (CV-scalar-kind), `test_non_finite_numbers_are_reported` (CV-nonfinite-number), `test_both_invalid_is_not_reported`, `test_signed_fields_may_be_negative`, `test_valid_value_differences_are_information`, `test_different_publications_are_not_comparable_but_lists_are_written`, `test_different_place_is_not_comparable_but_lists_are_written`, `test_place_absent_from_both_bodies_is_not_comparable` (CV-missing-place), `test_non_kma_or_unreadable_input_is_not_comparable`; and by `RecordedBodiesTest` on the recorded legacy bodies: `test_every_recorded_kma_body_passes_against_itself`, `test_rows_and_fields_removed_from_a_recorded_body_are_reported`, `test_numeric_strings_follow_the_sentinel_rules` (CV-string-sentinel), `test_heat_index_is_a_temperature_and_other_indices_stay_never_negative` (CV-negative-heat-index), `test_wind_components_use_the_legacy_missing_value`.
- **EXCLUDED:** the parts named in the intent are never counted as missing. One that has data in the reference is listed under its own key when the candidate lacks it, leaves it invalid or keeps it as an empty object or array. Fields only the candidate has (for example `forecastNarrative`, `freezeGrade`) are allowed. Attribution and `historyStatus` gap lists are not judged; a label or grade is judged only when its value field is equal, and otherwise listed as value-dependent when the candidate lacks it. Checked by `CompareTest`: `test_exclusions_are_listed_but_never_missing`, `test_excluded_parts_kept_empty_are_listed` (CV-empty-excluded), `test_attribution_and_history_gap_lists_are_not_judged`, `test_candidate_only_keys_pass`, `test_label_is_judged_when_its_value_field_is_equal`, `test_label_follows_a_differing_or_absent_value_field`.
- **DOCUMENTS:** `docs/architecture/mobile-api.md`, `docs/architecture/server2-kma-data-design.md` and `docs/evidence/research/kma-speed-options-2026-11-04.md` describe the two tools as above; dated evidence keeps its original text with a dated note. `docs/architecture/server2.md` has no section on KMA verification tools and stays unchanged.
- **PLACEMENT:** the placement gate passes against `server2/config/tasks/KMA-CLIENT-VALIDATION.json`, and the artifact policy passes on outgoing commits. `server2/tools/ci.py` runs the tests; its `run_isolated.py 'test_*.py'` selection discovers only `server2/deploy/benchmark`.

Classification evidence, from the legacy source at `0ed2eaa4` and the recorded bodies of the client wire contract: legacy writes -50 for a missing temperature, -100 for a missing `uuu` or `vvv` and -1 for any other field (`server/controllers/controllerTown.js:4679-4687`, the empty time table at `:5045-5051`, `_makeCurrent` at `:3510`, current defaults at `:3294` and `:3297`). `getHeatIndex` returns -1 only for invalid inputs and the temperature itself below 80 °F (`server/controllers/lifeIndexKmaController.js:528`, `:547`), and `sensorytem` is a wind chill or the temperature (`controllerTown.js:5141`, `:3075`, `:3118`). Both are read as temperatures: the recordings carry real negatives (`heatIndex` -14, -12.5, -11 and -1.2 in the `kma-town.json.gz` winter and snow cases, `sensorytem` down to -26). A `heatIndex` of -1 is also a valid -1.0 °C, so it is not treated as missing; its inputs `t1h`/`t3h` and `reh` are judged. `dspls` and `decpsn` return -1 for invalid inputs, legacy grades a negative discomfort index as invalid and clamps the decomposition index at 0 (`lifeIndexKmaController.js:419`, `:436`, `:478`, `:483`), and `frostGrade` and `freezeGrade` run from 0 to 2 and 0 to 3 (`:586`, `:613`); these stay never negative. In the 302 recorded object bodies every other negative value is such a missing value (-1, or -2.2 for `wsd`, in rows whose other fields are missing too), apart from `fromToday` and real wind components; `uuu` and `vvv` also show -1 in those rows, but -1 is a real component, so only -100 counts as missing.

Failure paths: a reference that is not a KMA body, an HTTP error capture or an unreadable file is not comparable (exit 2). A candidate row present with every field but invalid values is reported per value, not as a missing row.
