# Stored narrative cache outcome contract

`narrative::Read` remains Option-valued for the caller. `Service::read` holds the existing per-office lock within the original absolute deadline. An unexpired cached value is served only while its Narrative remains fresh; verified cached absence stays absent until the existing30s TTL. On a cache miss, observe the existing Store::read Result. Only Ok(Some(fresh value)) or Ok(None) may install a new cache entry. Err—including timeout, malformed/corrupt data, capacity or transport—returns None for this request without installing or replacing cache state. A later request can retry immediately with its own deadline. No new background retry, timer, config flag, S3/schema change or cross-office cache is introduced.

The Store already bounds the whole read with timeout_at and validates raw/catalog identity. Preserve those bounds and diagnostics. A cancelled caller cannot install a negative result. An expired previous entry remains expired after failure and is not served stale; this does not add stale-on-error behavior. The optional request may omit narrative under accepted latency rules. True absent results still cache, preventing repeated empty S3 scans.

AC1: failing/late read followed by immediately recovered data/confirmed absence re-enters storage; no30s failure poison. AC2: successful value, true absence, expiry and office isolation unchanged. AC3: intended before-fix failure, tests and actual owned-S3 publication/readback through public service, no live providers/keys, exact path and pre-merge review/CI records. Nation fan-out optimization is outside this increment.
