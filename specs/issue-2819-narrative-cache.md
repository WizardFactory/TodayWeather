# Stored narrative cache outcome contract

`narrative::Read` remains Option-valued. The existing per-office mutex holds separate confirmed answer and completed-error retry-after state. An unexpired answer serves only fresh narrative or confirmed absence, unchanged30s TTL. On cache miss, an unexpired error gate omits optional prose without reading storage. Otherwise observe Store::read within the original absolute deadline.

Ok(Some(value)) and Ok(None) install the normal30s answer and clear the error gate. Err—including timeout, corruption, capacity and transport—does not install or replace an answer: it starts a **one-second monotonic retry-after gate** and returns None. Next demand after that short gate can retry. An expired prior answer remains expired/unserved, its TTL is not extended by error. A successful refresh publication clears both answer and error gate immediately. Cancelled work with no observed Result does not manufacture an error/absence entry.

## Persistent-fault bounds and trade-off

The implementation owner selects short separate backoff, rather than accepting unlimited repeated failed reads from the initial prototype. One read can run per office under the existing mutex. After a completed failure, same-office demand does no storage work for1s; this is demand-triggered state, not a timer/retry task or operating quota. The admitted read retains the original request deadline and attach min(remaining,2s) cap. Store may examine up to8indexpages for each of today/yesterday (at most16indexLISTpages), followed by existing catalog/raw lookup bounds. Actual requests/latency/headroom are not measured here. Independent offices have independent gates; caller cancellations are not falsely classified as completed storage errors.

Recovery can wait up to the short gate plus existing read/lock deadlines, instead of falsely caching absence for30s. This updates the author-owned initial immediate-retry requirement; no unconditional prose availability, stale-on-error or production acceptance is claimed. No read-path provider acquisition, runtime mode, timer, storage schema or key allowance changes. Nation fan-out remains outside this increment.

AC1: typed/late error does not create30s absence; demand after1s retries and can recover exact prose. AC2: true absence/value TTL, expiry, office isolation and successful refresh invalidation remain. AC3: persistent fast faults cannot cause repeated same-office reads inside the error gate; pre-fix persistent counter fails, post-fix passes; new expired-entry control, real owned S3 recovery/early-gate/refresh checks, declared paths/docs, independent review and exact CI.
