# Specification: native CPU ownership and private operational metrics

Resource-aware production construction must satisfy the following behavior. Existing standalone constructors preserve their prior contract. Base c1ae9082; pre-merge endpoint, no production or merge authority. Numbered MF references bind the selected design assessment; they are implementation requirements, not completed checks.

MF1: CPU jobs receive the enclosing effective owner/store/request deadline with a 10 ms admission/completion margin. If remaining budget is <=10 ms, return typed LocalCapacity before scheduling. Move VC gzip out of the network-only timeout; keep network classification separate. S06 helpers propagate explicit effective deadlines and typed CPU errors. Air distinguishes local CPU refusal/CPU deadline from genuine stored-data miss/read failure, never funding a chain because local work was refused. Test a held CPU and both nested deadlines becoming ready together with paused time; a margin alone is not proof. Any outer-timeout race that hides local classification blocks Green and must be restructured, not accepted as provider failure.

MF2: Add distinct LocalCapacity propagation through VcTransportError/FundedVc/VcError before Reset or generic error arms. A consumed attempt remains spent; the unconsumed second-attempt reservation follows the existing release-to-pool path. No extra attempt, reset, refund or provider error/backoff arises from the local failure.

MF3: Storage Error::LocalCapacity is distinct from existing Capacity (size and local I/O admission). publish/repair after possible writes classify CPU loss as Ambiguous; reconciliation never gives resend authority. After all index publication is acknowledged and materialization alone cannot get CPU, return Indexed only after a fresh validated pin succeeds, as the existing size-Capacity branch does. Indexed is not CompleteSet/body success. Failed fresh pin after earlier writes remains Ambiguous. Before any possible write, LocalCapacity is definite not-attempted. Enumerate every exhaustive match and add focused partial-write/repair proof.

MF4: Preserve public world::Failure's existing three variants and the existing WorldReply::Error mapping. Carry local-capacity distinctions in private flight/load results or at typed source/storage boundaries and record Cause::Capacity before mapping outward. Never invent 503, Pending/deadline or a new public wire format. Existing standalone constructor signatures remain.

MF5: Preserve a bounded two-second per-cell local cooldown after an actual funded attempt followed by local parse/publication capacity loss. This is a private demand-throttling cooldown, not provider_down, provider_failures, invalid JSON or the 15-minute bad-body penalty. No such cooldown for pre-funding cold restore refusal. Air after a spent attempt may use the same two-second local cooldown with an explicit private classification, never the two-minute provider failure TTL. Verify no immediate repeated funded call while CPU remains full, then a fresh demand after cooldown can recover without provider penalty. No automatic retry inside a request.

MF6: Air local failure uses existing None/fallback-unavailable, not Pending's false deadline reason. Restore/parse refusal before funding does not start another provider and is not remembered as provider failure. Attempt-parse or publish loss stops the chain; spent funding stays spent. Only the explicit post-funded two-second local cooldown above may retain an unavailable row. An uncertain publication stays uncertain and cannot authorize original-body resend.

MF7: Queued waiter drop releases its bounded offer and increments queued cancellation; an admitted waiter drop increments started cancellation but leaves permits in the actual blocking closure, including the admitted-not-running interval. Panic versus runtime teardown/Stopped is distinct. CPU in-use now refers to injected process resources; the legacy foundation immediate API can reject behind FIFO native waiters and retains its earlier semantics. Local-only, nonmigrated KMA/warning/AirKorea stores are explicitly outside this slice's global-sharing claim. D2/F2 new CPU stages need an explicit later wholecandidate injection/reconciliation; no total process CPU/RSS claim is made here.

## Selected MF3/MF5 provenance clarification
The additive CatalogStore publication API may construct an invocation-scoped view sharing the original transport, IO gate, CPU resources and buffer gate. Its private Arc<AtomicBool> records only an actual CpuFailure in that invocation's CPU helper, shared with its RawRecordStore view. Return the original storage Error unchanged together with the typed local-capacity provenance. In particular an uncertain post-write result remains Ambiguous; do not turn it into a definite failure, resend, or broaden ordinary publication failures into CPU-only cooldown. World and air consume this provenance for their existing selected private local cooldown and chain-stop rules. No global flag, late attachment, new storage object, writer or replacement pool. Prove concurrent invocation attribution and pending closure lifetime; a late flag change must not retroactively relabel a returned response. Existing constructors, plain publish APIs and public wire failures retain compatibility.
