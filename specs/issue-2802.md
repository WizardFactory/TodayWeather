# Structured diagnostics contract

Scope/authority and ACs: [intent](../intent/issue-2802.md); exact files: server2/config/tasks/Logging.json. Audit: docs/operations/server2-logging-audit.md.

## Event and privacy contract
NDJSON on stderr, schema1, UTC RFC3339 timestamp, severity, fixed event/component/stage/cause/action/outcome vocabulary; generated trace_id (128-bit), operation_id/parent_operation_id and optional linked operation ID; safe route template, method enum, status/attempt/duration/count numeric fields. No API accepts a raw error Debug/Display string, URL, request/response body, key, coordinate, user/registration ID or notification text. IDs derive solely from process randomness/counters; incoming request headers never become identities. Every terminal record carries context so loss of a start record is not mistaken for success. Accepted FCM != confirmed delivery; a successful result write confirms only the result ledger. Unknown/cancelled remains distinct from failed before submission.

## Correlation
HTTP entry creates a root trace and safe route, preserving HTTP wire output. Task and spawn_blocking wrappers capture context before launch and restore thread-local state on unwind. JoinSet futures inherit explicitly. Writer commands carry enqueue context. Shared acquisitions retain the initiating owner context and link joining traces to the owner operation ID; no input key/hash is logged. A scheduled worker cycle creates a fresh root. A dropped operation emits cancelled, or unknown when an external side effect may be pending. Success is emitted only after the stage's acknowledged outcome; child success cannot establish its parent's durability.

## Output and failure bounds
A fixed bounded queue (<=512 events; event <=1024 bytes) feeds one dedicated stderr thread. Producers only try-lock/try-send/atomics: a slow/closed sink never awaits on request/background execution. Per-severity rate buckets reserve failure capacity independently from info/debug; filtered, rate-limited, queue-full, oversized and sink-error counters remain observable through internal metrics. Emit a bounded loss summary when possible, with explicit limitations if the sink is blocked. Runtime environment selects severity and a bounded rate at startup; invalid logging configuration falls back safely with a classified notice, not a product startup failure. No arbitrary sink path or network collector is added. Shutdown log flushing is bounded and cannot exceed the existing process stop budget. Preserve the stdout readiness/notice result protocol for existing tools.

## Operational behavior
Record request terminal status/admission, cache/restore/acquire, funded refusal/attempt/classification/retry/key rotation, S3 reads/publication/ambiguous reconciliation, existing void compensation, state restore/commit/snapshot, worker supervision/claim/OAuth/send/result, translation fallback and process bind/quiesce/drain/forced stop. Static safe classification replaces raw provider errors. Document operation lookup, ancestor/shared-work traversal, accepted-versus-durable outcomes, missing records/loss counters, timestamps, retention/rotation/access and incident escalation. No new retry/compensation/delivery mode is introduced.

## Proof
Before implementation, run a real old binary with synthetic HTTP requests and assert the new structured terminal event; retain the intended assertion failure, not an import/setup error. Then Rust unit/integration tests plus real owned-peer failure/retry/ambiguity and sensitive-value/flood/sink tests. Preserve functional response bytes/headers, provider attempt counts and side effects through existing regression/smoke suites. Run placement/artifact checks, update operator source/PDF/capture/flow and independent Grok review before integration. S19c consumes final diagnostics later; #2724 is excluded.
