# Stored air forecasts with coordinate observations
See [intent](../intent/issue-2831.md), #2770 and [mobile API](../docs/architecture/mobile-api.md).
AC1: retain the first named station from existing ordered nearby AirKorea metadata query in a separate request field. Do not infer an AirKorea identity from another provider stationName. AirKorea observations use their own station; coordinate observations use the retained metadata station. If none, leave current-only data. Propagate identity to both AirForecast and AirForecastList, with separate forecastStationName response provenance only on actual enrichment.
Use stored data only. KAQ remains preferred with any supported finite nonnegative future concentration; otherwise try AirKorea. Explicit/omitted AirKorea uses the same validation. Invalid/empty/expired rows add no forecast metadata; store errors remain optional middleware warnings. Do not combine source providers. Preserve actual publication per row and selected source summary.
Future slots are strictly after now and current observation; AirKorea preserves its observation +24h horizon. Other-provider slots use request current-hour +24h so stale AirKorea time cannot restrict them. Normalize KST and 24:00 with existing parser. Preserve concentration/AQI converter behavior and daily KAQ calculations.
AC2: serve the actual legacy air middleware chain over loopback HTTP with real isolated station/observation/forecast stores and a captured provider observation; retain the separate existing full weather-router smoke for DB 1.0/2.0 wiring; execute actual client chart block on JSON; compare current fields with current-only captured baseline and station/hour fixture values. Date-only slots fail numeric assertions.
AC3: no live deployment; record selective overlay, restart approval, non-AirKorea origin/public checks and rollback. Quota/publication recovery remains #2636. No app or server2 edits.

AC4 (AK history extension): on successful coordinate fallback, retain the already retrieved nearby AirKorea history separately. Both single/list responses restore finite nonnegative past concentrations and derived AQI within the preceding 24 hourly slots, strictly before the provider current hour and not after request time. Each numeric restored slot carries actual normalized KST date, source=airkorea and its nonblank stored stationName. Keep one station history (the existing selected first list), never blend station values within a slot. Prefer the latest valid value per pollutant/hour; reject invalid dates, other sources, unnamed rows, negative/nonfinite values and out-of-window rows. Missing/partial history stays empty where unavailable. Preserve provider last object and current slot, do not recalculate provider readings in place. Stored forecast selection/publication and observation freshness remain unchanged. Check isolated regression and real HTTP/Mongo -> installed chart numeric past/current/future PM/AQI.
