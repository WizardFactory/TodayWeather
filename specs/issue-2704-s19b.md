# S19b specification

CLI: `python3 server2/tools/native_suite.py --artifacts FILE --out NEW_DIR [--check ID]...`; `--list` lists fixed check definitions without running artifacts. Default is all 11 checks. IDs: kma-core, kma-rich, world, warnings, summary-model, summary-http, state, notice, conditional-alert, warning-push, workers. Repeated/unknown selections are rejected.

Artifact JSON schema 1: `revision` is a 40-character commit ID; `artifacts` maps fixed roles to `{path, sha256, profile: release}`. Paths are explicit and resolve relative to the manifest, executable regular files, SHA-256 exact. Required roles derive from selection; unused unknown roles are rejected. KMA replay artifact must be the exact `examples/kma_s3_replay` beside server2, matching its existing adapter. The suite never builds or downloads artifacts. Declared revision/profile are provenance, not verified compilation identity.

Before launching anything, validate all selected prerequisites and create a new output directory exclusively. Missing/invalid input gives BLOCKED/exit2 with no check executed. Recheck required hashes before each check. Each fixed command runs sequentially with only PATH, TMPDIR and locale/system essentials; no inherited provider/settings/proxy credentials. Use explicit Python interpreter and owned POSIX process group; timeout terminates that group then kills remaining processes. Existing adapters keep their original fixture/factory/expected assertions and cleanup. No arbitrary manifest command, shell execution or new product mode.

Report schema1: started/finished UTC, runner source SHA/revision, declared artifact revision, selected/available IDs, full_coverage boolean, per-check family/layer/limits, command, times, integer exit or timeout, status, artifact identities and log/child report paths+hashes. Checks not selected are NOT_RUN. Default PASS requires every check passed; subset PASS covers selected checks only and full_coverage stays false. A failed check does not hide later checks. Top-level FAIL/exit1 for a child error/timeout/result mismatch.

Child outcome validation: KMA report must PASS with detected self-check and zero unexplained/oracle mismatches; Rust test harness must have a positive passed count and zero failures; structured examples must contain the expected scenario plus PASS (warning catalog uses result pass); worker receipt must bind the actual binary hash and all 27 unique phase/trigger results passed. World smoke must emit its original final PASS marker. Empty/no-op exit0 is failure. Keep real HTTP/process, library-double, and frozen/coexistence layers distinct; suite PASS never implies previous-release recovery, live shadow, production latency or cutover.

Verification: meaningful controls for preflight, selection/coverage, zero/no-op/failure/timeout/stale output and hash drift; separate real functional suite using existing artifacts and actual isolated checks. Manual includes actual command/output screenshot, editable markdown and visually inspected PDF. Workflow shows preflight, fixed checks, per-layer evidence and scoped result. Existing CI gains tool controls; existing product suites/gates remain intact.
