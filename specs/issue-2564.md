# Historical observation contract
Revision 1, local implementation. Links: ../intent/issue-2564.md; ../reports/sdlc/issue-2564/investigation.md.

## Source and normalization
Use official HTTPS ASOS hourly and daily getWthrDataList. Select station IDs from explicit configured station allowlist; map towns to nearest configured city station with valid lon/lat, maximum 100 km. Retain station ID/name, distance, mapping method, source/product and fetchedAt. Missing metadata/coverage is an explicit gap, never an arbitrary station. Provider requests are station/date/time bounded; only completed KST dates D-7..D-1 are eligible. UTC storage timestamps derive explicitly from KST strings; daily dates never use hourly 00-to-24 conversion. Empty/nonfinite/sentinel/failed-QC fields are omitted. Hourly fields: temperature, humidity, hourly rain, wind, cloud-derived sky; precipitation type/lightning are not invented. Daily fields: extrema, average temperature, humidity, wind and daily rain; optional AM/PM weather remains unknown.

## Persistence and recovery
New version-independent ASOS cache keyed by deterministic Mongo _id = product:station:KST-slot, using inherent _id uniqueness. Store valid fields individually with atomic fill-only updates; no replacement of valid stored measurements. Hourly core completeness requires temperature and humidity; daily requires both ordered extrema. Partial records can be retried for missing core fields; unavailable optional fields are not zero. Recovery requests missing contiguous ranges only, with at most seven days per run, configured stations capped, concurrency 2, finite pagination/retry/timeout and no provider calls during weather reads. Mongo station lease prevents overlap; lease failure aborts that station and stale leases expire. No TTL deletes historical cache in this change. CLI requires explicit station/date bounds; collection disabled by default and enabled only by explicit environment configuration. Stored cache reads are separately enabled/configured for rollback. Scheduler uses the gather manager queue hourly and startup, with process overlap protection.

## API and merge
New controller middleware reads mapped station history once; fill only missing historical observation fields before short aggregation. Existing station fallback must not reinterpret unmarked BSON Date rows as verified UTC. Daily middleware runs after getPastMid/mergeMidWithShort and before enrichment/units, fills missing valid daily values for D-7..D-1, and records observation provenance. Historical observation validity requires valid extrema, not forecast AM/PM text. Add historyStatus with requested dates, missing hourly slots, missing daily dates, unavailable fields and mapping/read failure reason. Preserve forecast dailyStatus semantics. Response on cache error continues with existing weather and explicit gaps.

## Compatibility and verification
Retain three-hour short/template/client layout and both DB versions; use mounted KMA routers shared controller methods so old consumers remain compatible with additive metadata. Test KST midnight/month/year across host timezones, sparse hourly fields, daily-only data, repeated/concurrent recovery, malformed provider envelope/pages/identity/QC, write failure and preservation of valid observations/forecasts. Additional smoke exercises real local HTTP adapter and Mongo persistence if available plus actual route/client parsing with isolated external services. Live provider and production recovery remain unclaimed until verified separately.
