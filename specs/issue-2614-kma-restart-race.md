# Acceptance for the restart race

- **RACE:** with the stored reads of a family delayed past the request bound, a restarted process answers that family on its first request from its provider doubles: station minute and hourly rows, the ASOS history (yesterday values, past days, mapping), today's life slots, the narrative and active warnings. Each provider is asked once per dataset key; the settled answer equals a process that read S3. Checked by `a_slow_product_read_starts_the_current_pages_at_the_head_start` and `a_slow_asos_restore_answers_from_the_raced_ranges` (`tests/domestic/observe_product.rs`), `a_slow_life_read_starts_uv_at_the_head_start` (`tests/domestic/life_s3.rs`), `a_slow_office_read_fetches_that_office_once` and the whole answer `a_slow_restart_answers_every_stored_family_first` (`tests/domestic/full_response.rs`); the head start itself by `restored_by_reports_the_head_start` (`tests/resolver/race.rs`). Station pages that arrive while a slower provider is still waited for reach the first answer: `pages_that_arrive_before_a_slow_provider_reach_the_first_answer` (`tests/domestic/observe_product.rs`).
- **FAST:** with prompt stored reads, the first answer equals the producing process's answer and no provider double is called beyond what a running process calls. Checked by `a_fast_restore_asks_no_station_page` (`tests/domestic/observe_product.rs`), `a_current_stored_slot_asks_no_uv` (`tests/domestic/life_s3.rs`; pollen out of season is asked again by any new process, as before), `a_fast_office_read_fetches_nothing` and the whole answer `a_fast_restart_asks_no_provider` (`tests/domestic/full_response.rs`). The station, life and whole-answer cases give the head start a longer request budget so that a slow runner's prompt restore stays ahead of it.
- **FILL:** after a restart the absent hours of today and yesterday are acquired once each, D-2 and older never; a restored page older than a provider page does not replace it; ongoing-hour rows stay. Checked by `the_fill_asks_only_absent_hours_of_today_and_yesterday` (at 10:10 the stored previous hour, past its ongoing reach, is not fetched again) and `a_slow_product_read_starts_the_current_pages_at_the_head_start` (the acquired 10:00 city page stays after the older one is restored) in `tests/domestic/observe_product.rs`.
- **ASOS:** before any station fold, history uses the default station list (Seoul 108 for the Seoul cell) and makes no ASOS provider call when its restore is prompt. Checked by `history_uses_the_default_station_list_while_the_station_restore_runs` (`tests/domestic/observe_product.rs`).
- **LANES:** the rest of the restart read, expansion, product writes, image production and the KASI pass use the bulk lane; the first-answer restores and the request's zone-state read use the request lane, so a full bulk lane does not hold the first answer. Checked by `restore_rest_and_background_reads_use_the_bulk_lane` and `a_full_bulk_lane_does_not_hold_the_first_answer_restore` (`tests/domestic/observe_product.rs`), `the_image_production_uses_the_bulk_lane` (`tests/domestic/air_forecast_s3.rs`), `the_kasi_pass_uses_the_bulk_lane` (`tests/domestic/life_s3.rs`) and `the_zone_state_read_starts_with_the_request` (`tests/domestic/full_response.rs`, which also shows the read starting beside a warning cycle that never ends; `a_warning_cycle_that_never_ends_does_not_hold_the_response_past_the_bound` now expects the answer before the bound).
- **NEEDED-FIRST:** the life read restores today's slots before the rest of its window; with the rest delayed, the first answer has today's UV. Checked by `the_life_read_restores_todays_slots_first` (`tests/domestic/life_s3.rs`).
- **NARRATIVE:** a narrative read slower than one waiter is still published to the next answer; no error gate hides it. Checked by `the_narrative_is_read_while_the_snapshot_runs`, `a_waiter_timeout_keeps_the_next_narrative`, `a_slow_office_read_fetches_that_office_once` and `a_fast_office_read_fetches_nothing` (`tests/domestic/full_response.rs`); `a_deadline_expired_read_does_not_poison_the_next_request` (`tests/narrative/cache.rs`) now expects the next request to join the running read instead of the error gate (decision 6).
- **DOCUMENTS:** `docs/architecture/server2.md`, `docs/architecture/server2-kma-data-design.md` and the data design diagram describe the head start, the lanes and the fills.
- **PLACEMENT:** the placement gate passes against `server2/config/tasks/KMA-RESTART-RACE.json` (base `origin/feat/2614-kma-restart-observe`), and the artifact policy passes on outgoing commits.

Failure paths: a provider failure during the race leaves that family to the restore or to the next request (never 503 for late data); a restore failure after the race keeps the provider data; S16 completeness stays unsettled while restores run.
