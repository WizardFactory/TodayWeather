# Final registration copy and source-deletion reconciliation

This specifies F1 only at base `c1ae9082`. [Intent](../intent/issue-2819-final-registration-copy.md). Implementation is pending the root design gate stated below. This is a new explicit finalization command; existing conversion/import APIs and public registration behavior remain unchanged.

## Input and authority contracts

A private immutable source bundle identifies exact source store/database/collection scope, full source deployment revision, export generation (positive monotonic integer for that source), exported-at cutoff, prior import baseline digest/identity, both `pushes` and `alertpushes` raw exports, converted canonical records and converter counts/report digests. Each complete collection manifest includes raw/converted counts and content digests; duplicate collection/_id, malformed/rejected documents, absent files/scopes, mismatched counts/digests/revisions or excessive size reject the whole bundle before S3 mutation. Empty complete collections are explicit and valid; missing or truncated collections are not empty snapshots. Only the supported Mongo export contract is accepted; unknown/SQLite/coordinator source selection is BLOCKED.

Bundle provenance includes references and digests of an operator-reviewed actual process exit/no-respawn receipt, all mutation ingress/background-writer freeze receipt and cutoff/settlement evidence. The code checks existence, format, digest and reference binding; it cannot prove the receipts truthfully describe a real host or a complete database export. Manual operational acceptance remains distinct. No Boolean alone makes `freeze_verified`, `senders_stopped` or `production_eligible` true. Repackaging old data as a newer generation is not authenticated by a local hash; custody/source-identity evidence is an essential operational gate, explicitly not a tool guarantee.

Keep raw/private identity data in new0600 artifacts, refuse symlink/existing output targets, and print only counts, positions/reasons and digests. Existing environment/dotenv/S3 credential rules are reused; no new production endpoint override, provider call or deployment mode. The apply command writes the selected authoritative S3 state and requires its own operational authority; preparing the tool or passing its owned-peer smoke grants none.

## Preview contract (COPY-1/2)

Restore current authoritative native state through existing Durable logic. Bind bucket/region/state prefix, full source identity/generation/export digests, current seq/next_n, ordered collection records including import digests, and sorted tombstones into a canonical deterministic fingerprint. Include planner/tool/schema version and deterministic ordered operations in the plan digest. Source identity covers a stable source scope, not only a user-chosen filename.

Compare a complete prior import baseline to the final snapshot and current state:

- Identical final rows are unchanged. Source additions/updates are proposed only under the existing import ownership rules; a native modification or uncertain mixed ownership is a reported conflict and blocks destructive automatic application.
- A final-source absence is a `source_absent_delete` only when the baseline proves that collection/_id was imported from the same source and the current record/import digest still exactly matches the owned baseline. Never infer ownership from a matching token alone.
- Native-created/unrelated records are preserved; source absence never deletes them. Native-changed previously imported rows are retained as conflicts rather than silently replaced/deleted. Existing native tombstones remain tombstones and are never resurrected from stale source input.
- Distinguish `native_deleted_kept` (existing migration `deleted`) from new `source_absent_delete`. Do not relabel either count.
- Preview is read-only and fails closed if source scope/completeness, provenance bindings, ownership or the current native revision is unknown. It reports proposed counts and exact plan digest; it does not attest a host freeze.

## Atomic apply and replay contract (COPY-3/4)

Proposed bounded design for root confirmation: encode the whole finalization change set in **one existing durable journal entry**, at most the existing configured entry bound (default1MiB) and control-object bound. Reject oversize plans before any write; do not silently split, drop changes or claim all registrations were copied. No separate finalization control-object transaction or new writer service.

A bounded optional typed final-copy marker lives in canonical State, the journal header, and snapshot head (not snapshot record lines). It binds stable source identity, positive generation, predecessor seq/plan, export digest, base native-state fingerprint, and exact plan digest atomically with changes. Restore, external writer catch-up and snapshot preparation carry it; recognized malformed, non-increasing or seq-inconsistent metadata is corrupt. Marker absence preserves old encoding. Do not scan pre-snapshot journal history or add a separate highwater object. A claimed predecessor is checked with one bounded journal read and must match State; erased/missing/conflicting marks block. Digests do not authenticate source generation or custody.

The exact same encoded entry bytes (including metadata/nonce) must be size-checked against configured entry_bytes and the existing control-object bound before credential readiness or mutation, used for one original conditional-create attempt, and retained for reconciliation. Existing readback/conditional-void settlement may write a void; it never re-sends the original finalization payload. Do not encode once to estimate then regenerate different bytes in commit. Native fingerprint includes seq/next_n, ordered documents and import digests, sorted tombstones and the marker. A baseline row missing natively without a tombstone is inconsistent; a native-created colliding source _id with differing content is a conflict. Either blocks the whole plan.

Before apply, re-read source bundle and authoritative current state/high-water, regenerate deterministic preview, require the expected plan digest and current revision exactly, and reject native changes since preview. Use the existing journal conditional create, settlement and void semantics. Do not replan a stale destructive plan onto a later state automatically. A CAS conflict means STALE/BLOCKED; unrelated native changes are retained. The same source/generation with differing export or plan digest is a conflict, older/superseded generations are rejected, and an explicitly recognized already-committed exact operation is reported without writing again.

A write rejected before acceptance is NOT_APPLIED. A lost response that reconciles to the exact marker/entry may become COMMITTED. An unresolved outcome remains SETTLEMENT_REQUIRED and authorizes no retry, snapshot rewind, new source generation or second writer. A definitively voided attempt is not a success and needs a fresh preview bound to the changed sequence. On process restart, reconcile the retained exact operation/journal identity before any new apply. Cold restore must match the planned post-state and retained tombstones; a later unrelated native update must not be overwritten to make verification equal. Receipt distinguishes COMMITTED, VERIFIED, ALREADY_COMMITTED, STALE, NOT_APPLIED, BLOCKED and SETTLEMENT_REQUIRED as applicable.

Preserve claims/results and other state namespaces byte-for-byte. No delete/reset of authoritative S3 objects, no old snapshot replacement, no automatic failed/unknown delivery replay, no spent-budget reset. Existing older server2 readers must either restore the backward-readable journal changes safely or remain explicitly unsupported; losing source high-water after an older writer compaction/restart must never permit a stale final-copy command. Rollback eligibility of an entire release is not established by this PR.

## Operational procedure and safe limits (COPY-5)

Freeze receipt names actual sender identities/hosts and confirms process exit/no respawn, including all variants actually deployed. Freeze user edits on every public/internal/origin-bypass ingress plus token-update/cleanup/background writers, preserve last acknowledged cutoff and settle in-flight mutations. `Manager.stopManager()` and changing only SERVER_MODE are not proof. Original database is read-only during export. Final export, deletion reconciliation, cold state verification and single native owner activation are separate recorded steps; native delivery remains off until approved prerequisites and operator authority hold. If any step is uncertain, keep cutover blocked; do not restart legacy/native senders automatically.

Unsupported in this bounded increment: multi-entry finalization, arbitrary stores, live stop/freeze automation, production probes, generic fencing framework, F2 statistics wiring, quota2724 and whole-service rollback/production readiness.

## Current decoder and retention evidence (source only)

At basec1ae9082, `server2/src/push/durable.rs::parse_entry` (:185-245) parses an OrderedJson header, checks schema/seq, reads void/next_n/changes, and does not reject unknown header keys. Its returned value contains only next_n and changes; unknown metadata is discarded. `prepare_snapshot` (:682-734) serializes records/import digests and tombstones, with no final-copy metadata. `restore` resumes from head.seq+1. Therefore adding a header key appears syntactically tolerated by this exact reader source, but neither metadata preservation in snapshots nor runtime compatibility with a selected earlier release is established. This is not a backwards-compatibility PASS.

The selected design is Candidate C, corroborated by B's canonical-marker proposal, with A's complete-export/provenance contract retained. A fresh independent source-bound judge identified history-scan exhaustion and exact-byte commit gaps. No full historical scan is used. Metadata lives in header/head and must survive the new service writer's catch-up and compaction. Existing older readers may ignore it, but older writers erase it and are explicitly ineligible after finalization unless actual compatibility checks prove preservation. Both later qualified recovery releases must preserve the marker. No compatibility execution or full recovery qualification has yet occurred.

Use safe bounded source identifiers and integer generations through 2^53-1, with strict recognized metadata fields and lowercase SHA-256 strings. Same generation with changed bytes, absent or ambiguous predecessor and custody mismatch block before mutation. An absent sequence after unresolved commit is not proof of no write: retained exact operation identity must be reconciled using the existing readback/conditional-void semantics, never re-sent or re-planned automatically. Explicit settlement must not invent a second transaction or writer protocol.

## Review1 contract clarification

A source-owned row that was edited natively and is missing or also changed in the final source export is a conflict that blocks the **entire** preview/finalization. No partial plan, conflict-skipping or successful partial copy is returned. Native data remains untouched; retain the error and reconcile a complete authoritative source/baseline under the existing stop/freeze gate before producing a fresh plan. The current error identifies a conflict; no aggregate conflict-count report is claimed.

A retained conditional void is terminal NOT_APPLIED, including repeated settle after a lost void response; neither repeat submits the original payload. Marker erasure is detectable only with a claimed predecessor chain. If state has no marker and the supplied bundle claims no predecessor, code cannot distinguish first finalization from metadata erased by an ineligible old writer. Eligibility/custody forbid that operator sequence; no global marker-erasure detector or copied-operation custody fence is claimed.
