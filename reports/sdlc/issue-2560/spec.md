# Daily data contract
Missing optional input fields are absent, not defaults. Preserve wf/rnSt day 3–10 and numeric taMin/taMax day 3–10. Invalid supplied measurements are omitted; an item with no usable weather/temperature fails. Region and 06:00/18:00 KST publication identity are required. Valid temperatures: finite -50 < value < 60; probability: 0–100.
Primary sources have independent 36-hour maximum publication age, no future publication, and matching record date/time identity. Use the newest record only; never cherry-pick an older horizon hidden by a newer partial publication. Convert calendar offsets with UTC arithmetic over KST calendar values; never shift offsets to hide gaps.
Only complete daily weather (recognized AM/PM sky plus valid min/max) is exposed, preserving the existing consumer shape; omitted date means unavailable. rnStAm/rnStPm remain optional additive values. Short daily records overwrite by target date, with invalid/sentinel fields unable to erase a valid mid row. Preserve historical observation window today-7 through today; future maximum today+10. Publish additive dailyStatus with unavailable dates, source status and retired RSS state.
Retire legacy mid RSS collection and cache overlay unconditionally; fresh-looking cached RSS also has no precedence until a supported source is explicitly implemented. Low-level response/parser entry points must still reject HTML/malformed XML. No guessed replacement URL or credentials.
Daily health is separate from current/short freshness: validates primary source age, sorted unique target dates, no obsolete dates, and usable future mid horizons. Expose gaps rather than requiring fabricated continuity.

Verification amendment: short daily overlay requires publication age 0–24 hours and target <= publication date+4. Normalize optional raw short values before summarizing, omit sums/lightning/mean without valid sources, preserve actual negative temperatures. DB write errors must propagate before pruning old primary records.
