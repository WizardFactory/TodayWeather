# Correction contract

Preserve the existing executable contract and release gates. C1: root must not change CommonJS semantics of native tooling; web workspaces remain ESM. C2: await dialog events and their completed handling, and assert one confirmation per navigation attempt without sleeps. C3: favorite deletion must establish current notification capability and finish enabled server-rule cleanup before local success; unknown/unreachable state is recoverable and retains the favorite.

C4: serve current unhashed shell assets from the current cache; retain explicitly scoped prior-cache fallback only for hashed assets needed by old tabs. Build version must include worker and shell bytes, including icons/manifest. C7: assert server and worker route agreement across valid/invalid paths.

C5: serialize state claims/dedupe/persistence, never outbound push waits. Limit process-wide concurrent sends to four. Revalidate queued deliveries against current subscription/rule revisions; do not remove replacement subscriptions on stale 410 responses. Keep invocation timestamps and a five-minute maximum recovery window for missed ticks; startup handles the current minute. No distributed delivery or guaranteed exactly-once receipt claim. C8: require known catalog IDs with matching coordinates or canonical coordinate IDs matching validated coordinates.

C6: parse warning image URLs; allow only weather.go.kr and www.weather.go.kr, upgrade their HTTP links, reject credentials and unexpected ports/hosts. C9: select valid rain fields rather than property presence; record null interval when quantity is unavailable. KMA short rows use three-hour totals, observations use one-hour values, world hourly is one hour and daily totals are 24 hours. Rain and explicit snowfall stay separate in canonical API precipitation units; never infer snow depth from mixed precipitation. Accept legacy offline records without new snow fields, but suppress their unverifiable interval metadata.

C10: derive Vite host/port and API Origin from one development configuration, preserve explicit loopback overrides and strict production checks. No legacy server/collector startup or edits.
