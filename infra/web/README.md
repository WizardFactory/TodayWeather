# Static web hosting

The webapp is a static PWA for **app.tdywx.xyz**. Its only hosting target in this repository is [private S3 + CloudFront](static/README.md), with browser calls to the existing public TodayWeather API. No additional Node server, API proxy or notification service is deployed.

The former Docker/Caddy recipe and Node API workspace have been removed. Node is used for local development, builds and static preview only. Run `npm run build` and `npm start` from the repository root to inspect `web/dist` locally; the preview is not a production requirement.

The static directory contains a CloudFormation template, a known-route navigation function and deployment guidance. The uploader defaults to dry-run and preserves previous hashed assets. These are preparation artifacts: **the deployment method is not yet decided by AK**, and no workflow-based deployment is implemented. The [runbook](static/README.md) covers two options: reusing the existing distribution and bucket (attach the route function and CSP headers policy, then upload), or a new stack whose `AppDomainName` alias requires a planned cutover because the existing distribution already holds `app.tdywx.xyz`. Before any upload, the uploader verifies the alias, S3 origin, OAC, HTTPS redirect, LIVE route function, CSP `connect-src`, an empty `OriginPath` and the absence of error-to-page mappings. See the runbook for ordered uploads, [release identity and rollback](static/README.md#release-identity-and-rollback) (`release.json` `commit`/`builtAt`, the `web-static-dist` CI artifact retained 90 days), and [implementation status](../../docs/webapp/implementation.md) for data/device release boundaries.

**Deployment candidates.** Deploy only the `web-static-dist` artifact of a `push` run on `master`, or a clean local build (no `-dirty` suffix) of the commit being released. The **Web app** workflow also uploads `web-static-dist` on `pull_request` runs, but those build GitHub's temporary merge commit: their `release.json` `commit` is that merge commit's `GITHUB_SHA`, not the pull request head, and the merge commit never exists on `master`. Pull request artifacts are for review only and are not deployment candidates. After an upload, `--expect-commit` must be the commit of the artifact actually deployed (the `master` push commit, or the clean local `HEAD`), not a pull request head.

`scripts/web-live-smoke.mjs` is a read-only, unmocked browser smoke for use before deployment (local preview) and after it (`--base https://app.tdywx.xyz --expect-commit <deployed sha>`). The **Web live smoke** workflow runs it daily and on manual dispatch, never on pull requests, and writes a job summary that separates new warnings from the documented chronic ones. See the [live smoke](static/README.md#live-smoke) section for its checks, failure screenshots, ownership and triage by category, and the scheduled-workflow limits. The runbook also covers the Option A configuration rollback, waiting for the CloudFront invalidation and building an artifact for a commit that the CI path filters skipped.

Web Push is unavailable. The app presents mobile-app guidance and does not collect browser subscriptions or notification schedules. Any future browser alert service requires separate design and authorization; existing native push infrastructure is unchanged.
