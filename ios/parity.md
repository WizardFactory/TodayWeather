# Parity checklist (IN-18)

This checklist records how the native app in `ios/` reproduces the Cordova 1.1.1 iOS app (#2967, part of #2948). It covers the screens S01–S12 with their dialogs, the shell and app-wide elements that have no spec ID (X1–X11), and the iOS-only behavior of the Cordova build (I1–I12: its `ionic.Platform.isIOS()` branches, iOS templates and plugins). Removed and unreachable items, and the Android-only ones, are listed at the end for completeness.

**Parity oracle.** The Cordova iOS build: the source at the pull request's base revision, including its iOS branches, and captures of that build on iOS Simulators ([spec](../specs/ios-native.md#behavior-to-retain)). The [Cordova user manual](../docs/user/cordova-app/README.md) (Android captures) and the rewrite specification ([screens](../docs/rewrite/screen-specifications.md), [overlays](../docs/rewrite/screen-overlays.md)) name the screens and states. The Android [parity checklist](../android/parity.md) (AN-18) records the same rows for the Android app and is the reference for decisions already taken; where the sources disagree, the current Cordova iOS behavior wins.

**Current temperature (S03, S04).** The decimal separator and fractional digits use 70% of the whole-number font size in native forecast headers. The [header reference images](TodayWeatherTests/FractionalTemperatureReference/) start from the corresponding Cordova capture. Only the bounding rectangle of the temperature and recentered sky icon was replaced with the inspected native render (Xcode 27.2, iOS 26.5, November 19, 2026). Weather, matrix and settings screenshot tests compare the whole block with their existing tolerances. Integer headers still use the original captures. [Illustrated example](../docs/user/ios-app/current-temperature/manual.pdf)

**Columns.**

- **ID:** S and O IDs are the rewrite specification's. X IDs follow the Android checklist; I IDs are local to this checklist.
- **Cordova reference:** pages of the [manual](../docs/user/cordova-app/manual.pdf) (page N is step N of `manual.json`) and the spec section. "(text)" marks a page that describes the item without showing it.
- **Native evidence:** test suites, with the test where one test is specific (`Suite.test`). Tests are app-hosted (`TodayWeatherTests`, on a simulator) unless marked: (package) marks the `ios/Core` package's tests (`swift test` and the scheme), (UI) the XCUITest target `TodayWeatherUITests`, run by the scripts in `tools/` ([README](README.md)). A marker covers the suites between it and the previous semicolon or period. Reference sets are Cordova iOS captures under `TodayWeatherTests/<Set>Reference/` at 393×852 pt and scale 3 (the charts also at 375×667 and 440×956), compared by the AN-05 metric within the tolerances each set records; `MatrixScreenshotTests` compares each screen's manual state at 375×667 (scale 2), 393×852 and 440×956 in Korean and English (`MatrixReference/`). The iPad checks are `IPadFitTests` (every screen in iPad windows, rotated and resized, at `xxxLarge`) and `IPadUITests` (the iPad simulator itself turned).
- **Accepted differences:** decisions with their source. "Kept (#2948)" marks a documented Cordova anomaly (docs/rewrite A01–A49, [decisions](../docs/rewrite/decisions-and-open-questions.md)) the app reproduces on purpose: #2948 inherited AN-06's record (anomalies kept except A01; the free-form weather-address fallback; S13–S16 not built; 12:00 AM in the picker acts as Delete; D37), [intent](../intent/ios-native.md#decisions). Android IDs B1–B33 are the rows of [`android/tools/corpus/differences.md`](../android/tools/corpus/differences.md); "as AN-xx Bn" marks a difference the iOS sub-issue took over, with its section of this directory's [README](README.md) or the [plan](../plans/ios-native.md). "iOS (IN-xx)" marks a difference only the iOS app has, decided in that sub-issue.
- **Status:** "Covered" when each element of the row has native evidence; "Not built" for removed, unreachable or Android-only items.

**Delivery.** IN-18 ships in parts, as AN-18 did:

- **Part 1 (this checklist):** the checklist (AC1), the request-path tests (X11, AC3) and the iPad checks (X9, AC4).
- **Part 2:** the screenshot matrix at 375×667, 393×852 and 440×956 pt in Korean and English (AC2): for each screen S01–S12 and its main dialogs the state the user manual shows, as AK decided for AN-18 on 2026-11-11 ([intent](../intent/android-native.md#an-18-decisions-ak-2026-11-11)). Every state compared before stays at 393×852; the matrix adds the other sizes and the English states those sets lacked (`MatrixScreenshotTests`, [MatrixReference](TodayWeatherTests/MatrixReference/), [README](README.md#size-and-language-matrix-in-18)). Two scope decisions (accepted 2026-11-17): English is English with region US, because the Cordova iOS build takes its region from `navigator.language` and the iOS WebView reports en-US for an en-KR system too, so its English pages use °F, mph, inHg, mi, in and the AirNow standard (each capture records its units, and the native render takes them); S10–S12 are Korean only, because outside region KR the Cordova build has no menu rows for them and shows "USA" without data if one is opened.
- **Part 3:** the [native user manual](../docs/user/ios-app/README.md) (AC5): 41 illustrated steps, editable source, actual iPhone 16 simulator captures and a rendered PDF.

**D41, device classes and orientation.** The native app supports iPhone and iPad in every orientation and window size (IN-07 AC3) and recomputes its sizes from the current window, where a Cordova view kept the screen's sizes from `initSize` ([spec](../docs/rewrite/screen-specifications.md#device-classes-and-orientation)); the hourly chart's opening column (A49) stays. As in AN-18, this is a deliberate difference for window support (Split View and Stage Manager windows smaller than the screen); on an iPhone in portrait the window is the screen, so the captured sizes are unchanged. iPadOS 26.5 refuses a programmatic rotation of a test host's scene, so `IPadFitTests` turns and resizes the window's frame and `IPadUITests` turns the simulator. The fit checks require every identified element inside the window; they keep what the Cordova CSS does at larger sizes on purpose: S10's mode buttons end with an ellipsis when their title does not fit (`text-overflow`), and S10's and S11's labels grow at their fixed positions, so at `xxxLarge` neighbouring labels can cover each other (IN-13). In a window narrower than the 330 pt map (a Split View third) the map and its labels scale down to the window (IN-18), where the Cordova page would have cut the map.
